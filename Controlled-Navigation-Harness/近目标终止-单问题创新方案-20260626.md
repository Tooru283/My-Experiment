# 近目标终止决策 — 单问题多创新点方案

> 这份文档承接 `新论文创新点引入.md`。
>
> 上一版把方法收束成 U1/U2/U3 三个并列单元（drift / stop / recovery），
> 这是一个"系统 harness"结构，reviewer 容易读成工程外壳。
>
> 本版的核心调整：**把整篇论文压到一个问题上做深，让多个创新点都是同一个问题的不同切面，而不是三个并列贡献。**

---

## 0. 一句话结论

```text
不要再加模块。
选定一个问题：小 VLM 能走到目标附近，却停不住（OSR→SR 转化失败）。
围绕这一个问题，分层做出 4 个互相支撑的创新切面 + 1 个跨 backbone 主张。
```

---

## 1. 为什么选"近目标终止"作为唯一核心问题

### 1.1 这是数据指出的最大杠杆

| 指标 | 你的最佳 ep100 | 说明 |
|---|---|---|
| OSR | 27-29% | 走到目标 3m 内的能力 |
| SR | 18-19% | 真正停在 3m 内的能力 |
| OSR-SR gap | 9-10 条/100 | **每 100 个 episode 有约 10 个"到过但没停住"** |

把这 10 条转化成功，SR 直接到 27-29%，干净超过原文 GPT-4 的 19%，并超过所有 ≤10B 的 HiMemVLN 变体。

### 1.2 这是一个文献承认、但你独占的切口

- **MSGNav 已经把它命名为"最后一公里问题（Last-Mile Problem）"**：知道目标位置 ≠ 找到合适的终止视点，已有方法通常停在最近可达点、视野差，导致任务失败。→ 问题的合法性有 CVPR 级论文背书，你不是自造问题。
- **HiMemVLN 完全没碰这个问题**：它做的是分层记忆，且 memory 在小模型上不 work（Qwen2.5-VL-7B 只有 SR=15%）。你的 OSR 已经证明"走到附近"不是瓶颈，**停不住**才是。
- 你的 OSR（27-29%）甚至高于 HiMemVLN 的 7-8B 变体（23-26%），说明你的导航前半段不弱，**真正欠的就是终止那一步**。

### 1.3 和上一版的关系

U2（Evidence-grounded Stop Verifier）从"三个并列单元之一"升级为**论文核心**。U1 / U3 降级为支撑组件（U1 提供 verify-phase 的干净上下文，U3 保证拒停后的受控回退），写进方法但不作为独立主贡献。

## 2. 围绕一个问题的 4 个创新切面

每个切面都只回答同一个问题的一部分："小 VLM 在最后一米，应该如何可靠地决定停 / 不停"。每个切面都有对应的可借鉴论文机制和可消融配置。

### 切面 A：问题形式化 + 近目标失败 taxonomy

**做什么**：把 OSR→SR 转化率定义成一个一等指标，并给出 near-goal 失败分类：
`walk-through`（走过头）/ `premature-stop`（提前误停）/ `near-goal-drift`（震荡漂移）/ `weak-target-miss`（弱终点漏停）。

**借鉴**：MSGNav 的 Last-Mile Problem 命名；你已有的 `analyze_navigation_jsonl.py` 已经能自动列出 `OSR=1 but SR=0` 和最大 drift（如 `810: 0.045m→5.18m`），直接产出 taxonomy 统计。

**为什么是创新**：一个被清楚命名、测量和分类的问题本身就是贡献。HiMemVLN 没有这个诊断视角，你有 per-episode trace，这是你独有的资产。

### 切面 B：视点感知的终止验证（核心机制）

**做什么**：把 STOP 从"selector 的一个动作选项"改成"目标满足性验证问题"。不止判断"目标是否可见"，而是验证"当前是否处在一个满足任务判定的终止视点"。

**借鉴（两篇直接对应）**：
- **MSGNav VVD（最优视点决策）**：对多个候选停靠位按目标可见性 / 关系满足度打分，选最可见、最稳定的终止视点，而不是最近点。直接打 walk-through 和 near-goal-drift。
- **Context-Nav 视点感知 3D 关系验证**：left/right/front/inside 这类关系依赖叙述者视角，不能只看当前单视角 VLM。先验 intrinsic 属性，再验 viewpoint-aware 关系。直接打你日志里"看到远处目标误当 arrival_evidence"的 false positive。

**落地**：在你已经设计好的 current-view verify auto-stop 上扩展——不只看 `__current_view__` 是否 allow，还要让 verifier 检查 relation/viewpoint 满足性，并在多个近目标候选间选最优终止视点。

### 切面 C：不确定性感知 / 可弃权的终止决策（真正的新意）

**做什么**：小 VLM 是 miscalibrated 的——它"看到了"但 confidence 不可靠（你现在用 `confidence>=0.95` 硬阈值就是在手动绕这个问题）。引入一个针对小模型的不确定性感知机制：证据不足时**允许弃权（abstain）= 不停、再观察一步**，而不是被迫做二元 stop/move。

**借鉴（两篇）**：
- **Fast-SmartWay 的 Disambiguation Module**：MLLM 判断信息不足时，原地旋转扫描补充观测再决策。消融显示 **+4.5 SR**（同任务 R2R-CE 100ep / GPT-4o）。把它从"移动消歧"迁移到"终止消歧"：near-goal 但 confidence 不足时，触发一次受控的环视/再观察，而不是直接走开或硬停。
- **AbstainEQA（CVPR 2026 Highlight）**：把"是否具备足够证据再行动"形式化为 abstention。借它做终止决策的理论锚：允许 STOP verifier 输出 `abstain`（证据不足，继续收集），把终止从二元判断升级为三态（stop / move / abstain-and-reobserve）。

**为什么是创新**：这是一个专门 for small models、且有理论命名的角度。大模型不太需要它（72B 校准好），小模型最需要——正好对应你"4B 也能可靠终止"的故事。

### 切面 D：预测-验证的停前确认

**做什么**：在 commit STOP 之前，先让模型预测"如果我现在停，这个视角应该满足指令的哪些条件"，再和实际观测核对；不一致就撤销 STOP。把被动停止升级成 decision boundary 上的主动核对。

**借鉴**：**Fast-SmartWay 的 FPBR（Future-Past Bidirectional Reasoning）**：执行前预测下一步该看到什么 + 回忆历史，做时间一致性验证。消融显示 **+3.5 SR**。迁移到终止：stop 前做一次"预测-核对"闭环，配合 U3 在核对失败时受控回退。

**注意**：这一层最重，要低频触发（只在 verify phase + near-goal 时），否则拖低 SPL。你 6/13 V24 的 SPL 教训说明额外步数会反噬路径效率，所以 D 必须严格门控。

---

## 3. 最硬的卖点：跨 backbone 一致性主张

你手上有 72B / 8B / 7B / 4B 四个 backbone 的对齐数据，这是**被严重低估的金矿**。论文最强的 positioning 是：

> 我们的近目标终止机制（B+C+D）在 4 个 backbone 上带来一致增益，
> 而纯 memory 增强（HiMemVLN）对小模型无效（Qwen2.5-VL-7B 仅 SR=15%）。
> 这说明：**显式的、证据驱动的终止决策可以补偿模型规模，而依赖基座能力去"读懂 memory"的方法不能。**

这一句把"我们打不过 72B"的劣势，转成"我们揭示了一个 memory 方法不具备的、规模鲁棒的性质"。

**前提（不可省）**：必须先补 **A0 baseline = 4B 裸跑原始 Open-Nav，无任何 decision-effect**。没有这个锚点，所有增益数字都无法归因，论文不成立。这是上一轮对话就强调过、至今仍未跑的对照。

## 4. 实验矩阵（全部围绕一个问题）

### 4.1 主指标

以 **OSR→SR 转化率** 为第一指标（你现在只报 SR/OSR，要把转化率单列），辅以 near-goal 失败 taxonomy 的分布变化。SPL/nDTW 作为不退化约束。

### 4.2 消融链（每次只开一个切面，建立在已修好的 A0/A1 + U1 verify-phase 上）

| 编号 | 配置 | 验证的切面 | 预期 |
|---|---|---|---|
| A0 | 4B 裸跑 Open-Nav | 锚点基准 | 建立真实 baseline |
| A1+U1 | harness + verify-phase 干净上下文 | 支撑层，不改终止 | ≈ A0 |
| S1 | + current-view auto-stop（你已设计） | B 的最小版 | +3-5% SR |
| S2 | + 视点/关系验证（MSGNav VVD + Context-Nav） | B 完整 | OSR→SR 转化率↑ |
| S3 | + 弃权 + 再观察（Fast-SmartWay Disambig + AbstainEQA） | C | false positive↓，weak-target-miss↓ |
| S4 | + 预测-验证停前确认（FPBR） | D | near-goal-drift↓，SPL 不退化 |
| S-full | B+C+D 组合 | 最终系统 | 目标 SR 24-27% |

对 4B / 7B / 8B 各跑 {A0, S-full}，画出"终止机制带来的 ΔSR vs backbone 规模"，与 HiMemVLN 的"memory 带来的 ΔSR vs 规模"并列对比。

## 6. 论文贡献表述（收束到一个问题）

> 我们针对零样本 VLN-CE 中被忽视的**近目标终止问题（OSR→SR 转化失败 / Last-Mile）**，提出一个证据驱动、视点感知、不确定性可弃权的终止决策框架。它把 STOP 从 LLM 的一个动作选项，重构为一个可验证、可弃权、可预测核对的目标满足性判断。在 4B 到 72B 的多个 backbone 上，该机制带来一致的 OSR→SR 转化提升，使一个 4B 本地模型在不依赖大模型能力的前提下，逼近甚至超越基于 72B 的记忆增强方法在小规模 backbone 上的表现。

三点贡献（都属于同一个问题）：
1. 形式化近目标终止问题并给出失败 taxonomy（切面 A）。
2. 视点感知 + 不确定性可弃权 + 预测核对的三态终止决策机制（切面 B+C+D）。
3. 跨 backbone 证据：显式终止决策可补偿模型规模，memory 增强不能（第 3 节主张）。

# 附录 A：追赶 P2DNav 的借鉴路线（已选定 = 在现有 Open-Nav 上借机制追）

> 背景：P2DNav（arXiv:2605.19634，Qwen3-VL）在与本实验**完全相同口径**（R2R-CE val-unseen, 100-ep, 3m）上，
> 4B 拿到 **SR 35 / OSR 51**，32B 到 **SR 50 / OSR 65**。这把"4B 上限 24-27"的假设推翻了——
> **天花板从来不是模型规模，是导航 pipeline。**
>
> 决策：**保留 Open-Nav 链路作为干净基线，借 P2DNav 的高杠杆机制把性能拉上来，论文定位在"受控诊断 harness + 近目标终止决策"。**

## A.1 先认清差距来自哪里

| 维度 | 你的 4B | P2DNav-4B | 差距来源 |
|---|---:|---:|---|
| OSR | 27-29 | 51 | **导航 pipeline**：方向优先 + downview grounding + 原生 VLM，比你更会走到附近 |
| SR | 18-19 | 35 | 上面的 OSR 差 + SDM 记忆 + RRM 弃权 |
| 转化率 OSR→SR | ~65% | **69%** | 两边都没解决好！P2DNav 也漏 |

关键结论：你落后的**主要是上游导航（OSR 差了 ~22 点）**，不只是终止。所以"只修终止"补不平 35。但反过来——**终止这个坑 P2DNav 也没填**（转化率才 69%，STOP 只是 Stage-1 一个选项，无专用终止验证器），这就是你的差异化空间。

## A.2 借鉴清单（按性价比排，每个作为独立 decision-effect 单元，保归因）

### B1：SDM 式对话记忆 —— 最大单项杠杆（P2DNav 消融 +13 SR）

**做什么**：把 selector 的历史从"单轮 prompt 塞全部历史"改成**原生多轮对话**：最近 1 步保留完整（图/视觉证据），更早步骤只留文本决策记录。

**适配你架构的注意点（重要）**：P2DNav 用 Qwen3-VL 原生多模态多轮对话保留"上一步的图"；你是 **Qwen3.5-4B 文本模型 + SigLIP 证据抽取**，没法直接塞原始图像。迁移方式要改成：**最近一步保留完整的结构化视觉证据（V1 candidate evidence + current-view verdict），更早步骤只留文本动作历史。** 本质一致（近端多模态证据 + 远端文本记录），落点适配你的接口。

**预期**：这是你最快、最可能大涨的一波。即使打个对折也可能 +5-7 SR。

### B2：方向优先解耦（P2D 思路，+3 但是地基）

**做什么**：selector 不要一步选 final waypoint，先在全景候选里选**方向/大致 view**，再在该方向内验证局部候选。仍在你的 waypoint 候选空间内做，不必推翻 waypoint predictor。

**价值**：让"方向错"和"局部点错"可分离归因——这正好喂给切面 A 的 failure taxonomy（P2DNav 天然给了 `direction_error` / `target_offset` 两层标签可借）。

### B3：差异化的执行前弃权（切面 C/D，必须和 RRM 拉开）

**P2DNav RRM 已经做了什么**：执行前判断**局部落点可不可走**（depth<0.25m、stuck），不可靠就 abort 重选方向。它主要提 OSR。

**你必须做的不同的事**：你的弃权/验证针对**目标满足性 / 是否到达该停**，不是局部可走性。即——
`RRM 问"这一步能不能踏出去"，你问"我是不是已经到目标、该不该停"`。
这是 P2DNav 留空的 OSR→SR 转化器，互补而非竞争。论文里要明确这句区分。

## A.3 与 P2DNav 的定位区分（写进 related work）

| | P2DNav RRM | 本工作终止验证器 |
|---|---|---|
| 反思对象 | 局部 grounding 可走性 | 目标满足性 / 到达判定 |
| 主要提升 | OSR（走到附近） | OSR→SR 转化（停得住） |
| 触发 | Stage-2 落点不可靠 | verify phase + near-goal |
| 关系 | —— | **互补**：可叠加在 P2D 式 pipeline 上 |

一句话定位：**P2DNav 解决"更会走"，我们解决"走到了更会停"——而且证明这个终止杠杆跨 backbone、跨 pipeline 都生效。**

## A.4 消融与现实预期

消融链在原文第 4.2 节基础上前置 B1：
`A0 → A1+U1 → +B1(SDM记忆) → +B2(方向解耦) → +S1(current-view auto-stop) → +S2/S3/S4(终止验证全套)`。

**现实预期（要诚实）**：B 路线大概率把你从 18-19 拉到 **mid-20s**，做得好接近 P2DNav 的小模型区间；但因为你**不改导航 pipeline**，OSR 上游差距（28 vs 51）很难完全补平，**追平 P2DNav-4B=35 的概率不高**。论文不靠"打赢 P2DNav"，而靠：(1) 干净的受控诊断与归因；(2) 终止决策这个 P2DNav 没解决的转化杠杆；(3) 跨 backbone 一致性。把故事讲在这三点上，比硬刚 SR 数字稳。

## A.5 立即行动

```text
M0  补 A0(4B 裸跑) + OSR→SR 转化率/taxonomy 进 analyze 脚本   ← 仍是地基
M1  B1：SDM 式对话记忆(改成"近端结构化证据 + 远端文本")        ← 先做,最大杠杆
M2  S1：current-view auto-stop(已设计)
M3  B2：方向优先解耦 + direction/target 两层 failure 标签
M4  S2/S3/S4：终止验证全套,明确和 RRM 的目标满足性区分
M5  跨 backbone {A0, full} × {4B,7B,8B}
```
