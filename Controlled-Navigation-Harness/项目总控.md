# Controlled Navigation Harness 项目总控

> 本项目从 Open-Nav v3 主线中拆分出来，作为独立实验项目管理。它不替代当前 Open-Nav v3 执行方案。

---

## 0. 当前一句话

```text
把 Open-Nav 从 LLM-centered navigation pipeline
重构为 controlled navigation harness，
用显式 Tool、State、Verifier、Trace 拆开原本耦合在 LLM 里的职责。
```

当前方案：[[07_Experiment/05_独立项目/Controlled-Navigation-Harness/实验方案|Controlled Navigation Harness 实验方案]]。

---

## 1. 项目边界

本项目要做：

- 围绕 Open-Nav waypoint-based baseline 构建受控 Harness；
- 建立行为不变的 `instrumented / harnessed Open-Nav baseline`；
- 定义 `AgentState`、`MetricsLogger`、`ContextBuilder` 等系统接口；
- 把 GeometryQuery、Grounder、VisualGraphMemory、TargetVerifier、FallbackController 定义为显式 Tool / Skill；
- 通过 rollout trace 支撑失败归因、阶段消融和后续恢复触发。

本项目当前不做：

- 不替代 Open-Nav v3 当前执行方案；
- 不直接切换 waypoint-free；
- 不做自由工具调用式 LLM Agent；
- 不引入在线多 sub-agent 协作；
- 不训练或微调新 policy；
- 不把模型升级混入模块收益。

---

## 2. 当前最小版本

最小可执行版本不是完整系统，而是：

```text
A0 Open-Nav original
  -> 固定原始 baseline

A1 harnessed Open-Nav baseline
  + AgentState
  + MetricsLogger / RolloutTrace
  + A1 waypoint logging
  + GeometryQuery logging
  + B1 Grounder diagnostic
  + C1 VisualGraphMemory diagnostic
  + ContextBuilder skeleton
  + enable_harness_logging = true
  + enable_decision_effect = false
```

第一阶段目标：

- 复现 A0 原始 Open-Nav；
- 建立 A1 行为不变的 harnessed baseline；
- A1 与 A0 的 SR/SPL/NE/TL 基本一致，证明 Harness 外壳不污染 baseline；
- 让 episode 可回放、可诊断；
- 得到 waypoint / geometry-query / grounder / memory / selector 中间指标；
- 为后续模块进入决策链提供证据。

---

## 3. Baseline 改造口径

本项目不是把完整 Controlled Navigation Harness 直接塞进 Open-Nav baseline，而是分三层推进：

| 层级 | 名称 | 行为变化 | 用途 |
|------|------|----------|------|
| A0 | Open-Nav original baseline | 无 | 原始基线复现 |
| A1 | Instrumented / harnessed baseline | 无 | 只加状态、日志、GeometryQuery 和 trace |
| A2+ | Decision-impact variants | 有 | 逐步开启 soft geometry、rerank、memory penalty、verifier、fallback |

论文和实验记录中应把 A1 写成 `instrumented baseline`，不能把 A1 的 trace 完整性或诊断能力写成 SR/SPL 方法收益。从 A2 开始，才进入可声明方法改进的消融链。

## 5. AgentVLN 参考判断

AgentVLN 对本项目的启发主要是架构边界，而不是实验设置本身：

- **采用**：VLM/LLM 只做高层裁决，感知、几何、记忆、验证和恢复交给显式 Tool / Skill。
- **采用**：2D-3D cross-space mapping 的思想，用于候选 waypoint 的几何可解释性诊断。
- **采用**：QD-PCoT 的“缺什么几何信息就查询什么”，但改成受控 Geometry Query，不让 LLM 自由发问。
- **采用方式**：先 logging-only 记录投影有效性、深度有效性和 query-oracle agreement，再决定是否进入 ContextBuilder。
- **暂不采用**：AgentVLN-Instruct 训练、完整 skill-call policy、SLAM / RTAB-Map 栈、在线自由调度器。

## 6. 下一步

1. 固定 A0 原始 Open-Nav 复现配置和日志路径。
2. 建立 A1 harnessed baseline，并验证 A1 与 A0 的 SR/SPL/NE/TL 基本一致。
3. 设计 `AgentState` 字段和 `metrics_logger` trace schema。
4. 确定 A1 GeometryQuery、B1 Grounder、C1 Memory 的 logging-only 最小实现范围。
5. 与 Open-Nav v3 主线保持隔离：任何主线改动必须单独登记。
