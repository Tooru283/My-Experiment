# L1 规格：约束队列式进度定位（替换 `completion_estimation`）

> 蓝本 = CA-Nav 的 **CSM**（[[CA-Nav]]，arXiv 2412.10137）。**只移植 CSM，不移植 CVM**——
> CVM 依赖价值图，我们没有；CSM 只需要"检测器能否确认当前约束"，与地图无关。
> 本规格所有可行性数字均**已在我们自己的 100 集上实测**（见 §2），不是从论文外推。

---

## 0. 一句话

把「每步问 LLM 走到几成」换成「**维护一个有序约束队列，只检查第一个未满足的约束组，全满足才前进一格**」。
进度由**约束满足**驱动，不由**模型自述**驱动。

**这同时解决三件事**：
① `completion_estimation` 的 75 次进度倒退 → **队列单向，结构上归零**；
② 泛类地标实例歧义 → **不需要分辨"哪个 doorway"**，只需判"现在有没有 doorway 在 r 内"，是哪个由前序约束隐式确定；
③ 每步 15.7s 的 LLM 调用 → **热路径零 LLM**。

---

## 1. 为什么循环能破（这是本设计的关键，值得单独写）

我们此前的判断是：泛类地标（doorway/hallway 占锚点 40%，同一步内中位出现在 3 个方向、唯一率仅 14.6%）
无法用外观分辨，唯一依据是"它在序列里的位置"，而那正是待求的量 —— **循环**。

**CA-Nav 的破法是根本不去分辨是哪个。** 因为队列**单向递进**：
判定第 i 个约束时，只回答「**现在有没有一个 doorway 在 r 内**」；
「是哪个 doorway」由「前 i−1 个约束已经满足」隐式确定。

→ **实例级识别被降级为类别级检测 + 顺序。** 循环消失。

⚠ 残留风险：同一步内两个 doorway 都落在 r 内时会**提前推进一格**。这是本设计的主要失效模式，
必须在闸门里单独测（见 §5）。

---

## 2. 可行性：三类约束在我们的数据上都能建（已实测）

**指令分解已经有了**：`episode_metadata` 里 `actions`（有序子动作）+ `landmarks`（有序地标）
均为每集一次的 LLM 产出，**可对全库离线预计算并缓存，热路径零成本**。

实测（100 集）：

| 量 | 值 |
|---|---|
| 每集子动作数 | 中位 **5**，均值 4.7，范围 2–10 |
| **地标能按顺序对齐到动作序列的集** | **91 / 100** |

子动作按约束类型归类（468 条）：

| 类型 | 占比 | 判定器 | 我们有吗 |
|---|---|---|---|
| **location（房间类）** | **37.6%** | VQA "Can you see the \<X\>?" 或闭集房间分类 | ⚠ 需接（SpatialBot 可问；或 SigLIP 闭集 + **MP3D region 标注做标定**） |
| object（含带地标词的） | 36.1% | 开放词汇检测 **∧ 距离 ≤ r** | ✅ RAM 给类别 + 航点距离给几何，**今天可拼** |
| **direction** | **17.9%** | **odometry 位姿窗口**，叉积/点积算转向 | ✅ **零模型**，位姿精确 |
| 未分类 | 8.3% | — | 走弃权 |

**三类判定器我们都有或能便宜得到。真正要新写的只有队列状态机本身。**

## 3. 三类约束的判定规格

### 3.1 Object 约束

`满足 ⟺ 该类别出现在任一候选方向的 RAM 标签中 ∧ 该方向的航点距离 ≤ r`

- CA-Nav 用 GroundingDINO + r≈5m。我们先用 **RAM 标签 + 航点距离**（零新模型）。
- ⚠ **r 必须标定，不能照抄 5m**：我们候选步长中位仅 1.50m，5m 阈值会让几乎所有候选都满足。
  建议先用 **r = 2×步长中位 ≈ 3m** 起步，在留出集上扫。
- **不得用 SpatialBot 报的物体距离**（r=0.171、整数占 86%、已判为负资产）。

### 3.2 Location 约束（占比最大，优先做）

`满足 ⟺ 当前所处区域被判为 <房间类>`

- 这是**区域级**判断，**天然不需要实例消歧** —— 这正是那 37.6% 好做的原因。
- 两条实现路径，**先做后者**：
  - (a) VQA：SpatialBot 问 "Can you see the \<location\>?" → 有现成通路，但引入 LLM 调用
  - (b) **闭集房间分类**：SigLIP 对 ~15 个房间类打分。**MP3D 自带 region 标注 = 免费 GT**，
    可离线标定到指定 precision。**这是唯一能立刻拿到可信精度的一档。**
- ⚠ 前置：先查旧 `grounding_score` 的 `s_room` 是否做过**跨查询归一化**
  （其权重曾拟合为精确 0.000，但那可能是构造性 bug 而非 SigLIP 不行 —— 未查明前不得据此排除 SigLIP）。

### 3.3 Direction 约束

`满足 ⟺ 最近 W 步的位姿变化与要求的转向一致`

- ⭐ **必须用轨迹窗口，不看单帧朝向。** CA-Nav 明说单帧不稳。
  我们 20260720e 的方向先验正是"方向词 vs 候选角度"的**单帧**做法，净负 −0.91/−0.74。
- 实现：取 `positions`/`headings` 在窗口 W（建议 2–3 步）内的变化，叉积定左右、点积定前后。**零模型。**
- ⚠ **预期收益低**：CA-Nav 消融说方向约束"只能进一步微调"。
  **不要把它当主力**——我们已经在这一类上花过一整轮了。

## 4. 队列与切换

```
C = [c_0, c_1, ..., c_N]          # 每个 c_i = 一组约束（可含多类）
j = 0                              # 当前指针，单调不减

每步:
    if all(satisfied(c) for c in C[j]):
        j ← j + 1                  # 只前进一格，永不回退
    # 证据不足 → 保持 j 不变（弃权），不猜
```

**三条结构性保证**（对应 `completion_estimation` 的三个病灶）：

| 病灶 | 结构上如何归零 |
|---|---|
| 75 次进度倒退 | `j` 单调不减 → **归零** |
| 第 1 步就报 100%（69/94 集） | 必须逐格满足才能推进 → **不可能跳格** |
| 29/100 集全程输出不变 | `j` 由外部证据驱动，与模型措辞无关 |

## 5. 预注册闸门

**S1-a（离线，先跑）**：在 100 集 trace 上重放队列，用 GT 参考路径评估。

| 指标 | 闸门 | 现状对照 |
|---|---|---|
| 进度倒退次数 | **≤ 5** | 现 75 |
| 每集 `j` 的不同取值数 | **≥ 4** | 现中位 **2**（每集中位 6 步） |
| `None`/无输出率 | **≤ 1%** | 现 **4%** |
| **提前推进率**（前序约束未真正完成就切换） | **≤ 15%** | 无对照，本设计主要失效模式 |
| 单步耗时 | ≤ 1s | 现 15.7s |

⚠ **S1-a 是必要条件，明确不预测 SR**（项目已三次栽在"每步中间量变好但不转化"上）。
SR 侧的检验放在下游（终止门 / 选路先验），不在这一层。

**S1-b（在线）**：`COMPLETION_ESTIMATION.MODE` 增加 `constraint_queue` 档，与 C1 的 `rule` 档配对比较。

---

## 6. ⚠ 顺序建议：先做中间约束，不是终点约束

CA-Nav 消融的一条硬数字：**只保留最终子指令相关的约束，SR 掉约 21%。**

而我们从 2026-07-06 起的全部设计——目标锚点、终点锚点注册、L4 三重合取终止——**全在终点侧**。
新框架 [[新框架设计-ACN锚点链导航-20260727]] 的 S3（终止）也排在 S2（记忆）之前。

→ **建议把顺序倒过来**：先建能覆盖全程的约束队列（location 那 37.6% 是最大且最好做的一档），
终止判据作为队列的最后一格自然得到，而不是单独设计一套。

**实施顺序**：
1. **离线建队列 + 重放**（零 GPU，用现有 trace）→ 过 S1-a
2. location 判定器接入（先闭集房间分类 + MP3D 标定）
3. object 判定器接入（RAM + 航点距离，r 需标定）
4. direction 判定器接入（纯 odometry）——**放最后，预期收益最低**
5. 在线 S1-b

## 7. 已知风险（写在前面，防止事后找补）

1. **提前推进**：同一步内多个同类地标落在 r 内 → 跳格。已列入闸门。
2. **91% 对齐率意味着 9 集建不出队列** → 这 9 集必须走弃权分支，不能瞎推进。
3. **r 的标定依赖候选步长分布**，若 C2 改了步数预算，r 可能要重标。
4. **SigLIP 的先验证据是负面的**（`s_room` 权重曾为 0.000）。**在查明那是不是归一化 bug 之前，
   不得假定 (b) 路径可行**；若不可行则退 (a) VQA，代价是热路径多一次调用。
5. 本规格的可行性数字来自我们自己的 trace，但**约束判定器的精度全部未测** —— §5 的闸门就是测它。
