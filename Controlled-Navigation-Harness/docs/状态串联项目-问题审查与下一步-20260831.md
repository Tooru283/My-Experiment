# 状态串联项目：问题审查与下一步

> 本文审查 [[全链条重审-状态维度-20260730]]，并以 2026-08-05 的 ACN 离线结果、2026-08-26 的组会材料和当前代码为准，重新整理问题优先级。
>
> 纪律：已验证的事实、工作假说、待验证事项分开写；不把代码存在写成实验成立，不把离线指标写成在线收益。

## 一句话结论

**用空间状态串联整个项目是可行的，但当前还不能直接把它作为在线主干。第一优先级不是继续加模块，而是先得到一个没有数据污染、接线完整的基线；第二步才是把路线状态统一起来；第三步才是逐个做在线因果实验。**

本轮暂定的科研方向是：**用空间状态串联整个项目，论文先偏向问题诊断与架构解释，而不是先承诺一个新的模型或一个固定的性能增益。**

已经确认的设计原则：**停止必须由多项证据共同决定。** 还没有确认的策略：进度是否严格单调、一次是否只能推进一个目标、证据不足时是否一律弃权。这三点先作为对照实验，而不是写成系统公理。

当前最危险的误区是：空间图、进度队列和终止门已经有代码，于是误以为“状态已经进入系统”。实际上，当前配置下它们主要仍在记录；唯一明确参与多步决策的阶段信号还包含一条需要重新审计的目标距离变化路径。

## 一、对 20260730 文档的审查

### 1. 仍然成立的部分

| 原文判断 | 当前依据 | 现在应如何表述 |
|---|---|---|
| 每步让模型自报进度不可靠 | 早期报告第 1 步报满、出现进度倒退；后续配对测量中，约束队列与测地进度的相关性高于模型自报 | **模型自报进度不能作为唯一状态源** |
| 固定决策点上的选路能力很弱 | 三种模型在图像决策点上约为 39%–43%，没有随模型变大而上升 | 这是**无持久状态、固定候选接口下的决策点上限读数**，不是所有导航架构的总上限 |
| 状态需要外置维护 | 锚点链、空间图、地标池和单调进度队列都已经有代码或离线重放 | 这是当前的**工作假说和工程主线**，在线收益尚未证明 |
| 不能直接照搬论文分数 | AgenticNav、SpaceVLN 等同时改变了记忆、规划和动作接口 | 文献只提供结构启发，不能直接当成本项目的收益预估 |

### 2. 需要改写或降级的部分

#### A. “两个累积器被硬锁死”已经过时

原文把 `MEMORY_DIAGNOSTIC` 和 `VISUAL_EVIDENCE_MEMORY` 都写成被 `ValueError` 强制锁在日志侧。当前代码已经发生变化：

- `MEMORY_DIAGNOSTIC`、`PROGRESS_LOCATOR`、`TERMINAL_GATE` 在全局允许决策作用时可以进入白名单；
- `VISUAL_EVIDENCE_MEMORY` 仍不能直接改变决策；
- 当前 `run_OpenNav.yaml` 没有打开这些空间状态模块的决策作用，ACN 相关模块仍按默认值 `LOG_ONLY: true` 运行。

所以现在准确的说法是：**空间状态模块已经能记录，也部分具备接入决策的接口，但当前运行配置还没有形成一条真正统一的状态决策链。**

#### B. “L4 可以阻止停止”目前不是代码事实

`base_il_trainer_llm.py` 会计算 `terminal_gate_decision_effect`，也会把 `terminal_gate_results` 写入日志；但当前代码检索没有发现它参与 `stop_flag` 的主分支。也就是说，终止门目前是**评估器/日志器**，不是已经生效的停止门。

这件事必须先补单元测试和接线审计，再讨论“终止门是否减少假停”。否则离线判决表和在线行为不是同一个机制。

#### C. “状态是唯一缺失维度”不能写成定论

现有证据支持状态假说，但还没有本项目自己的在线干预结果。图像输入的决策点实验只说明：在固定决策点上，直接看图比文本好一些，但三种模型仍在 39%–43% 一档。它不能单独证明空间状态一定能带来多少 SR 或 OSR。

准确表述应是：

> **当前最值得优先验证的解释是：系统把一个需要跨步状态的任务，压成了无状态的单步候选选择。**

#### D. 数字口径必须以后续勘误为准

- 20260719 trace 的官方指标是 SR 20 / OSR 25；历史挂牌基线仍是 SR 16 / OSR 21，不能混成一条曲线；
- 旧的 `r=0.120` 已被后续配对测量改写，不再作为当前 L1 对照；
- L4 首轮较乐观的数字已经因严格匹配修正，不能继续引用旧的 allow 精度和 kill 面；
- 2026-08-05 之后本地 `logs/` 未发现新的导航运行记录，因此目前没有新的在线 SR/OSR A/B 结果。

## 二、当前真正的问题

下面按“先不解决就不能相信后面的实验”的顺序排列。

### P0：基线和决策路径还不干净

#### P0.1 当前阶段判断含有目标距离变化信号

当前 `run_OpenNav.yaml` 使用 `U_SERIES.DECISION_EFFECT_UNIT: combined`，其中 `PHASE_EVIDENCE.LOG_ONLY: false`。`phase_evidence.py` 会根据 `recent_distance_gains` 的非正次数进入 `recover` 分支；训练器把动作后的目标距离变化放入这个列表。

这条路径来自模拟器的目标距离，必须按 GT 风险处理。它不是视觉或语言观察得到的状态。如果它影响了阶段、选路上下文或恢复动作，那么这份配置不能作为干净的 oracle-free 基线。

**处理方式**：先保留日志，停止它参与决策；或者删除这条分支，改用空间图、动作失败和可观测证据定义阶段。改完后做一次全路径 grep 和小规模审计，再重新命名基线。

#### P0.2 配置已经容易漂移

历史文档里同时存在 SR16/OSR21、SR20/OSR25、不同步数上限和不同决策开关。每次新实验必须保存：

```text
配置文件哈希
模型名称和推理后端
所有 ENABLED / LOG_ONLY / decision-effect 开关
步数预算
数据与 trace 路径
```

没有这份快照，就不能把两轮结果称为配对 A/B。

### P1：空间状态已经拆成多个零件，还没有一个总状态

目前至少有以下几种状态来源：

| 状态 | 当前作用 | 主要缺口 |
|---|---|---|
| 锚点链 | 保存指令中的有序目标 | 约 9% 锚点无法形成可检查约束；对齐质量还要单独抽检 |
| 进度队列 | 维护单调的目标指针 | 进度倒退为 0，但每集不同取值中位仍约 2，未过原闸门 |
| 空间图 | 记录位置、重访和未探索方向 | 候选新颖度仍有坐标符号问题；图还没有成为统一决策输入 |
| 地标池 | 跨步累积地标证据 | 位置是方向级近似，不是实例级身份；严格匹配和到达证据仍需标定 |
| 阶段信号 | 给选路器提供 search/approach/recover 等上下文 | 当前实现混入模型自述，并存在目标距离变化审计风险 |
| 导航历史 | 把摘要后的观测和想法放回 prompt | 主要是模型对自身输出的再摘要，没有外部证据校验 |

**核心问题不是零件数量少，而是没有唯一的“路线状态”作为下游共同读取的事实源。**

### P2：进度判定的“能运行”还没有变成“判得对”

当前 L1 的结构性优点是进度不会倒退；但这只能证明状态机的形式约束成立，不能证明每次前进都正确。

还缺三类证据：

1. 房间判定的 precision：目前主要测了选择性，尚没有足够的 MP3D region 标注校准；
2. 物体判定的误报/漏报分解：严匹配后，新的主要卡点是 object 约束，但其中很多是 agent 没走到，并非检测器漏报；
3. 同一步出现多个相同类别地标时，单调队列是否会提前推进。

因此，L1 还不能直接替换在线进度估计，更不能直接让终止门生效。

### P3：有明确的代码接线和几何风险

- `visual_graph_memory.py` 的候选世界坐标仍使用与已标定约定相反的角度符号；目前主要污染 `candidate_novelty`，翻开关前必须修复或彻底隔离；
- `PROGRESS_LOCATOR` 的决策作用打开时，当前实现仍先调用一次 LLM 的 `completion_estimation`，再用队列文字覆盖结果。因此“省掉 15.7 秒/步”尚未兑现；
- 终止门的结果被记录，但没有证据表明它真正改变了主停止动作；
- 视觉证据、地标池、空间图和进度队列各自有事件，但还没有统一事件版本、时间戳和证据来源字段。

### P4：研究问题仍有两个未隔离的替代解释

1. **空间状态不足**：无状态单步选择的确很弱，文献也反复显示记忆和阶段规划有价值；
2. **动作接口受限**：当前航点候选可能没有提供足够的可执行方向，但对 9B 直接换成纯原语也有负面外部证据。

所以现在不能直接重写成 BEV 或 waypoint-free。先把空间状态在现有航点接口上做成一个可验证的中间层，才能知道问题究竟来自状态还是动作接口。

## 三、建议的统一状态

把空间状态定义成一个每步更新、但允许暂不确定的对象。名字可以叫“路线状态”，不再为它引入更大的理论术语。

```text
RouteState
├─ plan                    有序目标、检查条件和目标版本
├─ progress                当前目标、已确认目标、候选下一目标
├─ spatial_graph           已访问位置、已走边、曾提供但未选的边
├─ landmark_memory         地标类别、粗位置、可见性、到达证据
├─ loop_status             重访次数、当前节点、未探索分支
├─ budget                  已用步数、剩余预算、是否接近上限
├─ failure_status          最近一次可观测失败及其来源
├─ stop_evidence           各项停止证据、缺失项和最终判定
└─ provenance              每个字段的来源、置信度、是否弃权、是否影响决策
```

### 1. 必需字段与暂缓字段

第一版只需要保证状态能被复现和审计，不追求完整场景理解：

| 类别 | 第一版必须有 | 暂缓到后续 |
|---|---|---|
| 路线目标 | 目标顺序、当前目标、目标检查条件 | 复杂的自然语言重写和开放式子任务 |
| 进度 | 当前指针、历史指针、每次变更的证据 | 学习型进度预测器 |
| 空间 | 位姿节点、已走边、已提供但未选的方向、访问次数 | 完整三维场景重建 |
| 地标 | 类别、粗位置、可见性、到达证据 | 同一物体的精确实例身份 |
| 失败 | 停止被拒、动作停滞、回环、预算耗尽 | 自动恢复策略和主动回溯 |
| 停止 | 多项证据的逐项结果和缺失原因 | 单一综合置信度分数 |
| 审计 | `source`、`confidence`、`abstained`、`decision_effect`、版本号 | 更复杂的因果归因字段 |

每个字段必须注明来源：

| 字段 | 合法来源 | 禁止来源 |
|---|---|---|
| 位置和边 | agent 位姿、候选几何、实际执行动作 | 目标真值距离 |
| 地标 | RGB、RAM 标签、深度和几何融合 | 目标真值地标位置 |
| 当前目标 | 锚点链 + 已验证证据 | LLM 自报“我已经完成了” |
| 失败状态 | 选路为空、动作停滞、拓扑回环等可观测信号 | 事后读取成功标签 |
| 停止证据 | 进度、历史验证、当前地标证据 | 单独一条置信度或目标距离 |

状态更新的顺序先固定，进度策略暂不固定：

```text
读入当前观察
  → 更新空间图和地标池
  → 更新当前目标的证据
  → 按待验证的进度策略推进、保持或弃权
  → 计算回环/失败/预算状态
  → 规划当前目标
  → 选择动作
  → 记录动作后的状态
```

所有下游只读这个对象，不再分别读取旧的自述摘要、独立阶段猜测和临时字符串。进度策略需要保留三种候选，而不是提前选死：

| 策略 | 定义 | 要回答的问题 |
|---|---|---|
| A：保守推进 | 严格不回退、每次最多推进一个目标、证据不足就保持 | 是否能显著降低提前推进和错误停止 |
| B：连续推进 | 保持不回退，但同一步满足多个目标时允许连续推进 | A 是否只是把真实进度压得过慢 |
| C：带修正推进 | 允许在新证据下修正最近状态，但不能改写已确认的历史 | 严格单调是否牺牲了必要的纠错能力 |

“证据不足就弃权”是 A 的默认候选，不是已经验证的结论。三种策略先在同一批 trace 上比较，不能用不同数据或不同模型混淆结果。

### 2. 已确定的停止原则

停止和进度策略分开处理。停止必须同时检查多项证据，至少记录：

1. 当前目标链是否完成；
2. 先前目标是否有历史验证；
3. 最终地标是否有当前或跨步证据；
4. 是否存在明确的失败、回环或预算冲突。

任何一项不满足，都只能输出“暂不允许停止”及缺失原因，不能用一个总置信度覆盖具体证据。

## 四、下一步执行顺序

### 第 0 步：先做出可信基线

1. 固定当前 YAML、模型、数据路径和运行后端，生成配置快照；
2. 停止 `phase_evidence` 使用目标距离变化参与决策，保留同名日志字段但标记为 audit-only；
3. 做全路径 oracle 审计：从输入、状态更新、阶段判断到动作选择逐层检查；
4. 跑一个小规模 smoke，确认配置横幅、事件计数和停止路径都与预期一致；
5. 重新生成一份明确命名的 oracle-free baseline。

**通过条件**：没有目标真值进入决策；每个启用模块的 `LOG_ONLY` 和 decision-effect 状态都能在 trace 中复核；小规模运行无异常停止或事件缺失。

### 第 1 步：补齐状态层的工程闭环

1. 修复或隔离 `candidate_novelty` 的坐标符号问题，并加一个已标定候选坐标的单元测试；
2. 给 `RouteState` 定义统一 schema 和版本号；
3. 让锚点链、进度队列、空间图、地标池、失败状态都写入同一个 step 记录；
4. 给每个字段加 `source`、`confidence`、`abstained` 和 `decision_effect`；
5. 修正终止门接线：先用单元测试证明它能阻止不满足条件的 STOP，再做在线实验；
6. 在进度队列通过独立闸门之前，不删除原有 LLM 进度调用。

**通过条件**：同一个 step 能还原完整路线状态；状态不跨 episode 泄漏；终止门的日志结果和实际动作结果一致；所有状态字段均能追溯到合法输入。

### 第 2 步：只做离线判定器校准

按顺序处理：

1. 用 MP3D region 标注校准房间判定的 precision/recall；
2. 用严格词匹配和候选几何拆分物体判定的误报、漏报和“根本没走到”；
3. 测量多个相同地标同时出现时的提前推进率；
4. 在同一批 100 集 trace 上分别重放 A/B/C 三种进度策略；
5. 重新跑 100 集 L1 回放，保留旧闸门，不因结果不好就事后改门槛；
6. 若旧闸门确实不适合当前步数分布，单独写一份预注册修订记录，再开始下一轮。

**通过条件**：不能只看“不倒退”。三种策略都要报告前进 precision、提前推进率、弃权率、每集进度覆盖度和停止证据缺失率；这一步只决定哪种状态更新策略值得上线，不直接声称 SR 提升。

### 第 3 步：做单变量在线实验

在线实验必须按以下顺序，且每次只改变一件事：

1. **限制过早停止**：先小规模确认停止门真的触发，再看假停是否转成耗尽；
2. **增加行动步数**：在停止限制的结果明确后，再看接近目标的集是否能继续走到目标，同时监控 SPL 和远离目标的集；
3. **接入经过校准的路线状态**：先只让进度状态进入上下文，不同时打开终止门和回环告警；
4. **接入多证据终止门**：确认它真的改变 STOP，并观察假停、耗尽和成功集的转移；
5. **接入拓扑回环告警**：单独记录告警后的换向率、重访率和假停变化；
6. 只有前面出现稳定信号，才做规划器/执行器分层原型。

每轮都同时记录：SR、OSR、SPL、假停、耗尽、重访、轨迹长度、状态覆盖度、告警后的行为变化和运行时间。命中率只能作辅助指标，不能作为唯一上线依据。

### 第 4 步：再决定是否改变动作接口

如果路线状态已经通过离线和在线验证，但 OSR 仍被候选覆盖限制，再做局部动作 probe：

- 只选高 regret 决策点；
- 比较现有航点、固定角度原语和短距离连续动作；
- 只判断是否出现新的可执行方向，不直接宣称 SR 提升；
- 只有发现现有航点确实无法表达关键动作，才考虑重写动作主干。

## 五、近期停止条件

以下任一情况出现，就暂停扩大实验规模：

- 配置快照和实际 trace 的开关不一致；
- 仍有目标距离或成功标签进入决策路径；
- 终止门只写日志、没有改变实际 STOP，却被当成在线机制；
- 进度队列的前进 precision 没有校准；
- 多个状态模块各自输出不同的“当前目标”；
- 单轮同时打开停止限制、行动预算、图像证据和拓扑告警，无法归因；
- 只看到命中率变化，没有米制 regret、失败结构或 OSR 的配套变化。

## 六、目前不建议投入

- 继续换更大的同骨架模型：三档模型已在相近水平，区分性不足；
- 继续堆 prompt 或让模型自报困惑：此前信号接近随机；
- 直接移植完整 TSDF/BEV 或 waypoint-free 主干：当前状态链和基线还没有清理完；
- 更换开放词汇检测器作为第一反应：现有分析显示很多 object 卡点是没有走到，而不是检测器没认出来；
- 把文献中的记忆增益、L4 离线 allow 精度或 43% 决策点结果直接换算成 SR 预期。

## 七、给项目的最终判断

当前项目不是缺少更多孤立模块，而是缺少一条可以被审计、被回放、被下游共同读取的路线状态链。

下一阶段最重要的成果不一定是立刻涨 SR，而是完成下面这个闭环：

```text
指令中的目标
  → 外部证据形成路线状态
  → 路线状态驱动当前目标和动作
  → 动作结果更新路线状态
  → 失败与停止都能解释、复现、归因
```

如果这个闭环建立后在线 OSR 仍没有变化，才能有根据地说“问题不只在状态”，再把研究重点转向动作接口或训练主干。现在直接跳到后两者，仍然会重复过去“先改大模块、后补前提验证”的问题。

## 八、暂定的科研产出定位

现阶段先不把目标写成“提出一个一定提升 SR 的新模型”。更稳妥的主线是：

1. **问题诊断**：量化无持久状态时，单步候选选择能达到什么水平，以及错误如何转化为走不到、提前停止和反复重访；
2. **架构解释**：说明路线状态、空间记忆、进度和停止证据分别解决什么问题，哪些信息在当前系统中被丢弃或交给模型自述；
3. **可验证的状态框架**：给出统一的 `RouteState`、证据来源和单变量实验协议，比较不同进度更新策略，而不是先承诺某个固定增益。

因此近期论文材料应优先形成：

- 一套经过 oracle 审计的基线和失败分类；
- 一组固定决策点上界与空间状态缺口的证据；
- 一个能被离线回放、逐项解释、再进行在线 A/B 的路线状态框架。

只有在此基础上出现稳定的在线变化，才把“方法提升”放到标题和主结论中。
