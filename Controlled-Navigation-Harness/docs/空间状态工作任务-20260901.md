# 空间状态工作任务：路线状态闭环与可审计实验

> 本文是当前空间状态工作的执行入口。它整理并替代原“状态串联项目：问题审查与下一步”中的行动计划，但不删除、不覆盖原文。原文保留为问题审查和历史判断依据。
>
> 记录纪律：已验证事实、工程完成项、研究假设和待验证事项分开写。代码已经存在不等于在线收益已经成立；离线指标不直接等于 SR/OSR 提升。

## 0. 当前结论

本项目现在要解决的不是“继续增加一个记忆模块”，而是建立一条可以被复现、回放和归因的路线状态链：

```text
指令目标
  → 当前观察和可观测动作结果
  → RouteState
  → 当前目标 / 选路 / 是否允许停止
  → 执行动作
  → 动作后的 RouteState
```

研究问题暂定为：**在固定航点动作接口和固定模型条件下，统一的外部空间状态是否能减少走不到、提前停止和重复重访。**

当前不承诺新的 SR 增益。第一阶段的成功标准是状态链干净、接线正确、证据可追溯；第二阶段才判断哪一种状态更新策略值得进入在线决策。

## 1. 证据口径

### 1.1 已知事实

| 事实 | 当前口径 | 用途 |
|---|---|---|
| 无持久状态时的固定候选选择较弱 | 三档模型约 39%–43%，不能视为所有导航架构的上限 | 支持优先验证状态假设 |
| 模型自报进度不可靠 | 历史 trace 出现进度倒退和早期报满 | 不再把自报作为唯一状态源 |
| waypoint 不能直接丢弃 | 同模型外部对照中纯原语显著弱于带航点条件 | 保持现有动作接口，先隔离状态因素 |
| ACN 零件已有实现 | L0 锚点链、L1 约束队列、M1 空间图、M2 地标池、L4 终止门已存在 | 当前任务从“有无模块”转为“能否闭环” |
| L1 尚未通过上线闸门 | 形式上不倒退，但历史离线回放中推进不足、弃权较多 | 先做判定器校准，不直接切换在线进度 |
| 历史结果存在配置混用 | 2026-07-19 官方口径为 SR 20 / OSR 25；挂牌 clean baseline 仍记录 SR 16 / OSR 21 | 每轮必须使用配置快照和逐集 episode_end 指标 |

### 1.2 当前假设

1. 主要问题可能是把需要跨步记忆的任务压成了单步候选选择，但该解释尚未通过在线因果实验。
2. 空间状态首先应作为可审计事实源，而不是立即变成复杂规划器或学习型信念。
3. 进度的“严格单调”“一步最多推进一个目标”“证据不足就弃权”都应作为可比较策略，而不是预先写成公理。

### 1.3 未验证事项

- RouteState 接入后是否改变在线动作分布和失败结构；
- L1 房间、物体、方向判定的 precision/recall；
- 同类地标同时出现时是否提前推进；
- L4 终止门阻止 STOP 后，假停是否减少，还是仅转化为耗尽；
- 航点候选覆盖不足是否仍是 OSR 的主要限制；
- 当前配置中 V2、候选先验、回溯等其他决策机制对结果的贡献。

## 2. 当前工作的边界

### 2.1 本阶段要做

- 固定一个有配置 provenance 的 oracle-free 状态阴影基线；
- 统一 L0/L1/M1/M2/L4 的记录形态；
- 保证每个状态字段有来源、置信度、弃权和决策作用标记；
- 用同一批 trace 离线比较进度策略；
- 通过单变量 A/B 判断状态模块是否值得进入在线动作链。

### 2.2 本阶段不做

- 不直接更换 backbone，不以换大模型代替状态实验；
- 不直接重写为 BEV、TSDF 或 waypoint-free 主干；
- 不把命中率变化当作上线闸门；
- 不把目标距离、成功标签或事后测地距离放进在线 RouteState；
- 不同时打开停止限制、路线状态、回环、动作预算和候选重排再解释结果。

## 3. 已完成的工程工作

截至 2026-09-01，以下工作已经落地。它们是工程完成项，不是在线收益结论。

### 3.1 Oracle 隔离

- `run_OpenNav.yaml` 中 U1/U2/U3 已设为 `LOG_ONLY: true`，`U_SERIES.DECISION_EFFECT_UNIT: none`；
- `phase_evidence.py` 不再用 `recent_distance_gains` 触发 `recover`；
- 目标距离变化保留在 trace 兼容字段中，并明确标记为 `simulator_goal_distance_audit_only`、`decision_effect: false`、`abstained: true`；
- failure diagnostic、STOP rescue blocker 和 phase-aware scaffolding 不再把该距离变化传递给选路或恢复；
- RouteState 递归排除 `latest_goal_dist`、`distance_to_goal`、`distance_gain_selected`、`recent_distance_gains`、`success` 和 `oracle_success`。

### 3.2 统一 RouteState

新增 `vlnce_baselines/common/opennav_ext/route_state.py`，schema 为 `route_state.v1`，包含：

```text
plan              指令、动作、地标、锚点链
progress          当前指针、已确认索引、完成状态、阶段
spatial_graph     节点、访问次数、已走方向、未探索分支
landmark_memory   地标池大小、可见数、到达数、条目
loop_status       回环和重访状态
budget            步数、上限、剩余预算
failure_status    可观测失败及来源
stop_evidence     STOP 请求、终止门结果、缺失证据
provenance        来源、置信度、弃权和 decision_effect
```

训练器已经在同一步写出 `pre_action` 和 `post_action` 两类 RouteState 事件，并通过相同的 `write_navigation_record` 写入导航记录。

### 3.3 生命周期和终止接线

- L0 锚点链、L1 进度队列、M2 地标池的 reset 已从每次循环移动到 episode 边界，避免跨步状态被反复清空；
- 新增 `gate_stop_request`，L4 在 decision-effect 开启时可以把不满足合取条件的 STOP 转成继续行动；
- 终止门拒绝会写入 `terminal_gate_rejected`，用于检查“拒绝日志”和实际动作是否一致；
- L4 仍只能阻止 STOP，不能单独制造 STOP；degenerate 链路按既定策略弃权。

### 3.4 几何和审计工具

- 修复 `visual_graph_memory.py` 中候选新颖度的航向符号，使其与 M2 的已标定 waypoint 投影一致；
- `run.py` 会保存 secret-redacted 的 resolved config、配置哈希、模型和数据元信息；
- 新增 `scripts/audit_route_state_trace.py`，检查：
  - `run_metadata` 是否存在且包含配置快照和哈希；
  - `route_state` 是否存在、schema 是否为 `route_state.v1`；
  - RouteState 是否递归泄漏 oracle 字段；
  - L4 拒绝 STOP 后同一步是否仍发出 STOP。

### 3.5 已完成验证

- 5 个纯模块回归测试通过：oracle 隔离、RouteState 过滤、L4 接线、episode reset、候选几何符号；
- 修改模块通过 `py_compile`；
- `git diff --check` 通过；
- 改动前历史 trace 被新审计器正确拒绝，因为缺少 `run_metadata` 和 `route_state`。

运行时 smoke 尚未完成：当前开发环境缺少 `habitat_baselines` 和 `PyYAML`，不能把本地静态验证写成完整实验验证。

## 4. RouteState 规范

### 4.1 合法来源

| 状态内容 | 合法来源 | 禁止来源 |
|---|---|---|
| 目标顺序 | 指令解析、锚点链 | LLM 自报已完成 |
| 当前进度 | 约束队列和可观测匹配证据 | 目标真值距离、成功标签 |
| 位姿和边 | agent 位姿、候选几何、实际动作 | 测地距离 |
| 地标证据 | RGB、RAM、深度、候选几何融合 | 目标地标真值位置 |
| 失败状态 | 候选为空、动作停滞、回环、STOP 被拒 | 事后成功标签 |
| 停止证据 | 进度、历史验证、当前地标、预算和失败状态 | 单一总置信度或目标距离 |

### 4.2 更新顺序

每步按以下顺序组织；策略可变，但顺序和事件契约不能随实验臂改变：

```text
读入观察
  → 更新空间图和地标池
  → 更新当前目标证据
  → 按 A/B/C 进度策略推进、保持或弃权
  → 计算回环、失败和预算状态
  → 生成当前阶段和规划上下文
  → 选择动作或提出 STOP
  → 记录 pre_action
  → 执行动作
  → 记录 post_action
```

### 4.3 进度策略

| 策略 | 定义 | 主要指标 |
|---|---|---|
| A 保守推进 | 单调不回退；每步最多推进一个目标；证据不足保持 | 前进 precision、弃权率、提前推进率 |
| B 连续推进 | 保持单调；同一步满足多个目标时允许连续推进 | 是否减少过慢推进和无效停留 |
| C 带修正推进 | 可修正最近未确认状态，但不能改写已确认历史 | 错误修正率、历史一致性 |

A 是第一候选，不是结论。三种策略必须在同一批 trace、同一解析结果和同一阈值记录上重放。

## 5. 当前配置与基线定义

当前 `run_OpenNav.yaml` 不是完全关闭所有机制的纯基线，而是带有若干已存在决策机制的状态阴影配置。当前边界如下：

| 组件 | 当前状态 | 解释 |
|---|---|---|
| `GEOMETRY_INJECTION` | `False` | 不把 WaypointBert 距离注入导航观察 |
| U1/U2/U3 | `DECISION_EFFECT_UNIT: none`，各自 log-only | 空间状态相关 U 系列只记录，不改动作 |
| V1/V3/V4 | 记录或构造证据，V4 log-only | 视觉证据链仍在运行，不能把它当作状态干预结果 |
| V2 `VISUAL_TARGET_VERIFIER` | 当前为 decision-active | 必须在 A/B 中固定，不可与状态开关同时改变 |
| depth stop veto | 当前为 enabled | 只使用深度观测，但仍属于独立停止机制 |
| `CANDIDATE_PRIOR` | 当前为 decision-active | 属于独立选路机制，必须固定 |
| `BACKTRACK` | 当前为 enabled | 属于独立恢复机制，必须固定 |
| ACN RouteState | 记录已接线 | 运行前必须通过 trace 审计确认 |

因此新运行应使用明确的实验名，例如 `state_shadow_v1`，并在结果目录中保存 manifest。没有 manifest 的运行不能作为配对 A/B 对照。

## 6. 工作任务队列

### T0：重建可审计 smoke（当前队首）

**目标**：在具备完整 Habitat/场景/模型依赖的环境中跑少量 episode，确认新接线真的进入热路径。

**步骤**：

1. 固定模型、推理后端、数据 split、seed、步数预算和 YAML；
2. 用 `EVAL.EPISODE_COUNT=5` 跑 smoke；
3. 检查配置横幅、`run_manifest.json` 和 `resolved_config.yaml`；
4. 运行 `scripts/audit_route_state_trace.py <trace_dir>`；
5. 抽查 2 个 episode：每步是否有 RouteState，episode 内 reset 是否只出现一次；
6. 抽查有 STOP 的 step：L4 拒绝事件和 `action_pre_step` 是否一致。

**通过条件**：

- 所有 trace 有 `run_metadata`；
- RouteState 覆盖 pre/post action，schema 固定为 `route_state.v1`；
- RouteState 不含禁止字段；
- 未出现“终止门拒绝 STOP 后仍发送 STOP”；
- 配置快照、trace 开关和实际实验名一致。

### T1：完成离线状态校准

**目标**：判断 L1/M2/L4 是否“判得对”，而不只是“代码能运行”。

**任务**：

- 用 MP3D region 标注校准 location 判定 precision/recall；
- 分解 object 判定为误报、漏报和 agent 尚未走到；
- 检查同类地标多方向出现时的提前推进率；
- 在同一批 100 集 trace 上重放 A/B/C 三种进度策略；
- 保留旧闸门和阈值，任何修改写入单独的预注册修订记录。

**最低输出**：前进 precision、提前推进率、弃权率、每集进度覆盖度、停止证据缺失率、L4 各合取项通过率。

### T2：建立状态阴影控制组

**目标**：证明 RouteState 记录本身不会改变动作，并固定所有非状态机制。

**要求**：

- 同一模型、同一 split、同一 seed 和同一 episode 列表；
- U 系列保持 `none/log-only`；
- V2、depth veto、candidate prior、backtrack 的配置在所有臂中完全相同；
- 不用新的配置覆盖历史 trace；
- 结果目录、配置哈希和运行后端进入 manifest。

### T3：单变量在线实验

必须按下列顺序，每次只改变一个主要决策面：

| 顺序 | 实验臂 | 前置条件 | 观察重点 |
|---:|---|---|---|
| 1 | L4 多证据终止门 | T0 通过；离线停止证据已抽检 | 假停、耗尽、真停误杀、拒停后行为 |
| 2 | L1 进度状态进入上下文 | T1 的进度策略通过独立闸门 | 进度前进 precision、米制 regret、OSR |
| 3 | M1 回环告警 | 先固定 L1/L4 结果 | 重访率、告警后换向率、耗尽 |
| 4 | 多模块合并 | 单变量结果方向稳定 | 交互效应，不作为第一轮结论 |

原先提出的“禁早停 + 增加预算”仍可做，但必须先作为独立的停止/预算实验完成，不能和路线状态第一轮合并。它们改变的是失败转化和轨迹长度，不等于状态效果。

### T4：动作接口 probe

只有在 RouteState 已通过离线和在线验证，而 OSR 仍显示候选覆盖限制时执行：

- 只抽高米制 regret 决策点；
- 比较现有航点、固定角度原语和短距离连续动作；
- 先报告是否出现新可执行方向，不直接声称 SR 提升；
- 只有证实航点表达能力不足，才考虑主干重写。

## 7. 统一评测与报告模板

每一轮至少报告以下四组结果：

### 7.1 主指标

`SR`、`OSR`、`SPL`、`nDTW`、`NE`，以及有效 episode 数。

### 7.2 失败结构

假停、耗尽、环境结束、动作停滞、回环、STOP 被拒、达到预算但未成功、成功后未停止。

注意：步数达到上限不自动等于耗尽失败；必须根据 `episode_end` 和轨迹结果分类。

### 7.3 状态与因果指标

- L1：前进 precision、回退次数、弃权率、`j/N` 分布、每集不同进度取值数；
- M1：重访率、节点数、未探索分支数、告警后的方向变化；
- M2：池大小、目标词覆盖、visible/arrived 的严格匹配率；
- L4：各合取项通过率、拒绝原因、拒绝后的实际动作；
- 选路：米制 regret、候选覆盖、候选先验干预率；
- 工程：每步延迟、LLM/VLM 调用数、轨迹长度、预算消耗。

### 7.4 配对纪律

在线 A/B 必须使用同一 episode 列表、同一模型、同一数据和同一 seed。报告逐集翻转表和配对统计；不能只报告均值，也不能用不同配置目录名替代配置快照。

## 8. Go / No-Go 条件

### 允许进入下一阶段

- smoke 审计通过；
- trace 能完整还原一个 step 的 RouteState；
- 所有在线决策字段有合法来源；
- L1 的 precision 和提前推进率已有独立校准；
- 单变量实验中出现可解释的失败结构变化，而不只是命中率波动。

### 必须暂停

- 配置快照与 trace 开关不一致；
- RouteState 或其他决策上下文出现目标距离、成功标签等 oracle；
- L4 只产生日志，实际 STOP 未改变，却被当作在线机制；
- L1 只证明“不回退”，没有证明“推进正确”；
- 同一轮同时改变多个停止、状态和恢复开关；
- SR 变化没有 OSR、SPL、regret 或失败结构配套解释；
- 新状态模块造成跨 episode 泄漏、事件缺失或不可重放。

## 9. 近期具体执行顺序

当前按以下顺序推进，不提前扩大规模：

1. 在完整实验环境跑 `state_shadow_v1` 的 5 集 smoke；
2. 运行 RouteState trace 审计并保存审计输出；
3. 抽查 episode reset、pre/post action 和 STOP 拒绝一致性；
4. 对 L1 location/object/direction 做离线标注抽样；
5. 在同一批 trace 上重放 A/B/C 进度策略；
6. 只有 T1 通过后，才把 L1 或 L4 单独切入在线 100 集；
7. 100 集结果稳定后，再决定是否做更大规模复验。

## 11. 预期产出

近期产出不以“提出一个一定涨 SR 的新模型”为目标，而是形成三个可审计资产：

1. **干净基线**：配置、模型、数据、开关、trace 和运行结果可以互相校验；
2. **路线状态框架**：RouteState、证据来源、进度策略和终止判定可以离线回放；
3. **因果实验结果**：每个在线状态干预都有独立对照、失败结构和成本报告。

如果状态闭环建立后 OSR 仍不变，才有依据把研究重点转向动作接口或训练主干；在此之前不再进行无归因的大模块替换。
