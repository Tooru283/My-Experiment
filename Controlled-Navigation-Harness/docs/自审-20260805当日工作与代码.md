## 1. 🔴 主要发现：子串匹配 bug（已修）

### 病灶

`progress_locator._satisfy_object` 首版的判据是

```python
if head in t or t in key:   # head = 约束词的中心词，t = RAM 标签
```

**两个方向都是裸子串。** 在 100 集 trace 上审计：

| | 匹配次数 |
|---|---:|
| 现行（裸子串） | 1714 |
| 词级+词干 | 947 |
| **差 = 子串假阳** | **767 = 44.7%** |

最严重的几条**不是边缘情况**：

| 约束词 ← RAM 标签 | 次数 | 判定 |
|---|---:|---|
| `bed` ← `bedroom` | **119** | 🔴 在卧室里 ≠ 到了床边 |
| `red carpet` ← `red` | 22 | 🔴 |
| `white rug` ← `white` | 19 | 🔴 |
| `bed` ← `bedcover` | 12 | 🔴 |
| `bar` ← `barber shop` | 10 | 🔴 |
| `frame on the wall … "welcome"` ← `wall` | 19 | 🔴（顺带暴露 L0 产出了 13 词的垃圾"地标"） |
| `door` ← `doorway` | 194 | ✅ 合理 |
| `stairs` ← `stair` | 41 | ✅ 合理 |

**为什么这是严重 bug 而不是小噪声**：约束一旦满足就**推进队列**，所以每一次假阳都是一次
**提前推进** —— 而"提前推进率 ≤15%"正是 L1 预注册的**头号失效模式**。

### 修法

换成 **词边界 + 极简词干（只去复数 -s）+ 一张显式变体表**（`door/doorway`、
`stairs/staircase|stairway|stairwell|steps`、`rug/carpet`、`couch/sofa`、`tub/bathtub` …）。
理由：**一张手列的表可以被复核，一条子串规则不能。**

M2 的 `LandmarkPool.query()` 和词表准入原本是同一类裸子串写法，**已统一改用同一个
`term_matches`** —— 一个匹配器，一次审计覆盖两处。

## 3. 🔴 既有记录里的一条事实错误

日志里写着 20260719 目录下是"**两份逐字节相同的 run**，glob 把每集数了两遍"。
**实测：两份 run 的 md5 不同。**

| | run A (001700) | run B (130559) |
|---|---|---|
| 轨迹 / 步数 | **完全相同**（0 集有差） | 同 |
| `candidate_prior` 事件 | **0 次** | 有（100 集全有差） |
| `endgame_tilt_view` | 70 集计数不同 | 同 |

→ **不是"逐字节相同"，是"轨迹相同、日志内容不同"**（A 那轮 candidate_prior 没记录）。
"数了两遍"的推论对不对另说，但"逐字节相同"这个措辞必须改掉，
否则以后有人会据此认为两份可以随便混用。

✅ **当日分析未被污染**：我用的只有位姿 / RAM 标签 / 航点几何，这三样两份完全一致。
已用同一段代码在两份上跑 L1，输出**完全相同**（j/N 0.7321…、倒退 0、n=100）。

## 6. 教训

> **一条裸子串判据在小数据上"看起来能用"，是因为假阳和真阳都被算进了同一个数。
> 只有把它跟一个更严的规则并排跑，差额才显形 —— 44.7%。**

写进纪律：**任何字符串匹配判据，落地时必须同时实现一个更严版本并报差额。**
