# 全链条梳理：感知—认知—决策—执行—反馈

**基准状态（ep100 / val_unseen / 9B）：SR 20% · OSR 25% · 转化 80% · SPL 0.155**

本文只写**已落到代码里的东西**和**已实测的数字**。推测一律标注为假说。
每节结构：怎么做的 → 实测状态 → 瓶颈。

---

## 零、一句话结论

> **瓶颈不在感知，不在停止判断，而在"选哪个候选"这一步 —— 但已经证明，
> 仅仅把这一步选得更准，并不能提升 SR。**

支撑：`SR = OSR × 转化`。转化率 80%（历史封顶 92.3%），**OSR 25% 才是天花板**。
97 集失败归因显示 **77 个失败里 70 个从未走到目标 3m 内** —— 不是"到了没停"，
是根本没到。所以链条的压力全在"决策—选择"这一环。

但 §三.3 的 Arm C 实验证明：把每步命中率从 36.7% 提到 43.8%（折外），
**SR 净 +1 集、p=1.000、SPL 完全持平**。因果链断在"选得更准 → 轨迹更靠近目标"。

## 一、感知（Perception）

### 1.1 怎么做的

每步在当前位姿上做全景采样，四个组件串联：

| 组件 | 模型/实现 | 产出 |
|---|---|---|
| 模拟器 | habitat-lab v0.1.7 + Matterport3D | RGB-D 全景帧 |
| 候选生成 | `BinaryDistPredictor_TRM`（`base_il_trainer_llm.py:226`）| 可达路点的 angle_rad / distance |
| 场景标签 | RAM（`recognize_anything`，swin_l）| 物体标签串 `Scene Objects: ...` |
| 场景描述 | **SpatialBot3B**（`api.py:126`，视觉编码器是 SigLIP）| 自然语言场景描述 + 物体距离 |

关键调用是 `spatialClient.observe_view`（`api.py:153`）—— **每个候选方向调用一次**，
RGB 和 depth 一起喂进 SpatialBot（depth 单通道被打包成三通道:
`//1024*4`、`//32*8`、`%32*8`）。

候选记录由 `build_candidate_records(radius_dict, distance_dict, images_dict)` 构造
（`base_il_trainer_llm.py:1877`），运行时类型是 `agent_state.py:22` 的
**`CandidateState` dataclass**（不是 dict —— 这个坑造成过一整轮实验失效）。

`GEOMETRY_INJECTION`（把 WaypointBert 实测距离注入观测文本）**当前关闭** ——
McNemar p=0.21，无显著收益。

### 1.2 实测状态

**几何感知是可靠的。**候选世界坐标可从 `step_start` 的 positions/headings 加
`waypoint_candidates` 的 angle_rad/distance **精确重建**：
`θ = −heading − angle_rad`，`x += d·sin(θ)`，`z −= d·cos(θ)`，
用"预测选中候选位置 vs 下一步实际位置"标定，**误差中位 0.000 m**。

**语义感知的距离读数是语言先验，不是测量。**`observe_view` 输出的物体距离：

| 检验 | 结果 |
|---|---|
| 整数占比 | 64% |
| 完美等差阶梯（5/7/8/10 这种）| 37% |
| 与真实距离相关 | r = 0.175 |
| MAE | 1.74 m |

SpatialBot 在"说距离"，不是在"测距离"。

**深度传感器本身可用但信息量低**：提交停止时刻的前向深度对成败
**AUROC = 0.531**（成功中位 2.10m / 失败 2.37m，分布重合）。

### 1.3 瓶颈

**感知不是瓶颈。**候选集本身够用 —— 72 个迷路集的离线复算显示
**84% 的步骤里存在一个正确候选**。几何量精确，候选覆盖充分。

真正的问题是**语义感知的产出没有被有效消费**（见 §二.3）。

## 二、认知（Cognition）

### 2.1 怎么做的

**集级（每集一次）：**
- `get_actions(instruction)` → 把指令拆成编号动作序列（Qwen3.5-9B 文本）
- `get_landmarks(actions)` → 抽取地标（同上）

**步级（每步一次）：**

| 模块 | 作用 | 模态 |
|---|---|---|
| `estimate_completion` | 判断"指令走到第几步了" | 纯文本 LLM |
| `phase_evidence` | 由完成度映射到 phase（search/approach/verify/recover）| 规则 |
| `grounder_diagnostic` | 每候选的 `grounding_score` + 五维分解 | 规则 |
| `visual_evidence` | 每候选的 `final_target_visible` / `matched_instruction_terms` | VLM |
| `visual_evidence_memory` | 跨步累积视觉证据 | 规则 |
| `context_builder` / `multimodal_selector_context` | 拼装送进选择器的上下文 | 规则 |
| `save_history` / `review_history` | 观测摘要 + 思考摘要，构成 nav_history | 文本 LLM |

### 2.2 实测状态 —— 这一层问题最严重

**`completion_estimation` 自证伪。**它是每步最贵的单项（15.7 s / 步），但：

| 检验 | 结果 |
|---|---|
| 第 1 步就报"100% 完成" | **69/94 集** |
| 全程饱和 | 414/687 步 |
| 与真实进度相关 | r = 0.120 |
| **物理上不可能的"进度倒退"** | **75 次** |
| 步内相关（控制集间差异后）| **r = +0.037**，第 6 步起转负 |
| 不同集输出完全相同的字符串 | 18/93 集 |

它驱动了 **47.7% 的 phase 判定**，且 **70/95 集在第 1 步就进入 `phase=verify`**。
换句话说：**认知层的主时钟是坏的,而下游都在读这个时钟。**

**`visual_evidence` 只有一个维度有用。**14 维消融：

```
仅几何 4 维        36.7%（恰等于 9B 本身）
仅语义 10 维       38.7%
几何 4 + nmatch    41.8%  ← 最优
全 14 维           41.5%
```

`grounding_score` 的 s_room / s_dir / s_rel / s_dst 四个子维权重**精确 0.000，完全 inert**。
**唯一有用的语义特征是 `nmatch`（匹配到的指令词计数）。**

**死代码**：`visual_graph_memory.py` 和 `landmark_matching.py` 在主循环里 **0 处引用**。

**Oracle 残留**：`phase_evidence.py:149` 的 `non_positive_count >= 2` 分支
占 8.3% 的 phase 判定，**仍未清理**。

### 2.3 瓶颈

**认知层在生产大量经不起检验的中间量,并且下游在认真消费它们。**
每步 ~54 s 里,约 43% 花在 `completion_estimation` + 选择器两次纯文本调用上,
而前者已被证伪。

**这是成本瓶颈,不一定是 SR 瓶颈** —— 关掉它能省 ~3 h/轮,但没有证据表明关掉能涨 SR。
（`COMPLETION_ESTIMATION.MODE: rule` 已实现,待跑。）

## 三、决策（Decision）

链条压力最大的一环。分两条独立子链：**选哪个候选** 和 **要不要停**。

### 3.1 子链 A：选择（`move_to_next_vp`）

**怎么做的**：把候选 ID 列表 + 指令 + 动作 + 地标 + 历史 + 完成度估计 + 观测文本
拼成 prompt,送 Qwen3.5-9B(`spatialNavigator.py:602`),解析 `Prediction:` 后的候选号。
**这是纯文本调用 —— 选择器全程不看图像**,它读的是 `observe_dict` 里 SpatialBot 生成的
文本描述。

**实测状态**（n=656 决策点,候选数中位 4）：

| 策略 | 命中最优候选 | regret 均值 |
|---|---|---|
| **9B 选择器（现状）** | **36.7%** | 0.99 m |
| 启发式：步长最长 | 35.7% | 1.19 m |
| 启发式：转向角最小 | 32.9% | 1.16 m |
| 随机 | 27.7% | 1.17 m |

**9B 比随机强 9.0 点,但比"永远选最长的一步"只强 1.0 点。**
语义 grounding 的增量贡献 ≈ 1 点。

且无系统性方向偏差(选中 |转向角| 中位 81.0° = 最优 81.0°),
**错误是分散的,不存在廉价的偏置修正。**

### 3.2 子链 B：停止

**这是全链条最复杂的部分 —— `stop_flag` 初始化于 `:1837`,之后有 8 个改写点**
(`base_il_trainer_llm.py` 的 2995 / 3332 / 3386 / 3402 / 3425 / 3501 / 3805 / 3876)。
其中 `:3332` 是 `stop_flag = old_stop_flag` 的回填,其余 7 处都是置 True。

参与的门：`should_stop`(navigator 侧) → `visual_target_verifier` →
`arrival_gate` → `proactive_stop_gate` → `stop_evidence_verifier` → `depth_stop_veto`。

**实测状态**：

- **深度否决是死路**：AUROC 0.531,阈值扫描 2.0–8.0 m **没有任何净正操作点**
  (T=3.0 拦掉 5 个成功换 16 个失败)。
- **有一条路径绕过深度否决**(`:3383` `if old_stop_flag and visual_target_verifier_allows_stop(...)`,
  无 depth 合取项),21/65 集在四门全否决时仍停止。
  **不要堵** —— 堵上会杀死 5 个成功 = 全部 20 个成功的 25%。这个"漏洞"是意外承重的。
- **回溯空转**：offered 156 次、applied **3** 次(接受率 1.9%),3 集都不在涨跌名单,
  **对 SR 贡献为 0**。选择层几乎从不采纳 MOVE_BACK。

### 3.3 已结算的负结果：Arm C（候选先验）

用 trace 里"已算好但从未被消费"的信号拟合 5 维线性先验,在选择器说话之后覆盖它。

**折外命中率 36.7% → 43.8%（GroupKFold-5 按集、逐折重拟合、5 种子）。**
decision-active 跑 82 集,干预率实测 55.5%(预估 59%,**未触发协变量偏移警报**)：

| 轮次 | SR | OSR | 转化 | SPL | nDTW |
|---|---|---|---|---|---|
| Arm C **生效** | 19.5% | 24.4% | 80.0% | 0.143 | 0.415 |
| Arm C **失效** | 18.3% | 23.2% | 78.9% | 0.143 | 0.422 |

**净 +1 集(10 涨 9 跌),McNemar p = 1.000,SPL 完全持平。**

```
每步选得更准  →  轨迹更靠近目标  →  更多集进 3m  →  SR↑
 ✅ 36.7→43.8%       ❌ 断在这里
```

**这是本项目当前最重要的一条结论:命中率不是 SR 的有效代理指标。**

两个待验假说(**非结论**)：①训练标签用欧氏距离、不考虑墙(欧氏 vs 测地 r=0.854);
②单步贪心 ≠ 路径最优。

### 3.4 互补性存在,但不可从现有记录预测

386 组"选择器 vs 先验"分歧中:LLM 独对 99 / 先验独对 155 / 都错 132。
**完美仲裁 60.4% vs 全听先验 45.3%（+15 点奖金）。**

但在恰好一方正确的 254 步上,**没有任何可观测信号能分辨该信谁**：

| 特征 | AUROC |
|---|---|
| 距离差 | 0.588 |
| 先验 softmax 自信度(取反) | 0.566 |
| **LLM 自身的推理文本**：犹豫词 / 地标密度 / 长度 | 0.548 / 0.538 / 0.478 |
| nmatch 差 / final_target_visible / ncand / phase | ≈ 0.50 |

4 特征逻辑回归仲裁器最佳阈值仅 +0.6 点、阈值一动即转负 = 噪声。
**LLM 的正确性不可从任何现有记录预测,包括它自己写出的推理过程。**
→ 捕获这份互补性需要打分头**直接读视觉/文本表示**,而非更多手工标量。

### 3.5 瓶颈

**决策是真瓶颈,但不是"选得不够准"这种瓶颈。**

- 候选集 84% 够用(§一.3),选择器只比平凡启发式强 1 点(§三.1);
- 但把选择准确率提上去,SR 不动(§三.3);
- 而互补性上界很高(+15 点),只是当前的标量特征够不着(§三.4)。

**指向:需要一个读表示、且目标函数与路径级结果对齐的打分头。**

## 四、执行（Execution）

### 4.1 怎么做的

`test_decisions` 校验 `next_vp` 合法(必须在 `observe_dict` 里,或是
`STOP_CANDIDATE` / 条件开放的 `MOVE_BACK_CANDIDATE`)→ Arm C 覆盖钩子 →
`action_pre_step` 收口(**这是唯一能识别终末位姿的地方**,stop 已定但 `envs.step()` 未执行)
→ `envs.step()` → `action_post_step`。

有 3 个 `env_actions.append()` 发射点。

### 4.2 实测状态 / 瓶颈

**执行层是干净的,不是瓶颈。**动作发射无歧义,非法候选会被拦下。

唯一值得记的:`action_pre_step` 这个收口点是俯视终局采样(`ALWAYS_ON_STOP`)
唯一能挂的地方 —— 覆盖提交停止时刻从 32% 提到 100% 就是靠它。

## 五、反馈（Feedback）

### 5.1 怎么做的

| 环节 | 实现 | 时间尺度 |
|---|---|---|
| 单步进度 | `post_action_progress`（`distance_gain_selected`、`recent_distance_gains`）| 步内 |
| 失败诊断 | `failure_diagnostic` → `failure_type`（如 `stop_false_positive`、`empty_fallback_bad`）| 步内 |
| 恢复策略 | `recovery_policy` / `apply_failure_recovery` | 步内 |
| 历史记忆 | `save_history` → nav_history（观测摘要 + 思考摘要）| 集内 |
| 视觉记忆 | `visual_evidence_memory` | 集内 |
| 决策审计 | `decision_audit` / `record_u_override` | 离线 |

### 5.2 实测状态

**⚠ 这里有一个链条级的断点：反馈只在集内闭环,不跨集,也不进入任何权重。**

- **没有训练回路。**9B 是冻结的,SpatialBot 是冻结的,waypoint predictor 是冻结的。
  跑完一集,除了 log,系统不保留任何东西。
- 唯一"学到"的东西是 Arm C 的 5 维权重 —— 而那是**我离线拟合、手工写进
  `candidate_prior_weights.json` 的**,不是系统自己学的。
- `distance_to_goal` / `distance_gain_selected` 这些反馈量**是 oracle**,
  离线分析合法,**推理期不可用**。这条红线在 20260704 的 oracle 审计后一直守着。

**审计侧是健全的**（这是本项目做得最好的部分）:`decision_audit` 记录每次覆盖的
`original_action` / `proposed_action` / `final_action` / `override_reason`,
可以逐集拆开归因。Arm C 那 333 次覆盖能一次不落地对上账。

**持久化侧刚补上一个洞**：`checkpoint_stats_episodes.json` 曾因
`os.replace` 前缺 `fsync` 在掉电时被清零(20260720 丢了 8.8 h 统计),已修。
真正救命的是 `logs/navigation_records/*.jsonl` —— **逐集追加 > 原子替换的汇总文件**。

### 5.3 瓶颈

**反馈层是整条链上最弱的一环 —— 它根本不闭环。**

系统跑 100 集和跑 1 集,能力完全一样。所有"学习"都发生在**我离线看 trace、
改代码**这个外循环里,人在回路里当梯度。

**这解释了为什么单点改动的收益一直很小**:每个模块都是手工调的启发式,
互相之间没有联合优化,任何一处的增益都会被别处吃掉
（Arm C 就是活例子：每步命中 +7 点,SPL 一点没动）。

## 六、瓶颈汇总与优先级

| 环节 | 是否瓶颈 | 依据 |
|---|---|---|
| 感知 | ❌ 否 | 几何误差 0.000 m；候选集 84% 步骤含正确候选 |
| 认知 | ⚠️ 成本瓶颈 | `completion_estimation` 自证伪(r=0.120、75 次倒退)却占 43% 耗时；语义 14 维只有 nmatch 有用 |
| 决策-选择 | ✅ **是** | 只比平凡启发式强 1 点；70/77 失败是"从没走到 3m 内" |
| 决策-停止 | ❌ 否(接近上限) | 停止侧 oracle 天花板仅 +7 集 → SR 26.8%；深度否决 AUROC 0.531 无解 |
| 执行 | ❌ 否 | 无歧义,无已知缺陷 |
| 反馈 | ✅ **是（结构性）** | 不闭环、无训练回路、跨集零记忆 |

### 6.1 已经排除的路（别再试）

1. **深度否决**（任何阈值都净负,AUROC 0.531）
2. **回溯**（接受率 1.9%,贡献 0）
3. **重排 prompt 候选顺序**（实测无位置偏置：首位选中率 27.1% vs 均匀期望 25.8%）
4. **prompt 注入几何**（`GEOMETRY_INJECTION`,p=0.21）
5. **手工特征仲裁器**（最好特征 AUROC 0.588,4 特征器 +0.6 点即噪声）
6. **waypoint 路线**（20260702 关闭：候选 84% 够用,瓶颈在选择层）
7. **纯提升每步命中率**（Arm C,净 +1,p=1.000）← **本轮新增**

### 6.2 当前优先级

1. **打分头的目标函数重新设计** —— 从"命中欧氏最近候选"改为与路径级结果对齐的目标。
   这是 §三.3 负结果的直接推论,也是唯一能同时打中"决策-选择"和"反馈不闭环"
   两个瓶颈的方向。输入**必须是表示,不是手工标量**（§三.4）。
2. 验 §三.3 的假说①（欧氏标签不考虑墙）—— **纯离线,不占 GPU**,能廉价地判定
   是"标签错了"还是"贪心错了"。
3. `COMPLETION_ESTIMATION.MODE: rule`（成本杠杆,省 ~3 h/轮,SR 预期中性）。
4. `phase_evidence.py:149` 的 oracle 残留清理（8.3% phase 判定）。

## 七、诚实限定

- 全部数字来自 **ep100 / val_unseen**,n≈100 集。单点改动的效应量普遍小于
  可检测下限。
- **至今没有 run-to-run 方差估计**。温度 0 下同配置重跑逐字节复现,
  所以"±N 点噪声带"这种说法在本项目里**没有依据**。
- §六 的"是/否瓶颈"判定基于当前证据,**不是永久结论** ——
  尤其"感知不是瓶颈"依赖"84% 候选覆盖"这一条,它只在候选集层面成立,
  不代表语义感知足够好。
- §五.3 的因果解释（"单点收益被别处吃掉"）**是假说,未经检验**。
