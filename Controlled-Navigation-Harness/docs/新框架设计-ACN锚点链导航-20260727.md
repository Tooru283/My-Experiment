# 新框架设计：ACN 锚点链导航（Anchor-Chain Navigation）

> 依据 [[架构对照-SOTA差距与改造路径-20260727]]。目标不是复刻 SpaceVLN，
> 是在本项目已有基座与已知死路的约束下，取那套架构里**被消融证明有效**的部分。
> 纪律：分阶段、每阶段独立可验证、闸门预注册、全程 oracle-free、LOG_ONLY 先行。

---

## 0. 一句话

**把"逐步无记忆航点选择"改成"锚点链 + 空间记忆 + 分层规划"，
并把进度定位从『问 LLM』改成『度量 + 状态机』。**

---

## 1. 设计原则

**P1. 语言归 LLM，定位归度量。**
LLM 只留在真正是语言的地方（指令 → 锚点链，每集 1 次，可全库离线预计算）。
"我走到哪了 / 我到了没有"是识别与定位问题，用可标定的度量 + 结构约束做，不问 LLM。

**P2. 结构约束优先于模型能力。**
能用状态机保证的性质（单调不倒退、顺序验证、弃权），不要指望模型自觉。
75 次进度倒退应当在**结构上归零**，而不是靠更好的 prompt。

**P3. 每阶段独立可验证，且闸门不看命中率。**
[[project_arm_c_20260719]] 已证命中率 +7 点不转化为 SR。所有闸门落在
**失败结构侧**（假停数 / OSR / 倒退次数 / 转化率），不设"选中最优候选率"类闸门。

**P4. 一切新读取量先过 oracle 审计。**
[[project_oracle_leak_20260704]] 的教训：单一 GT 变量渗进 5 个门、−8 SR。
每个组件必须声明"读什么"，GT 只允许出现在**离线标定**里。

**P5. LOG_ONLY 先行。**
新组件一律先只写 trace 不参与决策，用同一轮数据验证离线与在线一致，再翻决策位。

---

## 2. 架构

```
┌─ L0 锚点链构建            每集 1 次 · LLM · 可离线全库预计算
│    指令 → C = [a_0 … a_N]
│    a_i = (landmark_phrase, room_type, action_verb, is_terminal)
│    复用现有 ACTION_DETECTION + LANDMARK_DETECTION
│
├─ M1 空间记忆图            每步更新 · 无模型
│    node = (pose, floor, region, landmarks_seen, step_ids, visit_count)
│    edge = 已执行转移 ∪ 曾提供的候选（可达性）
│    升级现有 VisualGraphMemoryDiagnostic（109 行，现 LOG_ONLY）
│
├─ M2 地标池               stage 级 · 每步更新 · 无 LLM
│    entry = (category, fused_pos, dist, bearing, visible, arrived)
│    复用现有 landmark_matching.py + RAM 标签 + 深度
│
├─ L1 进度定位             每步 · 无 LLM   ★ 替换 completion_estimation
│    SigLIP 锚定 + 几何一致 + 单调状态机 + 弃权 → j = 最远已验证锚点
│
├─ L2 规划器               每 stage 1 次 · 大模型
│    输入 全景 + M1 + C + j  →  子任务 σ = (目标锚点 a_{j+1}, 地标查询, 阶段预算)
│
├─ L3 执行器               每步 1 次 · 小模型
│    输入 自我中心视图 + 障碍 + M2 + σ  →  动作
│
└─ L4 终止                 三重合取
     最终锚点已定位 ∧ 先前锚点全验证 ∧ 地标证据支撑
```

**与现架构的对应**：L1 换掉 `estimate_completion`（`spatialNavigator.py:132`）；
L2+L3 拆开现在单层的 `move_to_next_vp`；M1 把已有的 diagnostic 从日志侧接进决策；
L4 换掉现在"停止请求占终止 72/100"的松散终止。

## 3. 组件规格

### L0 锚点链构建（每集 1 次，LLM）

现有 `ACTION_DETECTION` 出动作序列、`LANDMARK_DETECTION` 出地标列表，
**但两者是分离的两个列表，没有对齐成有序的"到哪→找什么"**。L0 = 补上对齐。

输出 schema（严格 JSON，便于离线抽检）：
```json
{"anchors":[{"idx":0,"landmark":"the kitchen counter","room":"kitchen",
             "action":"walk past","terminal":false}, ...]}
```
- 每集 1 次调用，**可对整个 val_unseen 预计算并缓存**，热路径零成本
- 可人工抽检 N 集，锚点链质量是 L1 的输入前提，必须单独有质量数

### M1 空间记忆图（每步，无模型）

现有 `VisualGraphMemoryDiagnostic` 只有「位置历史 + 距离」，产出
`revisit_score` / `candidate_novelty` / `loop_flag`，被 `MEMORY_DIAGNOSTIC.LOG_ONLY=True` 锁住。

升级项：
- 节点加 `floor`（已有位姿 y 分量）、`region`（SigLIP 房间分类或 RAM 标签）
- 边加**可达性**：不仅记走过的，也记"曾被提供为候选但没选"的方向 → 支持"回到岔路口"
- 合并规则：距离 < r 且 region 一致则并为同一节点

⚠ **价值定位在"避免重访"，不是"主动回溯"。** 回溯已证采纳率 1.9%、贡献 0
（[[current_task]] §一ter K），不要重开那条路。

### M2 地标池（stage 级，无 LLM）

`landmark_matching.py`（135 行）已被 3 个模块引用，但**没有跨步累积**。
补：按 stage 维护一个池，每步用 RAM 标签 + 深度融合位置，记录 `visible` / `arrived`，
stage 切换时清空。这是 L4 终止判据的证据来源。

### L1 进度定位（每步，无 LLM）★ 详见 §5

### L2 规划器 / L3 执行器

拆分依据：SpaceVLN 消融显示 planner/executor 骨架本身值最多
（剥掉全部记忆与 CoT 仍有 37.3）。调用频率：L2 每 stage 1 次、L3 每步 1 次。

⚠ **L2 输出的方向先验会影响候选排序，这与已证伪的 `GEOMETRY_INJECTION`
和 Arm C 的"步内重排"形态相近。** 区别在于 L2 携带记忆与锚点上下文，
是动态子任务而非静态先验——**但不得据此预设它会成功**，闸门照常。

### L4 三重合取终止

`stop` 只在三条同时成立时接受：
1. 最终锚点已定位（L1 的 `j == N`）
2. 先前锚点全部验证过（状态机历史，非当前帧）
3. 最终锚点有地标证据支撑（M2 中对应条目 `arrived=True`）

⚠ **不得以深度为主判据。** 深度在停止时刻 AUROC=0.531 已证无信息量
（[[current_task]] §一ter I），且开口类目标（门口/楼梯口）天然深度 >3m。

## 5. L1 进度定位详细设计（替换 completion_estimation）

### 5.0 ⚠ 前提未验证 —— 本节全部内容以 S0 通过为条件

**2026-07-27 自审发现**：本节详细设计了 L1，却从未验证 `completion_estimation`
**是否承重**。这重复了本项目 8 条死路里"没验前提就开工"的模式。
**S0（见 §6）必须先跑**；若时钟不承重，本节全部作废，直接跳 M1/L4。

### 5.1 现件的真实病灶：不是"不准"，是"退化"

`COMPLETION_ESTIMATION` 的输入是 `history_traj` + landmarks + actions，**全是文本**，
而 `history_traj` 本身已被 `THOUGHT_SUMMARY` / `OBSERVATION_SUMMARY` 压缩过：

```
图像 → SpatialBot 描述 →  摘要  →  LLM 判断走到哪了
      ↑损失一次      ↑再损失一次   ↑在二手摘要上推理，从不碰几何量与当前观测
```

实测（[[全链条梳理-感知认知决策执行反馈-20260720]] §2.2，已核对原文）：

| 检验 | 结果 |
|---|---|
| 第 1 步就报"100% 完成" | **69/94 集** |
| 全程饱和 | 414/687 步 |
| 不同集输出**完全相同**字符串 | 18/93 集 |
| 与真实进度相关 | r = 0.120 |
| 步内相关（控制集间差异后） | r = +0.037，**第 6 步起转负** |
| 物理上不可能的"进度倒退" | 75 次 |
| **驱动 phase 判定** | **47.7%**，且 **70/95 集第 1 步即进 `phase=verify`** |
| 单步耗时 | ~15.7 s |

⚠ **诊断修正**：它**输出近乎常数**（第 1 步即饱和、18 集字符串完全相同）。
因此 **r=0.12 这个数是被近常数输出撑起来的**——一个恒输出中位数的估计器也能刷出可观的 r。
**故不得把 `r ≥ 0.50` 当主闸门**，须改用对退化敏感的度量（输出熵、饱和步占比、步内相关）。

★ **它同时给出 L1 → SR 的因果假设**（本设计最强的立论，原稿遗漏）：
> 坏时钟 → 70/95 集第 1 步即进 `phase=verify` → 过早扣扳机 → **假停 56 集（均 8.3m）**

**S0 就是检验这条链的实验。**

### 5.2 新设计：四级，热路径无 LLM

| 级 | 做什么 | 用什么 |
|---|---|---|
| A 视觉锚定 | `s_land[i] = max_{12视角} sim(view, landmark_i)`；`s_room[i]` 同理 | SigLIP（`/root/models/google-siglip-so400m-patch14-384` 已在本地） |
| B 几何一致 | 已走测地距离 / 朝向变化 / 楼层变化 / 与 M1 的重访关系 | 纯计算 |
| C 持久化确认 | 连续 ≥2 步超阈值，且领先次优锚点边距 δ | 结构 |
| D 单调状态机 | `j_t = max(j_{t-1}, 新验证)`；证据不足则**弃权保持** | 结构 |

### 5.3 精度优先的四个机制（对应"精度要最高"）

1. **双帧持久化** —— 复用已有 `persistent_visual_confirm` 纪律
2. **领先边距 δ** —— 防相似地标互混
3. **单调不倒退** —— 75 次倒退在**结构上归零**，不依赖模型准
4. **默认弃权** —— 宁可报"进度未知"，不猜

阈值与 δ 在留出集上标定到**指定 precision**（如 ≥0.90），recall 随之而定。
"精度最高"因此是一个可拧的旋钮，不是形容词。

### 5.4 ⚠ 必须正视的前车之鉴

Arm C 拟合中 `grounding_score` 的 `s_room`/`s_dir`/`s_rel`/`s_dst` 权重
**精确为 0.000 = 完全 inert**，唯一有用的语义特征是 `nmatch`。

两点让我认为 L1 不同，但**都需闸门检验、不得预设**：
1. 那次测的是**选路**（哪个方向通往终点），L1 是**识别**（我是不是在厨房），后者简单得多
2. `nmatch`（视野中匹配到的指令词数）恰是唯一有用的那个，而校准过的 SigLIP 锚定
   就是 `nmatch` 的正确做法

**退路**：若 A 级闸门不过，退纯 B+D（几何 + 单调状态机），那已强于 r=0.12。

### 5.5 离线验证的数据基础（依据已更正）

- 100 集 trace 有每步精确位姿；M1 的离线渲染管线已证按位姿重建误差 0.000m
- GT 进度 = 位姿在参考路径上的测地投影比例，离线可算（**GT 仅用于标定与评估**）
- ⚠ **更正**：`completion_estimation` **不在** `logs/harness_traces/**.jsonl` 里
  （该 trace 无此 `event_type`），而在 **`logs/navigation_records/`**。
  已核实 `ep100/20260720` 那轮有 **600 条**、payload 为原始 `estimation` 字符串。
- ✅ **20260730 已确认**：clean_baseline_v1（20260705）**同样记录**——
  `logs/navigation_records/ep100/20260705/clean_baseline_v1_...jsonl`，
  `event="completion_estimation"` **650 条 / 100 集全覆盖**（另 32 条为非集内调用）。
  → **S1 的离线验证可以直接在合法基线上做，无需重跑。**

### 5.5b 退化度量的基线值（20260730 实测，S1 闸门直接用这组数）

设计要求"改用对退化敏感的度量"，但没给基线。现补齐（clean_baseline_v1，650 次调用 / 100 集）：

| 退化度量 | 实测 |
|---|---|
| **全程输出完全不变的集** | **29 / 100** |
| 每集不同输出数 | **中位 2.0**、均值 2.5（而每集中位 6 步） |
| 650 次调用产生的不同串 | 228 |
| 最高频串 | **`'None'`，27 次**（即约 4% 的调用直接失败返回 None） |

→ **一个"进度时钟"在中位 6 步的集里只取 2 个不同值，其中 29 集一个值都不换。**
**S1 预注册闸门（在此基线上）**：全程不变集 ≤5 / 100；每集不同输出数中位 ≥4；`None` 率 ≤1%。
- 成本：656 步 × 12 视角 ≈ 7900 张图，渲染约 20 分钟 + SigLIP 前向几分钟

### 5.6 公开风险（自审 20260727，不得当作已解决）

**R1 标签循环。** 拟合发射概率 `P(特征 | 处于锚点 i)` 需要每步**锚点索引**真值；
而 GT 只给得出参考路径上的**标量**进度比例。标量→索引需知道每个锚点落在路径哪一段，
**那正是待解的对齐问题本身**。出路：人工标注 20–30 集，或退为只预测标量进度。

**R2 模型复杂度对不上数据量。** 100 集 / 656 步要拟合转移+发射，状态数随锚点数变，
过拟合风险实在。**在此数据预算下更简单的设计可能更准**——HMM 并非"显然更强"。

**R3 SigLIP 的先验证据是负面的。** `grounding_score` 四维权重精确 0.000。
"可能因未做对比归一化"是**未经检验的假说，不是查明的死因**，不得据此假定 L1 可行。

**R4 精度闸门在精神上仍属"每步中间量"。** §4 表中"纯提升每步命中率"那一行的对照
过于宽松：L1 的 precision 闸门与之同类。**故 S1 的精度闸门只作必要条件，
明写"过 S1 不预测 SR"**，SR 侧的检验放在 S0 与 S3。

## 6. 分阶段实施与预注册闸门

⚠ **20260727 自审后调序**：新增 S0；S3 提前到 S2 之前
（L4 是 L1 唯一能落到失败结构侧的出口）。

| 阶段 | 内容 | 闸门（预注册） | 成本 |
|---|---|---|---|
| **S0** ★ | `COMPLETION_ESTIMATION.MODE: llm → rule`，检验时钟是否承重 | **失败结构侧**：假停数 / SR / OSR 的变化方向与量级 | **一个 yaml 字段 + 1 轮 ep100，且更快**（省 15.7s/步） |
| **S1** | L0 锚点链 + L1 进度定位，纯离线 | 对退化敏感的度量（输出熵 / 饱和步占比 / 步内相关）· 倒退 ≤ 5（现 75）· 前进 precision ≥ 0.90 · ≤ 1s/步。**⚠ 必要条件，不预测 SR**（见 R4） | 无导航运行 |
| **S3** | L4 三重合取终止 | 假停 56 → ≤ 30，**且 OSR 不降**（防误杀真停） | 1 轮 ep100 |
| **S2** | M1 空间记忆图接入决策 | OSR 上升 且 重访率下降；OSR 不降是硬约束 | 1 轮 ep100 |
| **S4** | L2/L3 分层 + 原语执行器 | SR 相对 clean_baseline_v1 提升，且 SPL 不劣化 | 重写，几周 |
| **S5** | `qwen3.5-plus`(规划) + `qwen3.5-flash`(执行) | SR 与成本联合 | 小 |

**S0 的两种结局都决定性**：
- 假停/SR 明显变化 → 时钟承重，L1 值得建，且已拿到对照基线
- 毫无变化 → **时钟不承重，L1 全部投资作废**，直接跳 M1/L4

**S1 不过 → 不进 S3/S2。** L1 是 L2/L4 的输入。

## 7. 调用预算（可行性）

现状：每步 5~6 次 VLM 调用，其中 completion 单项 ~15.7s，6.56 步/集。
新框架：L1 无 LLM；L2 每 stage 1 次；L3 每步 1 次小模型。
→ **即使步数从 6.56 涨到 100+，每步调用数下降足以抵消**，总成本预计持平或更低。
（⚠ 此为估算，S4 前须实测。）

## 9. 开放决策（需拍板）

1. **动作空间**：S4 是否真换原语？`POSSIBLE_ACTIONS` 已含
   `[STOP, MOVE_FORWARD, TURN_LEFT, TURN_RIGHT, HIGHTOLOW]`，habitat 侧无需改动。
   ⚠⚠ **这是一条承重假设，不是背景**：3–5 锚点 × 每锚点 2–4 跳 = **6–20 跳**，
   而预算 `SHORT=10 / LONG=12`（`default.py:235-236` / `run_OpenNav.yaml:150-151`）。
   **对相当一部分集，锚点链在航点基座上根本走不完。**

   ✅ **20260730 预算诊断已跑（纯离线，clean_baseline_v1）——承重假设证实，且比预想更硬：**

   | 每集步数 | 集数 |
   |---|---|
   | 3 步 | **21** ← 早停堆 |
   | 4–9 步 | 48 |
   | **10 步（SHORT 上限）** | **24** ← 撞墙堆 |
   | 11 步 | 0 |
   | **12 步（LONG 上限）** | **6** ← 撞墙堆 |

   **分布是双峰的，不是自然分布**：21 集在 3 步就放弃，**30 集精确顶在预算墙上**，
   中间只有 48 集自然终止。中位 6 步**不代表"任务只要 6 步"，只代表 agent 在 6 步就不走了**。

   ★ **由此得到一条设计层面的新推论（原稿没有）**：
   **S3 成功会把预算问题放大。** S3（三重合取终止）的作用是减少假停 →
   那 21 个早停集会跑得更长 → **它们也会撞上同一堵墙**。
   → **加大 `SHORT/LONG_ACTION_STEP_LIMIT` 不是可选优化，是 S3 的前置条件。**
   否则 S3 只会把"假停失败"换成"耗尽失败"，SR 不动而我们会误判 S3 无效。
   → **建议并入 §一decem 阶段 0 一起跑**（禁停 + 加大预算，同一轮，两个 yaml 字段）。
