# Open-Nav / Controlled Navigation Harness 当前实验进展

汇报时间：2026-08-26  
统计范围：2026-07-30 至 2026-08-25  
报告目的：汇报最新已验证结论、当前代码落地状态，以及下一轮在线实验计划。

> **口径声明**：本报告只把已有 trace、离线重放和代码检查得到的结果写成“已验证”。设计文档中的计划、`LOG_ONLY` 模块和未运行的 C0/C2 不作为实验收益报告。

## 一、先说结论

1. **当前最可靠的基线是 2026-07-19 trace 的官方指标：SR 20 / OSR 25 / SPL 0.155 / 转化率 80.0%。** 目录名 `clean_baseline_v1` 与挂牌数字不一致，后续必须以 `episode_end.metrics` 为准。
2. **主要瓶颈已经从“停得准不准”转向“能不能走到”。** OSR 与 SR 相差 5 个百分点，转化率 80% 已不是主要短板；真正的问题是候选航点和无状态单步选路导致的走远、耗尽和随机游走。
3. **换更大的 Qwen 没有突破选路上界。** Qwen3.5-9B、qwen3-vl-plus、qwen3.5-omni-plus 在同一批决策点上均为 39%–43%，没有随模型规模上升的趋势。
4. **ACN 代码已经落地，但仍处于离线验证阶段。** L0/L1/M1/M2/L4 均为 `LOG_ONLY`；L1 的预注册闸门尚未通过，因此不能宣称 ACN 已经提升 SR。
5. **下一步应先做 C0/C2 的小规模在线验证。** 当前配置仍是 C0=3、步数预算 10/12，计划中的 C0=4、C2=15/17 尚未形成新的 ep5/ep100 结果。

## 二、项目问题重新定位

最初的问题是：agent 经常已经到过目标附近，但最后没有成功停下。后续审计把问题拆成两层：

```text
候选航点是否能把 agent 带到目标附近？  -> OSR
到过目标附近后，是否能稳定终止？      -> OSR -> SR 转化
```

当前官方基线：

| 指标 | 数值 | 解释 |
|---|---:|---|
| SR | 20/100 | 最终停在成功半径内 |
| OSR | 25/100 | 轨迹中至少一次到过成功半径内 |
| OSR→SR | 80.0% | 到过之后最终成功的比例 |
| OSR-SR gap | 5 集 | 已到过但最终没有成功 |

因此，继续只优化 STOP gate 的收益有限。即使 C0 全部命中，OSR 的上限仍受“候选是否提供了可达航点”约束。

## 三、上次组会之后新增的关键证据

### 3.1 多模型上界：换更大模型没有解决无状态选路

在相同决策点、相同 prompt 骨架和相同候选图像上，只替换模型：

| 模型 | 候选图像 | 文字描述 | 几何信息 | 错配图对照 |
|---|---:|---:|---:|---:|
| Qwen3.5-9B | 41% | 30% | 26% | 18% |
| qwen3-vl-plus | 43% | 28% | 25% | 20% |
| qwen3.5-omni-plus | 39% | 29% | 27% | 19% |

随机基线为 25.7%，简单的“永远选最长步”在该子集为 43%。错配图在三个模型上都低于随机，说明模型确实在读取图像；但更大模型没有把选路能力推过 50% 闸门。

**结论**：同一航点候选骨架下，单纯换更大模型已经经验性关闭。问题更可能来自状态表示、候选生成和规划结构，而不是模型参数量。

### 3.2 OSR 口径和基线已经完成审计

此前用欧氏距离得到“31/100 到过目标”，与官方 OSR 不一致。审计后确认：

- 官方 `episode_end.metrics.oracle_success` = 25/100；
- trace 内测地距离 `min(distance_to_goal) <= 3m` = 25/100，逐集一致；
- 欧氏距离的 31/100 高估了 6 集，原因是穿墙直线距离低估。

同时发现 `clean_baseline_v1` 目录实际包含 SR20/OSR25 的 2026-07-19 轮次，而不是文档挂牌的 SR16/OSR21。之后所有数字以 trace 指标为真源，不再以目录名或旧表格为准。

### 3.3 ACN 离线代码落地，但 L1 还未过闸门

当前已经接入以下模块：

| 模块 | 作用 | 当前状态 |
|---|---|---|
| L0 Anchor Chain | 将动作和地标对齐成有序锚点链 | 已实现，覆盖率中位约 78%，无建链失败集 |
| L1 Progress Locator | 用单调约束队列替代不稳定的进度自报 | 已实现，离线重放；闸门未通过 |
| M1 Spatial Memory | 记录楼层、已走链边和未探索分支 | 已实现，当前只记录 |
| M2 Landmark Pool | 跨步积累与锚点相关的地标证据 | 已实现，已限制到锚点词表 |
| L4 Terminal Gate | 锚点完成、历史验证、最终地标到达三重合取 | 已实现，当前只记录 |

最新离线重放结果：

- L1 进度倒退次数：0；
- 每集不同进度值中位数：2，预注册要求为至少 4，**未通过**；
- 末步 L4：allow 26 集、block 74 集；
- L1/M2/L4 目前仍为 `LOG_ONLY`，没有改变导航轨迹。

这个结果说明 ACN 的结构性优点已经成立一部分：它可以保证进度不倒退，并且不增加 LLM 调用；但当前判定器还不足以替换线上进度估计。

### 3.4 运行时瓶颈已经量化

一轮 100 集约 8.68 小时、721 步、2531 次 LLM 调用：

| 阶段 | 时间占比 | 处理结论 |
|---|---:|---|
| `completion_estimation` | 36.3% | L1/C1' 若通过，可删除这条调用 |
| `navigator_move_to_next_vp` | 33.9% | 当前核心决策调用，暂不能直接删除 |
| `visual_evidence` | 24.0% | 每步都参与停止校验，不能简单砍掉 |
| `stop_current_view_evidence` | 5.9% | 条件触发 |

因此，最现实的加速路径不是 AirLLM 或换推理框架，而是验证 L1/C1' 后删除每步一次的 completion estimation。

## 四、已经关闭或不应重开的路线

以下路线已有定量死因，不作为下一轮主攻：

- 深度作为 STOP 裁判：AUROC 约 0.531，未发现净正阈值；
- 位移回溯：提供 156 次，仅采纳 3 次，SR 贡献为 0；
- training-free 候选先验：命中率改善不能转化为 SR；
- 候选打分头/隐藏态读取：接近随机，未达到米制 regret 闸门；
- M1 直接多模态选路：最佳约 41%–43%，未通过 50% 闸门；
- 单纯换更大 backbone：39%–43% 平台；
- P1 同分布重复采样触发：早期校准 AUROC 约 0.542，接近随机，不能作为当前主线。

这些负结果的价值在于：它们把问题从“再换一个模型/再加一个 prompt”推进到了“候选生成、空间状态和规划结构”的层面。

## 六、下一轮实验计划

### R0：先固定配置和实验身份

在新实验前记录：模型、prompt、`run_OpenNav.yaml`、commit、trace 目录和所有 decision-effect 开关。当前工作区有未提交修改，不能再依赖目录名作为配置身份。

### R1：C0 单独验证

配置：

```yaml
VISUAL_TARGET_VERIFIER:
  MIN_STEPS_BEFORE_ALLOW: 4
```

先跑 ep5，确认启动日志中出现：

```text
[HARNESS SWITCHES 2] C0.min_steps_before_allow=4
```

结构性验收不只看 SR：

- 是否真的出现 `before_min_steps`；
- 每集最少步数是否从 4 推到 5；
- 早停失败是否转移为耗尽失败；
- 失败集的最终测地距离是否下降。

### R2：C0 + C2 配对验证

在 R1 确认生效后，再叠加：

```yaml
NAVIGATION_RUNTIME:
  SHORT_ACTION_STEP_LIMIT: 15
  LONG_ACTION_STEP_LIMIT: 17
```

重点观察：

- 目标靠近组是否转化为更多 OSR；
- 远离组是否因增加预算而恶化；
- SR、OSR、SPL 是否同步改善；
- 失败是否从假停转为耗尽。

### R3：再决定 ACN/C1'

只有当 C0/C2 的失败转移关系明确后，才决定是否：

1. 让 L1 替换 completion estimation；
2. 打开 C5 拓扑告警；
3. 为 location 判定器做 MP3D region precision 标定；
4. 继续实现 C1'，同时测 OSR 和运行时间。

## 七、需要组会上明确的决策

希望组会讨论并确认三点：

1. **性能优先级**：是否先完成 C0/C2 的单开关在线验证，再继续 ACN？
2. **论文定位**：是否接受“诚实基线 + OSR 瓶颈诊断 + 负结果/止损方法”作为一条可发表主线，而不再追求用更大模型硬抬选路？
3. **工程边界**：若 C0/C2 不能把 OSR 推过约 35，是否转向 waypoint-free / 空间记忆 / 分层规划路线，而不是继续堆叠当前 selector 的局部规则？

## 八、可直接口头汇报的版本

> 这次汇报我主要更新三件事。第一，我们重新核对了基线和 OSR 口径。当前 2026-07-19 trace 的官方结果是 SR20、OSR25、SPL0.155、转化率80%，之前目录名和挂牌数字不一致，后续以 trace 指标为准。这个结果说明现在的主要问题不是已经到过目标后停不准，而是很多 episode 根本没有稳定走到目标附近。
>
> 第二，我们完成了多模型选路上界实验。Qwen3.5-9B、qwen3-vl-plus 和 qwen3.5-omni-plus 在相同决策点上的图像选路分别是41%、43%和39%，没有随模型规模提升。错配图会把结果降到18%到20%，说明模型确实在看图，但更大的模型没有解决这个候选航点选择问题。因此“继续换更大模型”这条路线先关闭。
>
> 第三，ACN 的 L0、L1、空间记忆、地标池和终止门代码已经落地，并在已有100集 trace 上完成离线重放。L1 可以保证进度不倒退，但不同进度状态的中位数只有2，没有通过预注册的4格闸门；所以现在仍然全部 LOG_ONLY，不能把它说成在线收益。
>
> 下一步我建议先做 C0/C2。第一轮把最小允许停止步数从3改成4，先跑 ep5 验证开关和失败结构是否真的改变；第二轮再把步数预算从10/12提高到15/17，观察增加预算能不能把假停转化为真正的 OSR。只有这两轮的失败转移关系清楚后，再决定是否让 ACN 进入决策路径。
