## 1. 落地清单

| 层 | 新文件 | 行为 | 新增模型 / LLM 调用 |
|---|---|---|---|

## 2. 🔴 首轮离线重放：L1 没过自己的闸门

`paper_analysis/acn/replay_acn_offline.py`（**导入线上真实模块**，不复制逻辑），100 集 trace：

### 2.1 L0 锚点链 ✅

对齐覆盖率中位 **78%**，**建不出链的集 0**。约束类型占比：

| object | location | direction | unknown |
|---:|---:|---:|---:|
| 38.5% | **34.6%** | 17.7% | 9.2% |

（与 L1 规格 §2 的离线统计基本吻合：36.1 / 37.6 / 17.9 / 8.3）

### 2.2 L1 约束队列 —— 结构保证成立，但队列推不动

| 指标 | 本方案 | 现状 | 闸门 | 判定 |
|---|---:|---:|---:|:--:|
| 进度倒退次数 | **0** | 75 | ≤5 | ✅ |
| 每集不同进度取值数 中位 | **1** | 2 | ≥4 | 🔴 |
| **最终进度 j/N 中位** | **0.00** | — | — | 🔴 |
| 每集弃权步占比 中位 | **100%** | — | — | 🔴 |

**中位集的队列一格都没推进。**

卡在哪一类约束上（= 该通道的价值下界，这正是本轮要测的量）：

| 卡住的约束类型 | 步数 | 占比 |
|---|---:|---:|
| **location** | **361** | **51.9%** |
| object | 150 | 21.6% |
| direction | 95 | 13.7% |
| unknown | 89 | 12.8% |

→ **一半以上的卡点是 location，而 location 判定器根本没实现（走弃权）。**
L1 规格 §3.2 早就写了「弃权率即 location 通道的价值下界」——**这轮把那个下界量出来了：51.9%。**

**结论：L1 现在不能翻决策位。** 翻了就是拿一个恒定的「尚无子动作被验证」
去换掉一个虽然噪声大但至少在变的估计，是净负。

### 2.3 M2 地标池 ⚠ 太松

每集池大小中位 **92**；**100/100 集**都至少有一条 `arrived=True`。

→ RAM 每个方向吐十几个标签，池子瞬间被泛类词填满，
**「最终地标有到达证据」这一条几乎恒真，作为 L4 的合取项没有区分力。**
需要收紧（只收锚点链里出现过的类别，而不是全部 RAM 标签）。

### 2.4 L4 三重合取 —— 被 L1 拖累

末步评估：**block 90 集 / allow 10 集**。

90% 的阻塞几乎全部来自第一条合取（`j==N` 不成立），而那是 L1 推不动的直接后果。
**L4 是 L1 的下游，L1 不通它就没有独立意义。**

## 2bis. ★ 第二轮：location 判定器补上之后（同日）

### 2bis.1 关键发现：**RAM 早就在报房间类，不需要新模型**

在 100 集 trace 上直接量：**93.8%** 的 location 约束，所需房间词在 RAM 标签里出现过。
**召回不是问题。问题全在选择性：**

| 判定规则 | 满足步占比 中位 | 首次满足位置 中位 | 从不满足 |
|---|---:|---:|---:|
| 任一方向出现该词 | **88%** | **步 0** | 6% |
| ≥50% 方向 | 60% | 步 0 | 17% |
| **≥50% 方向 + 泛类词停用** ← 采用 | **33%** | **9%** | 23% |
| ≥75% 方向 + 泛类词停用 | 25% | 18% | 41% |

**朴素的"任一方向出现"规则在中位约束上第 0 步就满足** —— 那正是 L1 要修的病
（旧模块 69/94 集第 1 步报 100%）。

**改用「主导性」判据**，物理含义清楚：**你在厨房里，多数方向看着都像厨房；
你隔着门往厨房里看，只有一个方向像。**

泛类词停用表 = `{room, hall}`：RAM 在 **73.2%** 的方向视图里报 `room`。
这类约束不含信息 → **判为"空满足"而非弃权**（弃权会让队列永久卡在一个本就没内容的格上）。
162 条 location 约束里 43 条是泛类。

同理修了 `unknown` 锚点：**占锚点 9.2%，却造成 20.3% 的卡步**（因为卡是永久的，
而一个锚点只占 1/N）→ 也判空满足。

### 2bis.2 ★ 结果：与真实进度的相关性翻倍

| 版本 | 与真实进度 r | j/N 中位 | 一步跳>1格 |
|---|---:|---:|---:|
| **现状 `completion_estimation`** | **+0.120** | — | — |
| 首版（location OFF，unknown 阻塞） | +0.181 | 0.00 | 3.2% |
| location ON，unknown 阻塞 | +0.217 | 0.50 | 7.8% |
| **location ON + unknown 空满足（现版）** | **+0.246** | **0.73** | 9.8% |

（真实进度 = `(d0 − d_t)/d0`，GT 仅用于**离线评估**，不上推理路径）

### 2bis.3 闸门逐条判定（不移动球门）

| 闸门 | 值 | 判定 |
|---|---:|:--:|
| 进度倒退次数 ≤5 | **0** | ✅ |
| 每集不同进度取值数 ≥4 | **2** | 🔴 **未过** |
| 提前推进率 ≤15%（用「一步跳>1格」作代理） | 9.8% | ✅（代理，非同一量） |
| 单步耗时 ≤1s | 无 LLM 调用 | ✅ |
| — 相关性 r（规格里是"对照"，不是闸门） | 0.120 → **0.246** | — |

🔴 **「不同取值数 ≥4」这一条没过，如实记录。**
观察到的原因：我们每集中位 **~7 步 / ~5 个锚点**，而持久满足修复会让队列在头格解锁时
**一次推进多格**（9.8% 的步跳 >1 格），于是取值数被压缩。
⚠ **这不构成重设闸门的理由** —— 闸门是看到结果之前定的。
如需改判据，应当作为一次显式的重新预注册，并写明改动理由与时间。

### 2bis.4 连带变化

- L4 末步：**block 62 / allow 38**（首版 90/10）—— 随 L1 推进而松动，仍是 L1 的下游
- 卡点重排：object **45.1%** / location 31.0% / direction 23.9%
  → **object 判定器（RAM 标签 + 航点距离）成了新的第一瓶颈**，
  与此前"object 约束覆盖 72%、瓶颈在 RAM 标签匹配而非距离阈值"的测量一致

## 2ter. ★ 第三轮：收紧 M2 之后，L4 第一次显出信号

### 2ter.1 M2 只收锚点链问到的类别

原来收全部 RAM 标签 → 每集池中位 **92** 条，**100/100 集**有 `arrived` → L4 第三条合取项恒真。
改成只收锚点链里的 landmark / room（含中心词，因为 RAM 报 `screen door` 而指令说 `the door`）：

| | 池大小 中位 | 有 arrived 的集 |
|---|---:|---:|
| 不限词表 | 92 | 100/100 |
| **限词表** | **10** | 99/100 |

### 2ter.2 三条合取项各自的真值率（越接近 100% 越没区分力）

| 合取项 | 为真 |
|---|---:|
| `chain_complete`（L1 的 j==N） | 39/100 |
| `all_previous_verified` | 52/100 |
| **`final_landmark_arrived`** | **65/100** ← 收紧前约等于 100/100，**现在有区分力了** |

### 2ter.3 ★ L4 判决 vs 实际成功（末步评估，100 集）

| | 集数 |
|---|---:|
| allow **且成功** | 15 |
| allow **但失败** | 22 |
| block **但成功** | **11** |
| block **且失败** | 52 |

- **allow 的精度 40.5%，基线成功率 26.0% → 高出 14.5 点**
- **block 的正确率 82.5%**
- 🔴 **kill 面 = 11 集**（会被拦掉的成功集）

**这是今天第一条正向的机制信号。** L4 不是随机拦截：它拦的 63 集里 52 集本来就要失败。

⚠ **但不能读成"净赚 41 集"**：拦停 ≠ 救回。被拦的集会继续走，可能后面成功，也可能变成耗尽。
真实收益要在线上量，且**这正是 C0/C2 那一对要处理的转化关系**（禁早停会把假停变耗尽，除非同时加预算）。

## 3. 由此确定的关键路径

> ✅ **本节已由 §2bis 执行，且结论被推翻了一半**：**不需要新分类器** ——
> RAM 已有 93.8% 的房间词召回，缺的是选择性，用主导性判据即可。下面保留原判断作为记录。
>
> ⚠ **但 MP3D region 标定仍然必须做**：§2bis 只量了**选择性**（满足步占比、首次满足位置），
> **没有任何一个数说明它判对了没有**。precision 至今为零证据。
> 本沙箱 `data/scene_datasets/` 只有下载脚本、无场景数据，标定须在有 MP3D 的机器上跑。

**location 判定器是整条 ACN 的瓶颈，不是"锦上添花的第三类"。**

L1 规格 §3.2 给了两条路，现在应当直接做后者：

- (a) VQA：`SpatialBot` 问 "Can you see the \<location\>?" —— 有现成通路，但热路径多一次调用
- (b) ⭐ **闭集房间分类**：对 ~15 个房间类打分，**MP3D 自带 region 标注 = 免费 GT**，
  可离线标定到指定 precision。**这是唯一能立刻拿到可信精度数的一档。**

⚠ **前置未清**：旧 `grounding_score` 的 `s_room` 权重曾拟合为精确 0.000。
但 20260805 已查明 `grounder_diagnostic.py:63-69` 把 `room/direction/relation/distance`
**硬编码为 0.0** —— 那个 0.000 权重是在拟合一个恒零特征，**不能据此认定 SigLIP 不行**。
这条路没有被证伪过，只是从没被真正测过。
