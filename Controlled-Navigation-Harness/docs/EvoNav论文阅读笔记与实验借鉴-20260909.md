# EvoNav 论文阅读笔记与当前实验借鉴

## 一、论文信息

- **题目：** *History to Future: Evolving Agent with Experience and Thought for Zero-shot Vision-and-Language Navigation*
- **方法名：** EvoNav
- **会议：** CVPR 2026
- **论文：** [CVF Open Access PDF](https://openaccess.thecvf.com/content/CVPR2026/papers/Dai_History_to_Future_Evolving_Agent_with_Experience_and_Thought_for_CVPR_2026_paper.pdf)
- **项目页：** [EvoNav_CVPR2026](https://github.com/daiguangzhao/EvoNav_CVPR2026)
- **代码状态：** 项目页目前仍写着 source code will be released，因此本文只能依据论文描述分析，尚不能核对实现细节。

## 二、一句话结论

EvoNav 把零样本 VLN-CE 从“当前观察直接选动作”改成一个历史—未来反馈循环：

```text
历史任务与历史场景 → 检索相关经验
当前指令、观察与轨迹 → 预测下一动作和下一地标
检索经验 + 未来提示 + 当前观察 → 选择当前 viewpoint
```

它最有价值的部分是**用下一地标构造场景查询，以及把轨迹经验和场景经验分开管理**。它所谓的“预测未来”不是生成未来 RGB、未来状态或物理轨迹，而是让大模型生成文本形式的下一动作与下一地标。它所谓的“evolving”也不是更新模型参数，而是持续向经验库追加记录，并在后续推理中检索。

## 三、研究问题与动机

传统 LLM/VLM 零样本导航器通常把完整指令、当前观察和少量历史放进模型，逐步选择方向。论文认为这种单向推理有两个问题：

1. 初始方向一旦选错，后续步骤缺少对历史错误的复盘，错误会连续传播；
2. 当前决策只解释眼前画面，没有显式判断“下一步应该做什么、接下来应当看到什么”。

EvoNav 因此提出两个互补模块：

- **F-CoT（Future Chain-of-Thought）：** 预测下一动作、估计已完成进度、预测下一地标；
- **H-CoE（History Chain-of-Experience）：** 检索历史轨迹经验和历史场景经验。

最终动作决策同时消费当前观察、当前轨迹、未来提示和检索结果。

## 四、F-CoT：未来怎样预测

### 4.1 指令拆解

首先用 LLM 把完整指令 \(I\) 拆成：

- 有顺序的子动作：例如 leave、go through、turn left；
- 空间地标：例如 bathroom、kitchen、bar、closet。

这一步与当前项目的“两阶段动作解析 + 地标/terminal target 解析 + Anchor Chain”目标相近。

### 4.2 预测下一动作

论文根据当前 episode 历史 \(H\)、当前观察 \(O\) 和完整指令 \(I\) 生成未来动作：

\[
P^f=\operatorname{LLM}(H,O,I)
\]

典型输出不是控制量，而是一句话，例如：

```text
Walk straight through the kitchen.
```

### 4.3 估计当前进度

论文再结合子动作、地标、预测的下一动作和历史轨迹，让 LLM 判断哪些动作已经完成：

\[
A^d=\operatorname{LLM}(\text{sub-actions},\text{landmarks},P^f,H)
\]

直觉是：如果模型判断“下一步应穿过厨房”，就反推出此前“离开浴室”等动作已经完成。

### 4.4 预测下一地标

根据完整指令和已完成动作，从原始地标列表中匹配下一动作涉及的地标：

\[
L^f=\operatorname{LLM}(I,\text{sub-actions},\text{landmarks},A^d)
\]

论文使用两条规则：

1. 下一动作明确提到地标时，输出地标列表中对应的规范名称；
2. 下一动作只有 left、right、forward 等方向信息时，输出 `None`。

这里的 \(L^f\) 有双重作用：既给最终 selector 一个方向语义提示，又作为历史场景检索的 query。

### 4.5 对 F-CoT 的准确理解

F-CoT 更接近“语义计划补全”，不是严格的未来状态预测：

- 没有学习环境动力学；
- 没有对候选动作做多步反事实 rollout；
- 没有生成未来视觉观察；
- 没有估计未来结果的概率分布；
- 下一动作和下一地标都可能受 LLM 幻觉影响。

因此，F-CoT 的优点是成本和接入门槛低，缺点是“预测”和“进度判断”没有物理证据约束。

## 五、H-CoE：过去怎样保存与查询

H-CoE 包含任务级轨迹经验和步骤级场景经验，两者的写入时机、query 和用途不同。

### 5.1 当前 episode 的短期历史

每走一步，系统把以下内容追加到当前轨迹历史 \(H\)：

- 模型的推理过程；
- viewpoint/场景描述；
- 选择的 viewpoint。

这部分作为下一步 F-CoT 和 selector 的直接上下文，不需要从向量库查询。

### 5.2 历史轨迹经验：构建

每个 episode 结束后，论文先根据预测路径与 GT 路径计算：

\[
R=\psi(NE,SR,OSR,SPL)(Nav,Nav^{GT})
\]

再让 LLM 按结果总结经验：

- **失败：** 分析错误、给出修正路线、总结同类任务注意事项；
- **成功且高效：** 保留并复现该决策过程；
- **成功但低效：** 总结怎样缩短路线、提高 SPL。

写入 Chroma 的轨迹经验大致为：

```text
(完整指令, 指令地标列表, 完整导航轨迹, 经验总结)
```

当前 episode 未结束时不能把自己的未完成轨迹写成完整任务经验；第 \(n\) 个 episode 只能查询此前已经完成的 episode。

### 5.3 历史轨迹经验：查询

论文使用当前指令中的**全部空间地标**作为 query，与历史经验库做文本向量余弦相似度，返回 Top-K 相似任务：

\[
T^e_n=\operatorname{TopK}\left(\cos(\text{current landmarks},M_{n-1})\right)
\]

轨迹经验主要提供全局路线模式和历史错误教训。

### 5.4 历史场景经验：构建

每完成一个 step，系统保存两种表示：

- **场景描述库 \(D\)：** LLM/VLM 场景描述的文本 embedding；
- **场景外观库 \(F\)：** CLIP 提取的图像 embedding。

论文强调只能使用已经完成步骤的观察，当前及未来步骤不能进入历史库。

### 5.5 历史场景经验：查询

场景查询使用 F-CoT 预测的下一地标 \(L^f\)，分成两路：

\[
V_d=\operatorname{T2D}_{retrieval}\left(\cos(L^f,D)\right)
\]

\[
V_f=\operatorname{T2V}_{retrieval}\left(\cos(\operatorname{CLIPText}(L^f),F)\right)
\]

然后合并文本描述检索和图像外观检索得到的场景结果。比如下一地标是 `Kitchen`，系统会返回历史中语义上像厨房、视觉上也像厨房的少量场景。

### 5.6 两类检索的区别

| 经验 | Query | 匹配方式 | 作用范围 |
|---|---|---|---|
| 轨迹经验 | 当前指令的全部地标 | 文本—文本余弦相似度 | 提供任务级全局经验 |
| 场景描述经验 | 预测的下一地标 | 文本—文本余弦相似度 | 提供当前步骤的局部场景先验 |
| 场景外观经验 | 预测的下一地标 | CLIP 文本—图像相似度 | 补充颜色、布局、纹理等视觉信息 |

## 六、最终动作决策

最终 selector 综合以下信息：

- 完整指令及拆出的动作、地标；
- 当前 observation；
- 当前 episode 历史；
- 已完成动作与下一地标；
- 检索到的轨迹经验；
- 检索到的场景经验；
- 当前候选 viewpoints。

模型先描述当前候选视图，再结合未来提示和历史经验选择一个 viewpoint。动作执行后，新的观察和决策继续写入历史，形成循环。

## 七、实验结果中最值得注意的部分

论文在 R2R-CE 上以 Gemini-2.5-pro 做的关键消融如下：

| 配置 | NE↓ | OSR↑ | SR↑ | SPL↑ |
|---|---:|---:|---:|---:|
| 直接推理 Base | 8.43 | 14 | 9 | 7.46 |
| 只加未来动作 | 6.31 | 33 | 25 | 22.10 |
| 只加未来地标 | 6.39 | 31 | 23 | 19.96 |
| 未来动作 + 未来地标 | 5.79 | 36 | 27 | 24.92 |
| 再加轨迹经验 | 5.69 | 42 | 31 | 27.64 |
| 完整 EvoNav | 5.04 | 51 | 43 | 37.77 |

论文还报告：

- 同为 Gemini-2.5-pro 时，EvoNav 的 SR/OSR 为 43/51，Open-Nav 为 23/30；
- 场景描述和场景外观都有效，文本描述略强，二者结合最好；
- Top-1 轨迹优于返回 2 或 3 条轨迹；
- 场景经验在 Top-4 图像时最好，继续增加会引入噪声；
- `30-start` 优于过早或过晚开始检索。

关于最后一点，结合“完整轨迹只能在 episode 结束后写入”的定义，本文将 `30-start` 理解为：先用 episode 序列的前一部分积累经验库，再对后续 episodes 检索，而不是单条轨迹走到 30% 才开始查询。论文原文措辞略有歧义，代码未公开前不把这一解释写成完全确定的实现事实。

这些数字证明该组合在论文协议下有效，但不能直接当作当前项目的预期增益，因为模型、episode 顺序、历史共享方式、提示词和评测子集都可能不同。

## 八、论文的优点

1. **Query 有明确来源。** 场景库不是拿整条长指令模糊检索，而是拿下一地标做局部查询。
2. **任务级与步骤级经验分开。** 完整路线经验和单帧场景经验承担不同职责。
3. **成功与失败都可写入。** 失败不只是丢弃，而是被总结为后续任务的避错经验。
4. **检索预算经过消融。** 论文明确展示更多历史不一定更好，小 Top-K 反而更可靠。
5. **无额外模型训练。** 主要依赖 prompting、embedding 和向量检索，适合快速验证。
6. **历史与未来形成闭环。** 下一地标不仅辅助当前推理，还主动决定应从历史中找什么。

## 九、论文的限制与实验协议风险

### 9.1 LLM 进度估计缺少可观测证据

论文使用 LLM 根据文本历史判断哪些动作已完成。这与当前项目已经发现的风险一致：模型可以把“计划穿门”误写成“已经穿门”，并继续在后续上下文中强化这一错误。

### 9.2 未来预测不是真正的世界预测

它没有判断“选择 viewpoint 3 后未来画面会怎样”，也没有比较多条动作分支的未来结果。F-CoT 主要是下一子动作/地标预测，不能等同于 world model 或 model-based planning。

### 9.3 历史经验生成使用 GT 结果

任务级经验通过 \(Nav^{GT}\)、SR、SPL 等结果评价生成。如果这些经验在 val_unseen 测试过程中写入，并被后续测试 episode 查询，那么实验属于 continual/transductive test-time memory，而不是 episode 独立的标准评测。其结果还会受 episode 顺序、同一 scan 是否重复以及 warm-up 比例影响。

这不等于直接读取当前 episode 的未来 GT，但必须与“每个测试 episode 互相隔离”的口径分开报告。

### 9.4 地标 query 过于粗糙

用全部地标检索轨迹、用单个下一地标检索场景，容易被 `door`、`room`、`hallway` 等泛类词干扰，也无法区分两个外观相似的 doorway 是否为同一实例。

### 9.5 事实与模型意见没有充分分权

论文把 observation、thought、action 一起放入轨迹历史。若没有明确 provenance，模型推理中的错误判断可能在总结后变成貌似可靠的经验。

### 9.6 复现条件仍不完整

代码尚未公开，暂时无法核对 embedding 模型、Chroma 配置、prompt、去重逻辑、检索跨 scan 规则和 episode 顺序敏感性。

## 十、与当前项目的对应关系

### 10.1 当前项目已经比论文更强的部分

| EvoNav | 当前项目 | 判断 |
|---|---|---|
| LLM 拆动作与地标 | 两阶段解析、复合动作展开、terminal target、Anchor Chain | 已覆盖且约束更严格 |
| LLM 估计已完成动作 | ACN/RouteState 根据当前证据、动作前后变化和执行回执推进 | 当前方案更可信，不应回退 |
| 模型自己决定停止 | StopCoordinator + VisualTargetVerifier + 证据链 | 当前权限边界更严格 |
| thought 与观察一起存历史 | 事实、执行回执和模型理由已可分开记录 | 当前结构更适合可靠记忆 |

尤其是“LLM completion”路线已经被当前实验否定并从权威进度链移除。因此不能因为 EvoNav 的消融好看，就把 LLM 进度估计重新接回 ACN。

### 10.2 当前项目真正缺少的部分

当前项目已有结构化完整历史，但还没有稳定的运行时查询机制。随着轨迹变长，selector 仍可能面对：

- 历史文本过长；
- 早期关键路口被近期记录淹没；
- 反复选择已经失败的方向；
- 同类门、房间和家具之间的实例混淆；
- 模型旧理由被误当成事实。

EvoNav 对当前项目的最大补充不是“重新做进度预测”，而是：

> 把 ACN 已经确定的当前/下一 Anchor 当作 query，主动找回与这个 Anchor、当前地点和失败事件有关的历史记录。

## 十一、借鉴决策

### 11.1 可以直接借鉴

1. **未来地标驱动查询。** 使用 ACN 的当前未完成 Anchor/下一 Anchor 作为 query，而不是让另一个 LLM 重新猜当前进度。
2. **轨迹经验与场景经验分库。** 地点—事件记忆负责全局走法，视觉快照/描述负责局部识别。
3. **小 Top-K 和固定上下文预算。** 把论文的 Top-1 轨迹、Top-4 场景作为候选搜索点，不直接当成最终超参数。
4. **成功、低效和失败分开处理。** 但分类必须来自可验证结果，而不是只靠 LLM 自我评价。
5. **先积累再检索。** 冷启动阶段经验不足时不强行查询；在线版本可进一步改成事件触发。
6. **查询结果记录 provenance。** 每条结果保留 episode、step、place、感知源、执行回执和入选分数。

### 11.2 改造后借鉴

1. **F-CoT 改成 F-Anchor。** 不生成自由文本式“我大概完成了什么”，直接读取 `RouteState.current_anchor`、`missing_evidence` 和 remaining anchors。
2. **纯语义检索改成混合检索。** 语义分数之外加入当前拓扑节点、相邻关系、时间、失败事件和来源可靠性。
3. **场景图像默认只返回引用。** 先把简短事实送进 selector；只有同类实例或空间关系难以区分时，才让视觉模型重看少量 RGB-D 快照。
4. **episode 后反思放到离线。** 标准 val_unseen 主结果不使用前序测试 episode 的 GT 反思；跨 episode 经验另设 continual 实验。
5. **检索结果只服务选路。** 它不能推进 ACN，不能确认动作完成，也不能批准 STOP。

### 11.3 不建议借鉴

1. 用 LLM 的未来动作反推权威路线进度；
2. 把历史 thought 当成已发生事实；
3. 在标准 val_unseen 主实验中边读取测试 GT 指标、边把总结写给后续测试 episode；
4. 只凭 `door/room/hallway` 等泛类词做向量 Top-K；
5. 每步把多条完整历史轨迹和多张图无条件塞进 Qwen；
6. 只看 selector 命中率判断记忆有效，而不看 OSR、路径和失败结构。

## 十二、推荐的最小方案：EvoNav-ACN Memory v1

### 12.1 目标

第一版只解决**单 episode 内的历史找回和避免重复失败**，不做跨 episode 学习，不改 ACN，不改 STOP 链，不增加新的 LLM 调用。

### 12.2 写入的事实记忆

每个完成 step 生成一个只追加、不可回写的 `MemoryItem`：

```json
{
  "episode_id": "...",
  "step_id": 7,
  "place_id": "agent-pose/topology cluster",
  "pose": {"position": [0, 0, 0], "heading": 0.0},
  "anchor": {
    "index": 2,
    "action": "go through",
    "landmark": "doorway",
    "room": "hallway",
    "relation": null
  },
  "observation_facts": {
    "matched_terms": ["doorway"],
    "scene_description": "...",
    "rgb_d_ref": "...",
    "sources": ["RAM", "SpatialBot", "visual_evidence"]
  },
  "decision": {
    "candidate_ids": [0, 4, 7],
    "selected_candidate": 4
  },
  "execution_receipt": {
    "measured_displacement_m": 0.12,
    "collision": true
  },
  "events": ["low_motion", "collision", "anchor_not_advanced"],
  "policy_opinion": {
    "selection_rationale": "..."
  }
}
```

`policy_opinion` 必须与事实字段分开，且检索到的 opinion 不具备状态写权限。

### 12.3 查询构造

查询不使用整条原始指令，而使用：

```text
当前 ACN Anchor：action + landmark + room + relation
+ 当前 place/topology node
+ ACN missing_evidence
+ 当前事件：loop / collision / low_motion / stop_rejected / anchor_stalled
```

建议的候选评分形式为：

\[
s=\lambda_s s_{semantic}+\lambda_p s_{place}+\lambda_e s_{event}
  +\lambda_r s_{recency}+\lambda_q s_{source}
  -\lambda_g p_{generic}-\lambda_d p_{duplicate}
\]

这里不是预设已经有效的最终公式。权重、阈值和 K 必须先在离线查询集上确定。

### 12.4 查询时机

近期若干步继续直接进入工作历史；较早记忆只在以下事件触发：

- 连续若干步 Anchor 未推进；
- 检测到同一 place/node 重访；
- 碰撞或低位移；
- 再次准备选择过去已失败的候选；
- STOP 被正式证据链拒绝；
- Anchor 切换，需要找与下一 Anchor 相关的旧观察。

事件触发比固定“每一步都查”更适合当前系统，也更容易控制延迟和提示词噪声。

### 12.5 返回给 selector 的格式

只返回短、可验证、与当前决策直接相关的字段，例如：

```text
[Memory evidence]
- Step 3, same place: candidate 4 was selected; displacement 0.12m;
  collision=true; anchor did not advance.
- Step 1, adjacent place: candidate 7 showed the target doorway and was not explored.
```

不要默认返回大段历史 CoT，也不要把“模型认为已经穿门”改写成“已经穿门”。

### 12.6 权限边界

```text
Memory retrieval ──→ waypoint selector only
当前观察 + 执行回执 ──→ ACN progress
ACN state + terminal evidence ──→ StopCoordinator
```

这是把 EvoNav 接入当前项目时最重要的改造。

## 十三、建议的实验顺序

### E0：离线查询质量，不影响决策

从已有 EP100 trace 选出以下 query 点：重访、碰撞、低位移、Anchor 长时间未推进、MOVE_BACK、STOP 被拒。人工或半自动标注哪些历史步骤对当前决策有用。

对比四个检索臂：

| Arm | 历史策略 |
|---|---|
| A | 最近窗口/时间倒序 |
| B | EvoNav 式 Anchor 语义检索 |
| C | place + event 检索 |
| D | Anchor + place + event 混合检索 |

报告 Recall@K、Precision@K、MRR、泛类词误召回、重复率、token 数和耗时。先确定检索本身能否找对记录；不能因为最终 SR 尚未运行就跳过这一层。

**进入在线实验的条件：** D 在相同预算下稳定优于 A/B，并通过同类 doorway、泛类 room、模型理由与执行回执冲突等 hard negatives。数值阈值应在标注集规模和基线分布确定后预注册，不在 val_unseen 上反复调参。

### E1：LOG_ONLY/trace-only 接线

实现 memory 写入、查询和 `memory_retrieval` trace，但不把结果交给 selector。检查：

- 只能检索 `step_id < current_step` 的记录；
- 无目标 GT、参考路径和 distance-to-goal 进入 query 或 memory；
- 每条结果含入选原因和分项分数；
- 同一输入固定 seed 可复现；
