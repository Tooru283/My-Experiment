# 导航记忆与查询机制调研报告

**调研时间：** 2026-09-08  
**调研对象：** 具身导航中的轨迹记忆、拓扑记忆、视觉场景记忆，以及 LLM Agent 的记忆查询方法。  
**当前代码状态：** 此前试写的“最近记录＋关键词＋执行异常”查询机制已撤回。当前保留结构化历史记录，但尚未引入新的历史检索策略。

## 一、调研问题

当前导航器会在每一步参考历史。结构化记录已经能够区分：

- 动作前看到了什么；
- Qwen 为什么选择该候选；
- 环境实际执行了什么；
- 实际位移和碰撞结果是什么。

但随着轨迹增长，把全部历史交给 Qwen 会产生三个问题：输入越来越长、无关记录干扰当前选路、旧的模型猜测可能被反复引用。本次调研主要回答：

1. 导航记忆应当按时间、地点还是语义组织；
2. 当前动作应该怎样形成查询；
3. 最近历史与较早历史如何组合；
4. 怎样避免模型自己的旧判断变成完成事实；
5. 怎样验证查询确实改善导航，而不只是缩短提示词。

## 二、主要论文

### 2.1 HAM-VLN：与当前系统最接近的方法

**论文：** [HAM-VLN: Harnessing Hierarchical Agentic Memory for Zero-Shot Vision-and-Language Navigation](https://arxiv.org/abs/2607.29600)，arXiv 预印本，2026 年 7 月提交。

HAM-VLN 面向使用多模态大模型进行逐步决策的零样本 VLN。它建立带深度信息的持续世界图：最近 waypoint 在有限窗口中原样保留；更早的地点按照与当前子目标的相关性、时间远近和重要性检索，并补充图上的一跳相邻地点。论文报告在不增加 waypoint 决策调用次数的情况下，将上下文长度降低超过 65%。

**可以借鉴：**

- 最近步骤与较早记忆采用不同处理方式；
- 查询条件来自当前子目标，而不是整条指令中的所有名词；
- 地点之间的连通关系参与查询；
- 记忆写入可以和原有选路调用共用一次请求，控制推理成本。

**不能直接照搬：** HAM-VLN 让模型同时写入房间、物体、导航进度和失败说明。当前项目已经由 ACN 维护正式路线进度，因此 Qwen 写出的进度只能作为模型意见，不能覆盖 ACN。HAM-VLN 目前是预印本，其报告结果也不能直接视为当前 R2R-CE 配置下的预期收益。

### 2.2 MemoNav：只让与当前目标有关的地图节点进入工作记忆

**论文：** [MemoNav: Working Memory Model for Visual Navigation](https://openaccess.thecvf.com/content/CVPR2024/papers/Li_MemoNav_Working_Memory_Model_for_Visual_Navigation_CVPR_2024_paper.pdf)，CVPR 2024。

MemoNav 将历史观测组织成拓扑地图节点。局部节点作为短期记忆，一个连接所有节点的全局节点聚合长期场景信息；模型根据当前目标对节点打分，暂时排除低相关节点，再由保留节点形成工作记忆。

**可以借鉴：**

- 导航历史应围绕“到过的地点”组织，而不只是按时间排列文本；
- 查询结果是为当前目标临时形成的工作记忆，完整记忆不应被真正删除；
- 重复或无关地点会降低决策效率，缩短历史必须考虑目标相关性。

**适用边界：** MemoNav 研究的是经过训练的 ImageNav 模型，其目标是目标图像，当前项目则使用文本指令、规则化 ACN 和零样本 Qwen。它的注意力和遗忘模块不能直接复制，但“完整地图、临时筛选、工作上下文”三层关系值得采用。

### 2.3 TrajRAG：检索过去的完整导航经验

**论文：** [TrajRAG: Retrieving Geometric-Semantic Experience for Zero-Shot Object Navigation](https://openaccess.thecvf.com/content/CVPR2026/html/Wang_TrajRAG_Retrieving_Geometric-Semantic_Experience_for_Zero-Shot_Object_Navigation_CVPR_2026_paper.html)，CVPR 2026。

TrajRAG 将轨迹压缩成同时包含空间布局和语义内容的表示，再用分层结构进行由粗到细的检索。导航中的候选探索方向形成轨迹假设，用这些假设查询相似的历史经验，返回的经验辅助大模型选择下一步。

**可以借鉴：**

- 查询对象可以是“准备走出的局部轨迹”，不必局限为单个地标词；
- 轨迹应同时保留几何变化和语义地标；
- 大量经验需要先粗筛，再读取细节；
- 成功路线和失败路线都可以形成经验，但必须说明其结果和来源。

**适用边界：** 这更适合后续跨 episode 或长期学习。标准 val_unseen 评测中，若系统把先前测试 episode 的结果写入公共记忆，会改变实验设定并可能造成评测污染。因此当前阶段应先研究单 episode 内的查询；跨 episode 记忆需要独立实验协议。

### 2.4 CMMR-VLN：多模态经验检索与失败反思

**论文：** [CMMR-VLN: Vision-and-Language Navigation via Continual Multimodal Memory Retrieval](https://arxiv.org/abs/2603.07997)，arXiv 预印本，2026 年 3 月提交。

CMMR-VLN 使用全景图像和显著地标索引历史经验，通过检索增强生成辅助导航。完成后，它保存完整成功路线；失败时，重点保存最初的关键错误。

**可以借鉴：**

- 查询不应只使用文本，也可以使用当前全景的视觉特征；
- 失败历史没有必要完整保存，最早导致路线偏离的决策可能更有价值；
- 写入策略与查询策略需要分别设计。

**适用边界：** 失败原因不能只由 Qwen 事后猜测。当前项目可以先用执行回执、碰撞、回退和 ACN 长时间不推进等可观察事件确定失败片段，再把模型解释单独保存。

### 2.5 3D-Mem：用多视角快照保留空间关系

**论文：** [3D-Mem: 3D Scene Memory for Embodied Exploration and Reasoning](https://openaccess.thecvf.com/content/CVPR2025/html/Yang_3D-Mem_3D_Scene_Memory_for_Embodied_Exploration_and_Reasoning_CVPR_2025_paper.html)，CVPR 2025。

3D-Mem 不只保存离散物体名，而是保存覆盖一个区域的多视角图像快照，从而保留物体共现、方向和空闲空间等难以用简单关系词表达的信息。它还保存面向未探索区域的 frontier snapshots，并通过预筛选控制长期记忆规模。

**可以借鉴：**

- `left of`、`through`、开口和房间关系需要比物体标签更丰富的视觉上下文；
- 文本摘要不应是唯一记忆，必要时应保留可回看的 RGB-D 或其引用；
- 查询可以先根据物体和地点筛选，再让视觉模型查看少量原始快照。

**适用边界：** 当前每步视觉推理已经较慢，不能把大量历史图片重新送入 Qwen。视觉快照更适合作为按需二级证据，而不是每步默认输入。

### 2.6 LightMem：固定预算和两阶段检索

**论文：** [Lightweight LLM Agent Memory with Small Language Models](https://aclanthology.org/2026.acl-long.588/)，ACL 2026 长文。

LightMem 将即时上下文、可复用摘要和长期知识分层。在线阶段在固定预算内先进行向量粗检索，再做语义一致性重排；较重的归纳与合并放到离线阶段。论文关注对话式 Agent，但它直接讨论了小模型场景中查询构造、候选过滤与延迟之间的矛盾。

**可以借鉴：**

- 为返回条数和输入 token 设置固定预算；
- 先使用便宜方法产生候选，再对少量候选精排；
- 在线导航只做必要查询，历史合并和统计可以离线执行；
- 写入、检索、长期整理是三个不同职责。

**适用边界：** 当前 Qwen-4B 不适合每步再承担一次记忆重排。第一版应使用可检查的程序评分或已有视觉/文本特征，避免新增模型调用。

### 2.7 Hindsight：把观测事实和模型意见分开

**论文：** [Hindsight: Structured Agent Memory that Retains, Recalls, and Reflects](https://aclanthology.org/2026.acl-demo.27/)，ACL 2026 System Demonstration。

Hindsight 将世界信息、经历、观察和意见分别组织，并组合向量检索、关键词匹配、图关系与时间过滤。其核心启发不是某个具体排序公式，而是让系统能够区分“发生过什么”和“模型怎样解释它”。

**可以借鉴：**

- 执行回执、感知结果、ACN 正式状态和 Qwen 理由必须分开存储；
- 查询结果需要携带来源，使用者才能判断其可靠程度；
- 模型意见可以辅助选路，但不能通过记忆查询升级成动作完成事实。

这一点与当前项目最关键的问题直接对应：`The left waypoint should take me through the doorway` 是行动意图，不能在历史中变成 `passed through the doorway`。

### 2.8 HAMT 与 DUET：两个重要的导航基线思想

**论文：** [HAMT: History Aware Multimodal Transformer for Vision-and-Language Navigation](https://arxiv.org/abs/2110.13309)，2021；[DUET: Think Global, Act Local](https://openaccess.thecvf.com/content/CVPR2022/html/Chen_Think_Global_Act_Local_Dual-Scale_Graph_Transformer_for_Vision-and-Language_Navigation_CVPR_2022_paper.html)，CVPR 2022。

HAMT 联合编码指令、长时间历史和当前观测，说明长路线中历史确实有价值；DUET 一边利用动态拓扑图做全局规划，一边保留局部视觉细节。这两项工作不是面向 LLM 的显式检索系统，但提供了两个重要对照：完整历史能否优于压缩历史，以及全局地点结构能否与当前局部候选共同改善决策。

## 三、调研得到的共同结论

### 3.1 记忆不能只是一串文字

导航中的“何时发生”和“在哪里发生”同样重要。只保存一句 `saw a doorway`，无法判断这是当前位置、之前经过的位置，还是另一个同类门口。更合理的记忆单元应同时包含时间、地点、观察、动作与结果。

建议的记忆单元：

~~~json
{
  "memory_id": "episode:step:place",
  "episode_id": "...",
  "step": 7,
  "place_id": "由自身位姿聚类得到的拓扑节点",
  "pose": {"position": [0.0, 0.0, 0.0], "heading": 0.0},
  "observation_refs": {"rgb_d": "引用，不默认放入提示词"},
  "perception": {
    "ram_tags": [],
    "scene_description": "...",
    "source": "RAM / SpatialBot / Qwen"
  },
  "action_receipt": {
    "candidate_id": "3",
    "command_distance_m": 2.0,
    "measured_displacement_m": 0.1,
    "collision": true
  },
  "acn_state": {
    "current_action": "Go through the doorway",
    "status": "unknown",
    "missing_evidence": ["verifier_not_implemented:cross"]
  },
  "policy_opinion": {
    "selection_rationale": "The doorway appears left."
  }
}
~~~

其中 `pose` 是智能体自身状态，不包含真实目标位置；`policy_opinion` 永远不能作为 ACN 完成证据。

### 3.2 查询必须同时考虑任务、地点和证据缺口

只有关键词相关性会召回“名字相同但实例不同”的物体；只有时间远近会忘记早期关键路口；只有视觉相似度又可能把外观相近的不同房间混为一处。

建议的查询由四部分组成：

~~~text
当前 ACN 动作及其目标、关系
+ 当前地点和当前全景特征
+ ACN 当前缺少的证据
+ 当前失败信号：碰撞、低位移、重复选择或回退
~~~

候选记忆的排序可以综合：

~~~text
动作相关性
+ 视觉地点相似度
+ 拓扑距离
+ 时间新近性
+ 证据可靠程度
- 与已选记忆的重复程度
~~~

这是根据论文归纳出的待验证设计，不是已经确定有效的公式。具体权重和返回数量应通过开发集或离线标注选择，不能直接在 val_unseen 测试结果上反复调参。

### 3.3 最近历史与较早历史应采用不同规则

近期步骤提供动作连续性，适合原样保留；较早步骤数量更多，适合按地点和当前任务检索。这一结构同时出现在 HAM-VLN 的近期窗口、MemoNav 的工作记忆和 LightMem 的分层存储中。

建议第一版采用：

~~~text
工作历史：最近若干步，直接读取
地点记忆：同一地点和拓扑邻居，按需读取
事件记忆：ACN 推进、碰撞、低位移、回退，按当前状态读取
视觉证据：只返回引用，需要判断空间关系时再查看
~~~

这里暂不固定“最近几步”和“返回几条”的数值，先通过离线查询实验确定预算。

### 3.4 查询结果只能辅助选路

查询系统找回的是过去记录，不是当前动作已经完成的证明。例如，历史中曾在 Step 2 看到 door，只能说明当时某个方向出现了门，不能证明 Step 7 已经穿过该门。

权限关系应保持：

~~~text
记忆查询结果 ──→ 帮助 Qwen 选择下一方向
当前观测与执行回执 ──→ 交给 ACN 检查动作变化
ACN 路线状态与终点证据 ──→ 交给 StopCoordinator
~~~

模型理由、历史摘要或检索分数都不能直接推进 ACN，也不能直接批准正式 STOP。

## 四、对当前项目的推荐方案

### 4.1 第一阶段：单 episode 的地点—事件记忆

第一阶段只处理本次 episode 内的历史，不引入跨任务经验。完整记录保持不可变，并从中建立两个轻量索引：

1. **地点索引：** 使用智能体自身位置和连通关系形成拓扑节点，同一地点的多次观测合并引用；
2. **事件索引：** 标记 ACN 推进、碰撞、低位移、重复候选和 MOVE_BACK 等事件。

每一步始终提供近期工作历史。当出现动作切换、长时间不推进、碰撞、回退或 STOP 提案时，再查询较早的地点和事件。查询记录必须包含入选原因和各项分数，便于从日志复核。

这一阶段不增加 LLM 请求：程序负责候选筛选和排序，原有 waypoint selector 使用检索结果。

### 4.2 第二阶段：加入视觉地点匹配

若仅靠位置聚类和文本地标无法区分相似位置，再加入当前全景与历史全景的视觉特征匹配。原始 RGB-D 使用引用保存，只有少量高排名快照进入二级视觉检查。

必须特别评估：转身后是否仍能识别同一地点、相似房间是否被错误合并、同类别门口是否被当成同一目标实例。

### 4.3 第三阶段：跨 episode 经验记忆

只有在单 episode 方案有效后，再研究 TrajRAG/CMMR-VLN 风格的成功路线和失败片段检索。该实验应单独命名为 continual 或 lifelong setting，并规定：

- 记忆来自哪些数据划分；
- 是否允许在评测过程中写入；
- episode 之间是否共享场景；
- 报告冷启动与已有记忆两种结果。

标准零样本 val_unseen 主结果建议保持 episode 间记忆隔离，以免与旧基线的实验协议不一致。

## 五、实验设计

### 5.1 先建立离线查询测试集

从已有 EP100 trace 中选择需要历史信息的时刻，例如重复转向、碰撞后恢复、重新遇到旧地标、返回旧路口和提出 STOP。对每个时刻标注哪些历史步骤对当前决策有用，以及用途属于：

~~~text
定位当前地点
确认已经来过
避免重复失败
寻找未探索分支
理解当前动作目标
辅助终点身份判断
~~~

查询模块首先评价：Recall@K、Precision@K、MRR、重复记录比例、来源组成和查询耗时。这里评价的是“能否找回有用记录”，不能用最终 SR 替代查询质量。

### 5.2 在线消融

| 实验 | 提供给 selector 的历史 |
|---|---|
| A | 当前完整结构化历史 |
| B | 只有近期窗口 |
| C | 近期窗口＋地点拓扑查询 |
| D | 近期窗口＋地点、动作、失败信号的混合查询 |

除历史输入外，ACN、视觉证据、STOP 链、episode 列表、模型和解码参数均保持相同。报告：SR、OSR、SPL、nDTW、平均步数、碰撞、MOVE_BACK、重复候选/重复地点、正式停止来源、selector 输入字符或 token 数、查询耗时及每步总耗时。

### 5.3 关键反例

查询机制至少应通过以下反例：

- 当前寻找 bedroom，历史中出现 dining room，不能因共有 `room` 就高排名；
- 两个不同 doorway 外观相似，不能只因类别一致就合并实例；
- Qwen 旧理由写“已经经过 sofa”，执行回执显示碰撞，该理由不能成为完成证据；
- 早期关键路口与当前回退直接相关，不能仅因时间较远而丢失；
- RAM 某一帧漏掉房间标签，不能把“未检测到”保存成“确定不在房间”；
- val_unseen 的某个测试 episode 不能无说明地成为后续测试 episode 的经验库。

## 六、结论与近期决策

最适合当前项目的方向不是通用对话向量库，而是**带来源的地点—事件记忆**：近期步骤保持原样，较早历史围绕当前 ACN 动作、当前位置、拓扑关系和失败信号查询。HAM-VLN 提供最直接的系统参考；MemoNav 和 DUET 支持地点拓扑组织；LightMem 支持固定预算和两阶段筛选；Hindsight 支持事实与意见分离；TrajRAG、CMMR-VLN 和 3D-Mem 更适合后续的跨 episode 经验及视觉快照扩展。

当前先保留“结构化完整历史”作为无查询基线。下一步应建立离线查询测试集并确定检索指标，再实现可开关的 memory v1，随后做 A/B/C/D 消融。现阶段不把查询机制接入主 Pipeline，也不把未经在线实验验证的设计写成已解决问题。
