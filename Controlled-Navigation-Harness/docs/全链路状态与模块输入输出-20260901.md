# 全链路状态与模块输入输出：当前实现数据契约

> 本文只描述当前工作树实际存在的 pipeline，不描述目标架构。目标架构见 [[主Pipeline重构设计-20260901]]。
>
> 阅读方法：每个模块都回答五个问题——谁调用、输入是什么格式、输出是什么格式、输出交给谁、当前是否改变最终动作。

## 0. 一页结论

当前运行不是一条统一 RouteState 主链，而是三条并行数据流：

```text
在线动作流
Habitat observation
  -> waypoint predictor
  -> CandidateState[] + RGB-D
  -> SpatialBot/RAM observe_dict
  -> LLM completion + LLM selector
  -> V2/depth/candidate-prior/backtrack 等覆盖
  -> Habitat action

空间状态流（当前主要是 shadow）
instruction/actions/landmarks
  -> L0 anchors
  -> L1 progress + M1 graph + M2 landmark pool
  -> L4 terminal verdict
  -> RouteState v1
  -> trace/navigation record

评估审计流
envs.step() info
  -> distance/success/OSR 等 simulator 指标
  -> audit/navigation record/episode metrics
  -X-> RouteState 和在线 selector
```

当前最重要的权限事实：

| 数据/模块 | 当前是否进入动作决策 |
|---|---:|
| LLM completion `estimation: str` | 是，是在线进度文本 |
| L1 `progress_locator_results: dict` | 否，默认 `LOG_ONLY=true` |
| M1 `memory_results: dict` | 否，默认 `LOG_ONLY=true` |
| M2 `landmark_pool_results: dict` | 否，只给 L4 和 RouteState |
| L4 `terminal_gate_results: dict` | 否，默认 `LOG_ONLY=true`；代码具备拒绝 STOP 接口 |
| RouteState v1 | 否，只写记录/trace |
| V2 VisualTargetVerifier | 是，可拒绝 STOP |
| depth STOP veto | 是 |
| candidate prior | 是，可覆盖移动候选 |
| backtrack | 是，可提供并执行 `MOVE_BACK` |
| U1/U2/U3 | 否，当前 `DECISION_EFFECT_UNIT=none` |

## 1. 公共数据类型

### 1.1 Episode 文本

| 名称 | Python 格式 | 产生者 | 直接消费者 |
|---|---|---|---|
| `instruction` | `str` | Habitat observation 的 `instruction.text` | action/landmark 解析、V1、V2、completion、selector、RouteState |
| `actions` | `str`，通常以换行分隔子动作 | action detection LLM 或 `actions_cache.json` | L0、completion、phase、STOP、selector |
| `landmarks` | `str`，通常以换行分隔地标 | landmark detection LLM 或缓存 | L0、V1/V2、M2 vocabulary、L4、selector |
| `history_traj` | `str` | `navigator.review_history(nav_history)` | completion、phase、STOP、selector |
| `estimation` | `str` | `navigator.estimate_completion()`，或 decision-active L1 覆盖 | phase、`should_stop`、V2/U2、selector |

注意：当前 `estimation` 仍是在线权威进度输入；RouteState 不是它的替代品。

### 1.2 图像与 waypoint 几何

```python
images_dict: Dict[str, Dict[str, PIL.Image.Image]]
# {candidate_id: {"rgb": PIL.Image, "depth": PIL.Image}}

radius_dict: Dict[str, scalar]
# {candidate_id: angle_rad}；名称虽叫 radius，实际是相对转角（弧度）

distance_dict: Dict[str, scalar]
# {candidate_id: waypoint_distance_m}
```

三者由 `construct_image_dicts(batch_distances, batch_angles, images_list)` 产生。

### 1.3 CandidateState

`build_candidate_records(radius_dict, distance_dict, images_dict)` 输出：

```python
CandidateState(
    candidate_id: str,
    direction_id: int,
    angle_rad: Optional[float],
    angle_deg: Optional[float],
    distance: Optional[float],
    raw_rank: int,
    image_ref: Optional[str],
    geometry_score: Optional[float],
    grounding_score: Optional[float],
    novelty_score: Optional[float],
    final_prompt_rank: Optional[int],
)
```

直接消费者：GeometryQuery、Grounder、V1、M1、candidate prior、trace。主 selector 实际仍主要读取 `observe_dict` 和候选 id，而不是读取完整 CandidateState。

### 1.4 observe_dict

```python
observe_dict: Dict[str, str]
# {
#   "1": "Direction 1 ... Scene Description: ... Scene Objects: chair | door | ...",
#   "2": "Direction 2 ...",
# }
```

产生者：`Open_Nav.observe_environment()`，其内部逐候选调用 SpatialBot 与 RAM。

直接消费者：

- LLM selector；
- `navigator.should_stop()`；
- V1/V2；
- fallback ranker；
- L1/M2 的 RAM tag 提取器；
- V3/V4 和诊断模块。

当前 `GEOMETRY_INJECTION=false`，所以 waypoint distance 不写进 selector 的观察字符串。

### 1.5 AgentState：已定义但未使用

源码定义了 `AgentState` dataclass，字段包括 episode/environment/candidates/perception/memory/selector/action/verifier/fallback/metrics。

**当前训练循环没有构造或传递 AgentState。** 实际状态仍存在局部变量、模块实例和事件日志中。因此后文不把 AgentState 画成真实链路节点。

## 2. Episode 初始化链

```text
Habitat reset
  -> generate_input(observation)
       输出 instruction:str, images_list
  -> action detection / cache
       输出 actions:str
  -> landmark detection / cache
       输出 landmarks:str
  -> L0 build_anchor_chain(actions, landmarks)
       输出 anchor_chain_result:dict
  -> reset L1/M1/M2 及其他 episode state
```

| 生产者 | 输入 | 输出格式 | 给谁 | 生命周期 |
|---|---|---|---|---|
| `generate_input` | Habitat observation | `(instruction: str, images_list)` | 解析器、waypoint 图像构造 | 每集初始化，图像每步更新 |
| action detection | `instruction:str` | `actions:str` | L0、completion、selector | 每集一次，可缓存 |
| landmark detection | `instruction:str` | `landmarks:str` | L0、V1/V2、M2、L4 | 每集一次，可缓存 |
| L0 `build_anchor_chain` | `actions`, `landmarks` | `anchor_chain_result:dict` | L1 reset、M2 vocabulary、RouteState | 每集一次 |
| L1 `reset_episode` | `anchors:list[dict]` | 无返回；清空 `j/history` | L1 内部状态 | 每集一次 |
| M1 `reset_episode` | 无 | 无返回；清空 graph/history | M1 内部状态 | 每集一次 |
| M2 `reset_episode` | anchor terms | 无返回；设置 vocabulary | M2 内部状态 | 每集一次 |

### 2.1 L0 输出 schema

```json
{
  "anchors": [
    {
      "idx": 0,
      "landmark": "door",
      "room": null,
      "action": "go",
      "raw": "Go through the door",
      "terminal": false,
      "kind": "object",
      "key": "door"
    }
  ],
  "n_anchors": 4,
  "n_landmarks": 3,
  "n_landmarks_aligned": 2,
  "alignment_coverage": 0.75,
  "kind_counts": {"location": 0, "object": 3, "direction": 1, "unknown": 0},
  "degenerate": false
}
```

字段流向：

- `anchors[]` -> L1 constraint queue；
- anchor landmark/room terms -> M2 vocabulary；
- `anchors` 和完整结果 -> RouteState.plan；
- 不直接进入 selector，不直接产生动作。

## 3. 每步阶段 A：环境观察和候选构造

```text
Habitat observations
  -> waypoint predictor
  -> batch_angles / batch_distances
  -> construct_image_dicts
  -> images_dict + radius_dict + distance_dict
  -> build_candidate_records
  -> CandidateState[]
```

| 模块 | 输入格式 | 输出格式 | 直接消费者 | 动作影响 |
|---|---|---|---|---:|
| waypoint predictor | batched Habitat tensor observations | `batch_angles`, `batch_distances` 等 tensors | `construct_image_dicts` | 候选集合本身决定可执行空间 |
| `construct_image_dicts` | angles/distances + 12-view images | `images_dict`, `radius_dict`, `distance_dict` | perception、candidate builder、动作编码 | 是 |
| `build_candidate_records` | 三个 dict | `List[CandidateState]` | harness 模块和 trace | 间接；当前 selector 不完整消费其分数字段 |
| backtrack availability | last move、ego pose history、候选是否为空 | `{offered, stalled, dead_end, reverse_action_args, block_reasons...}` | selector allowed actions | 是，可能加入 `MOVE_BACK` |

## 4. 每步阶段 B：候选感知

```text
images_dict
  -> SpatialBot scene description
  -> RAM tags
  -> observe_dict: Dict[candidate_id, str]
```

### 4.1 SpatialBot/RAM 输出

每个候选最终合并为一个字符串，而不是结构化对象：

```text
Direction 3 ...
Scene Description: a hallway with white double doors ...
Scene Objects: hallway | door | wall | stairs
```

下游有两种消费方式：

1. selector/V2/fallback 直接读取整段文本；
2. L1/M2 用正则读取 `Scene Objects:` 后的 `|` 分隔 tag。

训练器由此临时生成：

```python
view_tags: Dict[str, List[str]]
# {candidate_id: [lowercase_ram_tag, ...]}

view_geometry: Dict[str, Dict[str, Optional[float]]]
# {candidate_id: {"angle_rad": ..., "distance": ...}}
```

`view_tags + view_geometry + agent pose` 是 L1 与 M2 的共享输入。

## 5. 每步阶段 C：视觉、几何和记忆模块

### 5.1 模块总表

| 生产者 | 输入 | 核心输出格式 | 直接给谁 | 当前动作影响 |
|---|---|---|---|---:|
| GeometryQuery | CandidateState、pose、images | `List[dict]`，每候选 world/depth/置信度 | diagnostic context、trace | 否 |
| GrounderDiagnostic | instruction/actions/landmarks、observe_dict、candidates | `List[dict]`，每候选 grounding score/约束 | diagnostic context、trace | 否 |
| V1 VisualEvidenceLogger | 文本目标、CandidateState、RGB-D、observe_dict | `visual_evidence_results:dict` | V2、V3、V4、fallback、candidate prior | 间接/是；V1 本身 log-only，但消费者可生效 |
| candidate prior scorer | CandidateState + V1 candidate evidence | `(scores:Dict[str,float], ranks:Dict[str,int])` | selector 后置 override | 是，当前 `LOG_ONLY=false` |
| V3 VisualEvidenceMemory | pose/heading + V1 + landmarks | `visual_evidence_memory_results:dict` | V4、U 系列、trace | 否 |
| V4 MultimodalSelectorContext | observe_dict + V1 + V3 | `augmented_observe_dict`, summaries | selector（仅 decision-active 时） | 当前否 |
| M1 VisualGraphMemory | step、pose/heading、CandidateState[] | `memory_results:dict` | RouteState、context builder；可追加 alert | 当前否 |
| L1 ConstraintQueueLocator | step、pose/heading、view_tags/view_geometry | `progress_locator_results:dict` | L4、RouteState；可覆盖 estimation | 当前否 |
| M2 LandmarkPool | step、pose/heading、view_tags/view_geometry | `landmark_pool_results:dict` + 内部 entries | L4、RouteState | 当前不直接影响动作 |
| L4 TerminalGate | L1 dict、M2 实例、最终地标 term | `terminal_gate_results:dict` | STOP gate wiring、RouteState | 当前否 |

### 5.2 V1 输出格式

V1 顶层是调用与解析结果：

```json
{
  "skipped": false,
  "model": "...",
  "requested_candidate_ids": ["1", "3"],
  "sampled_all": false,
  "parse_error": null,
  "schema_error": null,
  "schema_warnings": [],
  "parsed": {
    "candidates": [
      {
        "candidate_id": "1",
        "visible_landmarks": ["door"],
        "matched_instruction_terms": ["door"],
        "missing_instruction_terms": ["stairs"],
        "final_target_visible": true,
        "arrival_evidence": false,
        "confidence": 0.72,
        "spatial_notes": "..."
      }
    ]
  }
}
```

实际候选 schema 经过 `normalize_visual_evidence_parsed()` 归一；未采样不等于视觉否定。

数据去向：

- `parsed.candidates[]` -> V2；
- 同一 evidence -> candidate prior 分数；
- 同一 evidence -> fallback ranking；
- 同一 evidence -> V3 跨步视觉记忆；
- 不直接写 RouteState v1。

### 5.3 candidate prior 输出

```json
{
  "log_only": false,
  "scores": {"1": 0.83, "2": 0.25},
  "ranks": {"1": 1, "2": 2},
  "prior_top": "1",
  "candidate_count": 2
}
```

消费位置：LLM selector 得到移动候选后，`_candidate_prior_override(selector_vp)` 比较 softmax probability gap；可能把 selector 候选替换为 `prior_top`。它不覆盖 STOP 或 MOVE_BACK。

### 5.4 M1 输出格式

```json
{
  "visit_count": 3,
  "nearest_previous_step": 4,
  "revisit_score": 0.81,
  "candidate_novelty": {"1": 0.7, "2": 0.2},
  "loop_flag": true,
  "node_id": 2,
  "node_visit_count": 3,
  "node_count": 5,
  "loop_alert": true,
  "height_delta": 0.0,
  "alert_text": "Spatial memory alert: ...",
  "floor": 1,
  "floor_count": 2,
  "offered_directions": ["1", "2"],
  "taken_directions": ["2"],
  "unexplored_branch_count": 1
}
```

数据去向：

- graph/loop 字段 -> RouteState.spatial_graph/loop_status；
- `alert_text` -> 只有 M1 decision-active 时才追加到 selector context；
- `candidate_novelty` 当前不直接改变候选排序；
- selector 提交移动后调用 `note_taken(candidate_id)` 更新 M1 内部边记录。

### 5.5 L1 输出格式

```json
{
  "j": 2,
  "n_anchors": 4,
  "progress": 0.5,
  "complete": false,
  "current_kind": "object",
  "current_key": "stairs",
  "current_raw": "Go to the left of the stairs",
  "abstained_this_step": true,
  "abstain_steps": 3,
  "ever_satisfied": [0, 1],
  "distinct_j_values": 3,
  "regressions": 0,
  "stall_kind_counts": {"object": 2},
  "degenerate": false,
  "step_id": 6
}
```

输入判定规则：

- object：RAM tag 匹配且对应 waypoint `distance <= OBJECT_RADIUS_M`；
- direction：跨步 pose/heading window；
- location：RAM room tag 在候选方向中的占比达到 dominance；
- unknown：当前 `VACUOUS_UNKNOWN=true` 时直接满足。

数据去向：

- -> L4 的 `locator_state`；
- -> RouteState.progress.locator；
- decision-active 时 -> `completion_text():str` 覆盖 LLM estimation；
- 当前 `LOG_ONLY=true`，所以不覆盖在线 estimation。

重要：L1 当前同一步会先标记所有满足的 anchor，再连续推进 `j`，因此它实现的是“连续推进”，不是严格“一步最多一格”的策略 A。

### 5.6 M2 输出格式

M2 内部 entry：

```json
{
  "category": "door",
  "fused_pos": [1.2, 0.0, -3.4],
  "n_obs": 4,
  "first_step": 1,
  "last_step": 6,
  "min_distance": 1.5,
  "visible": true,
  "arrived": true
}
```

对外 `landmark_pool_results` 会移除 `fused_pos`：

```json
{
  "stage_id": 0,
  "pool_size": 3,
  "visible_count": 1,
  "arrived_count": 2,
  "tags_seen_this_step": 5,
  "entries": [
    {"category": "door", "n_obs": 4, "first_step": 1,
     "last_step": 6, "min_distance": 1.5, "visible": true, "arrived": true}
  ]
}
```

位置来源是候选 waypoint 粗坐标，不是对象实例坐标：

```text
theta = -heading - angle_rad
x' = x + distance * sin(theta)
z' = z - distance * cos(theta)
```

数据去向：

- `LandmarkPool.query(final_landmark_term)` -> L4；
- summary -> RouteState.landmark_memory；
- 不直接给 selector。

### 5.7 L4 输出格式

```json
{
  "verdict": "block",
  "allow_stop": false,
  "reason": "blocked by: chain_complete, final_landmark_arrived",
  "conjuncts": {
    "chain_complete": false,
    "all_previous_verified": true,
    "final_landmark_arrived": false
  },
  "j": 2,
  "n_anchors": 4,
  "final_landmark_term": "doorway",
  "final_landmark_entry": null,
  "degenerate": false,
  "decision_effect_enabled": false
}
```

数据去向：

- -> `gate_stop_request(stop_requested, reason, gate_result, decision_effect)`；
- -> RouteState.stop_evidence.terminal_gate；
- -> trace。

当前默认 `LOG_ONLY=true`，因此 `decision_effect_enabled=false`，L4 verdict 不改变 stop_flag。若启用，L4只能把 STOP 改为继续，不能主动制造 STOP。

## 6. 每步阶段 D：历史与在线进度

```text
nav_history:list
  -> navigator.review_history()
  -> history_traj:str
  -> navigator.estimate_completion()
  -> estimation:str
  -> 可选 L1 completion_text 覆盖
```

当前配置 `COMPLETION_ESTIMATION.MODE=llm`：

```python
estimation = navigator.estimate_completion(
    actions, landmarks, history_traj, current_step
)  # -> str
```

然后代码计算：

```python
locator_text = progress_locator.completion_text()  # -> str or None
if progress_locator_decision_effect and locator_text:
    estimation = locator_text
```

因此：

- 当前在线：LLM estimation -> STOP/phase/selector；
- L1 默认只记录；
- 即便未来 L1 生效，现代码仍先调用 LLM 再覆盖；
- completion trace 会记录原值以及 `locator_applied`，但下游实际变量可能已经被覆盖。

## 7. 每步阶段 E：Phase/U 系列

### 7.1 PhaseEvidence 输出

输入：instruction/actions/landmarks、`estimation:str`、history、step、最近 failure，以及兼容用 audit-only distance gains。

```json
{
  "phase": "search|approach|verify|recover|unknown",
  "current_subgoal": "...",
  "phase_reason": "...",
  "visual_budget": "low|medium|high",
  "confidence": 0.68,
  "action_count": 4,
  "completed_action_count": 2,
  "final_action_completed": false,
  "recent_progress": {
    "recent_distance_gains": [],
    "source": "simulator_goal_distance_audit_only",
    "decision_effect": false,
    "abstained": true
  },
  "last_failure": {"trigger_type": null, "failure_type": null}
}
```

数据去向：U1 context、U2、failure diagnostic、RouteState.progress.phase。当前 U 系列为 `DECISION_EFFECT_UNIT=none`，不改变 selector/STOP/recovery。

## 8. 每步阶段 F：STOP 数据流

当前 STOP 有两个主要提议入口和一个 proactive 入口：

```text
A. completion should_stop -> stop_flag
B. LLM selector predicts STOP -> next_vp="STOP"
C. proactive visual gate -> stop_flag
```

它们会经过部分相同但分散的验证逻辑。

### 8.1 should_stop 输出

```python
(stop_flag: bool, stop_reason: str) = navigator.should_stop(
    actions, landmarks, estimation, history, observation, step
)
```

副产物：`navigator.last_stop_gate_metadata: dict`，包含 action completion/final target 等解析结果，供 V2/U2/phase 使用。

### 8.2 V2 输入输出

输入包括：source、instruction/actions/landmarks、estimation/history/observation、V1 evidence、STOP proposal、selected candidate、step。

核心输出：

```json
{
  "source": "completion|selector|proactive",
  "step_id": 6,
  "stop_proposal": true,
  "stop_reason": "...",
  "verdict": "allow|reject|abstain",
  "final_target_visible": true,
  "arrival_evidence": false,
  "matched_final_landmarks": ["door"],
  "missing_final_landmarks": ["doorway"],
  "selected_candidate_verdict": {},
  "candidate_verdicts": [],
  "supporting_candidate_id": "3",
  "confidence": 0.72,
  "contradictions": [],
  "allow_blockers": [],
  "allow_warnings": []
}
```

V2 当前 decision-active，可拒绝 STOP。其输出也给 U2 和 failure diagnostic。

### 8.3 depth STOP veto

输入：与 STOP 相关方向的原始 depth image 和阈值。

输出为包含 `available/confirmed/vetoed/depth/threshold/fail_open` 等字段的 dict，直接参与 STOP 放行。它是独立停止机制，不属于 L4。

### 8.4 U2 StopEvidenceVerifier

输入：V2 dict、stop metadata、phase、文本目标、estimation、视觉持续性和 depth 结果。

输出：

```text
allow_stop: bool
allow_rescue: bool
abstain: bool
reject_reasons: list[str]
rescue_blockers: list[str]
intrinsic/trajectory/relation support
confidence: float
```

当前 U2 log-only。函数签名仍接收 `latest_goal_dist` 兼容旧 trace，但当前在线规则不应以该值做决策。

### 8.5 L4 接线

```python
resolved_stop, resolved_reason, blocked = gate_stop_request(
    stop_requested, reason, terminal_gate_results,
    terminal_gate_decision_effect
)
```

当前 `terminal_gate_decision_effect=false`，所以输入 STOP 原样返回。若为 true 且 L4 `allow_stop=false`，返回 `(False, "", True)`，后续进入移动选择/回退。

### 8.6 当前实际 STOP 次序

```text
completion proposal
  -> V2
  -> depth veto / proactive visual logic
  -> L4（当前只记录）
  -> 若未 STOP，运行 selector
       -> selector may propose STOP
       -> V2 + depth + U2(log-only) + L4(log-only)
       -> 拒绝后重新选移动或 fallback
  -> final stop_flag
  -> env action 0
```

当前没有单一 `StopDecision` 对象；stop_flag 会在多个分支被改写，这是目标重构要解决的问题。

## 9. 每步阶段 G：移动选路

### 9.1 Selector 输入

```text
instruction:str
actions:str
landmarks:str
history_traj:str
estimation:str
selector_observation:list[str] 或等价文本集合
selector_observe_dict:Dict[str,str]
candidate ids
可选 MOVE_BACK
```

若 V4/U1/M1 均 log-only，selector 看到的是原始 observe_dict，而不是这些模块构造的增强文本。

### 9.2 Selector 三段输出

1. `move_to_next_vp()`：

```python
predictions: List[str]
thoughts: List[str]
break_flag: bool
navigator_prompt: str
```

2. `thought_fusion(predictions, thoughts)`：

```python
fused_pred_thought: Dict[str, str]
# candidate_id/STOP/MOVE_BACK -> fused thought
```

3. `test_decisions(...)`：

```python
next_vp: str       # candidate id | "STOP" | "MOVE_BACK"
thought: str
error_number: int
```

### 9.3 Selector 后置消费者

| 顺序 | 模块 | 输入 | 输出/效果 |
|---:|---|---|---|
| 1 | legality checks | `next_vp`, candidate ids | 非法候选进入 fallback |
| 2 | candidate prior | 移动 `next_vp` + scores | 可能替换为 prior top |
| 3 | selector STOP verification | STOP + V2/depth/U2/L4 | allow 或转回移动 |
| 4 | fallback ranker | observe_dict + V1 +目标词 | `selected_candidate`, ranked list |
| 5 | backtrack apply | MOVE_BACK + last move | reverse `action_args` |

这些覆盖没有统一 DecisionRecord；目前散布在 selector、audit 和 action 事件中。

## 11. RouteState v1：输入映射、输出和真实消费者

### 11.1 构造位置

每步调用两次：

- `route_state(stage="pre_action")`：当前写在 `should_stop()` 之前；
- `route_state(stage="post_action")`：envs.step 后，带最终候选和动作摘要。

`pre_action` 这个名字容易误解：它不是“完整决策输入快照”，因为 STOP proposal、selector 输出、candidate override 尚未全部产生。

### 11.2 字段由谁提供

| RouteState 区域 | 上游生产者 | 数据格式 | 当前下游 |
|---|---|---|---|
| `plan` | instruction/actions/landmarks + L0 | strings + anchors dict/list | trace only |
| `progress` | L1 dict + phase dict + decision flag | structured dict | trace only |
| `spatial_graph` | M1 dict + candidate ids | structured dict | trace only |
| `landmark_memory` | M2 summary | structured dict | trace only |
| `loop_status` | M1 dict | structured dict | trace only |
| `budget` | step/step limit | ints/bools | trace only |
| `failure_status` | FailureDiagnostic dict | filtered dict | trace only |
| `stop_evidence` | L4 dict + final stop fields | filtered dict | trace only |
| `action` | selected candidate + action result | filtered dict | trace only |
| `provenance` | builder | source/confidence/abstain/effect | trace only |

### 11.3 顶层输出

```json
{
  "schema_version": "route_state.v1",
  "episode_id": "244",
  "step_id": 6,
  "stage": "pre_action|post_action",
  "plan": {},
  "progress": {},
  "spatial_graph": {},
  "landmark_memory": {},
  "loop_status": {},
  "budget": {},
  "failure_status": {},
  "stop_evidence": {},
  "action": {},
  "provenance": {}
}
```

真实消费者只有：

```text
write_navigation_record("route_state", state=...)
harness_logger.log_event("route_state", {"state": ...})
offline audit/replay scripts
```

**当前 selector、V2、candidate prior 和 env action builder 都不读取 RouteState。**

### 11.4 progress 字段的语义陷阱

当 L1 log-only 时：

- `progress.source = "llm_completion_estimation"`；
- 但 `progress.current_index/total/locator` 仍复制 L1 的结构化结果；
- RouteState 没有保存完整 LLM estimation 的结构化解析结果。

因此 `source` 表示“在线进度决策来源”，而 `current_index` 实际来自 shadow L1。离线分析不能把两者当成同一来源。这是 RouteState v2 需要拆成 authoritative/shadow progress 的原因。

### 11.5 禁止字段

RouteState 递归删除：

```text
latest_goal_dist
distance_to_goal
distance_gain_selected
recent_distance_gains
success
oracle_success
```

它们可以出现在独立 audit/episode_end 事件中，但不能通过 RouteState 回到在线链。

## 12. Failure、fallback 与 recovery 的流向

| 模块 | 输入 | 输出格式 | 消费者 | 当前动作影响 |
|---|---|---|---|---:|
| FailureDiagnostic | selector empty、STOP rejected、loop、candidate missing 等事件 | `{trigger_type,failure_type,confidence,reasons,evidence}` | RouteState、U3、trace | 否 |
| VisualEvidenceFallbackRanker | observe_dict、V1、instruction/actions/landmarks | `{selected_candidate, ranked_candidates, scores, diagnostics}` | selector 失败或 STOP 拒绝路径 | 是 |
| RecoveryPolicy | failure + fallback +候选 +预算 | `{applied,selected_candidate,reason,budget_before/after}` | 动作覆盖接口 | 当前否，U3 log-only |
| BacktrackPolicy | ego stall/dead-end + last move +预算 | availability/apply dict | selector 和 env action builder | 是 |

注意：fallback 是当前真实决策模块；RecoveryPolicy 是 U3 shadow；二者不是同一个组件。

## 16. 当前最关键的断点

1. RouteState 聚合了状态，但所有在线模块并不读取它。
2. 在线进度是 LLM string；L1 dict 只是 shadow，且两者没有统一结构化 provider。
3. V1 输出被多个决策模块消费，却没有进入 RouteState 的候选证据区。
4. STOP 在多个分支改写 `stop_flag`，没有唯一 StopDecision/DecisionRecord。
5. CandidateState 有 score 字段，但 selector 主要消费 observe_dict；分数在 selector 后才覆盖结果。
6. `pre_action` RouteState 写在 STOP/selector 之前，不是完整决策输入闭包。
7. M2 的 fused position 是方向级 waypoint 近似，不是对象实例位置。
8. `AgentState` 只是未接线 dataclass，不能作为当前架构描述依据。
9. GeometryQuery 与 M1/M2 的世界坐标约定仍需保持隔离，前者当前 log-only。
10. action output summary 混有在线可观测字段和 oracle audit 字段，必须继续在边界处分流。

## 17. 当前链与目标链的边界

当前事实：

```text
多个模块各自计算
  -> 局部变量互相传递
  -> RouteState 在旁路聚合并记录
```

目标设计：

```text
ObservationFrame
  -> 单一 StateReducer
  -> 权威 RouteState
  -> DecisionContext
  -> 单一 StopCoordinator / ActionCommand
```

因此，本文可用于定位“当前谁把什么给了谁”；不能把它当成新 pipeline 已经实施的证明。
