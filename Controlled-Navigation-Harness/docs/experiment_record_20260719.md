## 二、否定结果一：深度否决是死路

**提交停止时刻的前向深度对成败 AUROC = 0.531**（成功中位 2.10m / 失败 2.37m，分布重合，
n=65：成功 15 / 失败 50）。

阈值扫描（deny stop when depth > T）：

| T | 拦掉成功 | 拦掉失败 | 净 SR |
|---|---|---|---|
| 2.0 | 8 | 31 | −8 |
| 2.5 | 7 | 22 | −7 |
| **3.0（现行）** | **5** | **16** | **−5** |
| 4.0 | 3 | 13 | −3 |
| 8.0 | 0 | 2 | 0 |

**没有任何一个操作点是净正的。** ep100 的 +4 SR 不是过滤生效，是轨迹扰动（path_length +0.73）
碰巧撞上目标 —— 与 p=0.388 完全一致。

口径：扫描假设被拦下的集不会在后续步骤转成成功，是悲观上界；但 AUROC≈0.5 独立于该假设。

这证实了 20260718 §一bis C 的推断并把它量化：veto 读的是**前方最近表面距离**，与目标位置无关，
因此不携带"该不该停"的信息。

### 2.1 有一条停止路径绕过深度否决 —— 但不能堵

`base_il_trainer_llm.py:3218`：

```python
if old_stop_flag and visual_target_verifier_allows_stop(selector_verifier_results):
    stop_flag = True        # ← 无 depth 合取项
```

深度只通过 `depth_confirm` 喂进 `stop_evidence_verifier.verify()`，而该结果仅被 rescue/override
分支（:3232 的 `u2_rescue_allowed`）消费。主路径从不咨询深度。

实测 **21/65 集在四个门（completion/proactive/proactive_commit/selector）全判 vetoed 时仍然停止**，
其中成功 5 / 失败 16（失败者中位距目标 9.53m）。

**结论：不要堵。** 堵上会杀死 5 个成功 = 全部 20 个成功的 25%，而被拦下的 16 集中位已在 9.5m 外，
转成成功概率很低。这个漏洞是意外承重的 —— 它在抵消 veto 的误杀。这同时是 §一bis D 预注册误杀
风险的第一份实测：**误杀率 5/21 = 24%**，红线（=0）被突破。

## 三、否定结果二：回溯空转，且冒烟脚本会报假 FAIL

ep100 实测：`backtrack_offer` 724 次、其中 offered=True **156** 次、`backtrack_apply` 仅 **3** 次
（ep715 / 171 / 765）。接受率 **1.9%**，且这 3 集都不在涨跌名单 → **对 SR 的贡献为 0**。

机制是通的（3 次 apply 均带完整 `action_args`），问题在**选择层几乎从不采纳 MOVE_BACK**。

⚠ **`verify_smoke.py --mode backtrack` 会报假 FAIL**：ep1 冒烟里 2 次 offer、0 次 apply，脚本判

INCONCLUSIVE。脚本的判据需要加最小 offer 样本量。

## 四、否定结果三：选择器不是坏，是弱；语义贡献≈1 点

### 4.1 离线方法（可复用，不需要重跑）

- **目标位置离线可得**：`data/datasets/R2R_VLNCE_v1-2_preprocessed/val_unseen/OpenNav_R2R-CE_100_bertidx.json.gz`
  含全部 100 集的 `goals[0].position` 与 `reference_path`。
- **候选世界坐标可精确重建**：`step_start` 提供每步 positions/headings，`waypoint_candidates` 提供
  每候选 angle_rad/distance。角度约定 **θ = −heading − angle_rad**，
  `x += d·sin(θ)`，`z −= d·cos(θ)`。
- **约定是标定出来的不是猜的**：用"预测选中候选的位置 vs 下一步实际位置"检验四种候选约定，
  误差中位分别 1.821 / 1.670 / 1.338 / **0.000** m。重建是精确的。
- 欧氏 vs 测地：相关 0.854、中位低估 0.81m。regret 数值是近似，命中率是排序统计受影响小。

### 4.2 结果（n=656 决策点，候选数中位 4）

| 策略 | 命中最优候选 | regret 均值 |
|---|---|---|
| **LLM 选择器（现状）** | **36.7%** | 0.99m |
| 启发式：步长最长 | 35.7% | 1.19m |
| 启发式：转向角最小 | 32.9% | 1.16m |
| 启发式：raw_rank 最小 | 30.0% | 1.23m |
| 随机 | 27.7% | 1.17m |
| 启发式：步长最短 | 17.2% | 1.33m |

**9B 比随机强 9.0 点，但比"永远选最长的一步"这个平凡几何启发式只强 1.0 点。**
语义 grounding 的增量贡献约等于零。

无系统性方向偏差：选中 |转向角| 中位 81.0° = 最优 81.0°；步长中位 1.50m = 最优 1.50m。
错误是分散的，不存在廉价的偏置修正。

成功集命中 48.4% / regret 中位 0.06m，失败集 34.0% / 0.66m —— 选择质量确实关联成败。

## 五、验证：beeline regret 是不是正确的优化目标

§四的全部结论建立在"最靠近目标的候选 = 最优"这一假设上。VLN 要求沿指令路径走，该假设需要检验。

### 5.1 参考路径不是更好的目标

把评判目标从"直线距目标最近"换成"距 `reference_path` 最近"重算命中率：

| 策略 | 目标直线 | 参考路径 |
|---|---|---|
| LLM 选择器 | 36.7%（比随机 **+9.0**） | 29.6%（比随机 **+6.6**） |
| 步长最长 | 35.7% | 26.4% |
| 随机 | 27.7% | 23.0% |

选择器对**目标直线**的贴合反而强于对参考路径。→ beeline 口径没有 mis-specified。

### 5.2 regret 能预测成败，且不是长度或难度的伪影

| 量 | 成功中位 | 失败中位 | AUROC |
|---|---|---|---|
| 全集平均 regret | 0.35 | 1.01 | **0.773** |
| 全集累计 regret | 2.28 | 5.16 | 0.674 |
| **前 3 步平均 regret** | 0.43 | 0.90 | **0.662** |
| 对照：集长（步数） | 5.50 | 6.00 | 0.523 |

- **前 3 步**版本因果上早于结局，排除"成功集末段天然低 regret"的混淆。
- 集长 AUROC 0.523 → regret 不是长度伪影。
- 控制初始难度（初始距目标 AUROC 0.745）后分层：近半 **0.777**（成功 17/失败 33）、
  远半 0.674（成功 3/失败 47，样本太少噪声大）。→ regret 不是难度的代理变量。

**结论：Arm C（选择层重排）方向成立，beeline regret 是有效的优化目标。**

## 六、ENDGAME_TILT_VIEW：预算错配修复

### 6.1 20260719 ep100 暴露的问题

俯视触发 298 次 / 100 集，但 **`MAX_PER_EPISODE=3` 在 98/100 集被用满且全烧在第 1–3 步**
（最后触发步中位 3.0，集末步中位 7.0），**只覆盖到 21/100 集的末步、32%（21/65）的提交停止时刻**。
名为 ENDGAME 实际采的是开局。

**根因：`final_clause` 是坏信号。** step=1 时 `action_count` 中位 5、`completed_action_count`
中位 4 —— LLM 在还没移动前就自报"5 个动作完成了 4 个"，**81/100 集在第 1 步就满足 final_clause**。
它 oracle-free 但不携带终局信息。

### 6.2 修复与离线验算

`ARM_ON_FINAL_CLAUSE` 默认关 + `MIN_STEP_GAP=3` 摊开集内采样 + `MAX_PER_EPISODE` 3→4 +
新增 `ALWAYS_ON_STOP`（在 `action_pre_step` 收口点无条件补一发终局样本，该点 stop 已定且
`envs.step()` 未执行，是唯一能识别终末位姿的地方）。

| | 旧 | 新 |
|---|---|---|
| 总触发 | 296 | **257** |
| 覆盖提交-stop 时刻 | 21/65 (32%) | **65/65 (100%)** |

成本反而降 13%。ep1 冒烟验证：触发步 2/5/8（间隔严格 3）、终局样本命中提交步 8。

⚠ 期间一次模拟错误已修正：初版按 `step_length` 比例开窗，但 `step_length` 是预算上限（10/12），
而 59/100 集提前停止（末步中位 7），该方案会漏掉近半数集。改用只依赖运行时可见量的
`cap + gap` 策略后重算才得到上表。

**注意 committed_stop 只覆盖 65/100 集** —— 另 35 集撞步数上限、从不提交停止。下轮拿到的是
65 个标定样本，不是 100 个。

### 6.3 俯视本身的信号强度被高估了（自我更正）

−30° 俯角 + 1.25m 相机高 → **打到空地板就是 2.50m**（`h/sin|pitch|`）。ep100 俯视深度中位 **2.20m**，
即多数读数是地板不是物体：

| 区间 | 占比 |
|---|---|
| 落在空地板带 2.50±0.25m | 34% |
| < 2.25m（比地板近＝真有物体） | 54% |
| > 2.75m | 11% |

拆解此前引用的"46%（138/298）眼平 >3m 而俯视 <3m"：其中 **55% 落在地板带（伪信号）**、
仅 27% 是真近物。**真实信号约占末段时刻 12%，不是 46%。**

→ **撤回"把俯视接进 veto、用 min(tilt, eye)"的提议。** 反例见 ep1 冒烟：step8 四门全判 vetoed
（眼平 4.35m），俯视读 1.90m，但真实距目标 **4.70m**，失败。按 min 口径会放行一个该拦的假停。

已把 `floor_intersect_m` 写进 `endgame_tilt_view` 事件（从实时传感器高度计算），防止后续再把地板
当目标。

## 七、Arm C 落地：可观测特征候选先验（当日实现）

§四给出瓶颈、§五验证目标口径后，当日**实现了选择层的第一个改动**。此前所有工作都是测量，
选择层代码零改动。

### 7.1 探路：可观测特征的上界在哪

§四留下的开放问题是"36.7%（LLM）到 100% 之间，可观测特征原则上够得着多少"。
用 trace 里**已经算好但从未被消费**的信号做离线拟合回答：

- `grounder_diagnostic` 每步已产出每候选的 `grounding_score` + 五维分解
  （object/room/direction/relation/distance）；
- `visual_evidence` 的 `raw_response` 含每候选的 `final_target_visible` /
  `matched_instruction_terms` / `missing_instruction_terms` / `visible_landmarks`；
- 但 `waypoint_candidates` 记录里 `geometry_score` / `grounding_score` / `novelty_score` /
  `final_prompt_rank` **全为 null** —— 脚手架算了不写、写了不用。

拟合设置：656 决策组 / 2625 候选行，标签 = 该候选是否欧氏最靠近目标（离线 oracle），
逻辑回归（numpy 手写，环境无 sklearn），**GroupKFold-5 按 episode 分组**防同集泄漏。

| 策略 | 折外命中 |
|---|---|
| 随机 | 27.1% |
| `grounding_score` 单独 | 32.9% |
| 步长最长（最好单一启发式） | 35.7% |
| **仅几何 4 维**（dist/ang/rank/ncand） | **36.7%** |
| **LLM 选择器（9B）** | **36.7%** |
| 仅语义 10 维 | 38.7% |
| 几何 4 + `grounding_score` | 38.3% |
| 全部 14 维 | 41.5% |
| **几何 4 + `nmatch`（5 维，最终形态）** | **41.8%** |

线性+二次+交互项折外反而降到 40.2%（过拟合）→ **线性是对的形态**。
5 维模型换 5 个 CV 种子重测：41.8 / 43.4 / 43.8 / 46.5 / 45.0 → **44.1% ± 1.6**。

### 7.2 两个结构性发现

**A. `grounding_score` 的四个维度是死的。** 最终权重里
`s_room` / `s_dir` / `s_rel` / `s_dst` **精确为 0.000**，`s_obj` 仅 +0.018。
唯一有用的语义特征是 `nmatch`（视觉里匹配到几个指令词，一个整数计数），权重 +0.2999，
与 `dist` 的 +0.3030 并列第一。**精心设计的五维语义分解不如一个计数器。**

**B. LLM 的选择不携带几何之外的可利用信息。**
把"LLM 是否选了该候选"作为第 6 维特征加入，折外命中**从 41.5% 降到 40.4%**。

但两者并非同一回事——分歧分析。

> ⚠ **本小节原始数字于 20260720 作废并重算，见 §十一。**原表基于误差 1.5 m 的候选
> 坐标重建。精确重建（0.000 m）下为：一致 268 组命中 141；分歧 386 组中
> LLM 对 99 / 先验对 155 / 都错 132；**完美仲裁上界 60.4%**，全听先验 45.3%。
> 结论方向不变（仲裁奖金大、无可观测信号可分辨），量级更大。

即：语义确实在近百组里赢了几何，但**没有任何可观测信号能事先分辨该信谁**。
→ 这是训练线（打分头）的确切靶点。§十一 已直接尝试并证伪了"手工特征仲裁器"。

混合实验佐证同一结论：softmax 概率按 20/30/50/70/80% 与 LLM 选择线性混合，
最好 38.1%，全部低于先验单独的 41.5%；"LLM 选择在先验里排名 >2 时改投先验首选"得 39.2%。
**没有任何混合形态优于先验单独。**

### 7.3 实现

- 新增 `vlnce_baselines/common/opennav_ext/candidate_prior.py` +
  `candidate_prior_weights.json`（含 provenance 字段）。
- 新增配置 `OPENNAV_HARNESS.CANDIDATE_PRIOR`（`ENABLED` / `LOG_ONLY`），
  yaml 置 `ENABLED: True` + `LOG_ONLY: True`。
- 挂载点在 `visual_evidence` 之后、`multimodal_selector_context` 之前（需要 `nmatch`，
  且必须早于选择器上下文构建）。位于 `harness_enabled` 守卫内，`harness_logger` 保证非 None。
- 把分数写进此前 inert 的 `geometry_score` / `final_prompt_rank` 字段，并发
  `candidate_prior` 事件。
- `LOG_ONLY: False` 时按先验重排候选顺序交给选择器（**仅重排，候选集不变，选择器保留最终权**）。
- 运行时实现用离线数据回放校验：**45.3%**（含训练集，对应折外 44.1%），与拟合脚本一致。

### 7.4 两条未验证的风险（禁止直接翻 decision-active）

1. **重排路径未审计**：`LOG_ONLY: False` 会 in-place `sort` candidates，而下游是否严格按
   `candidate_id` 取用、重排会否影响 `images_dict` 或方向映射，**没查**。这与当日早些时候
   `generate_input` 的 `tilt_` 前缀坑是同一类失败面（位置编号 vs 语义 ID）。
2. **44.1% 不是 SR**：它是"命中最靠近目标的候选"。目标口径已由 §五验证，但命中率→SR 的
   传导只能靠跑。且权重拟合于 LLM 主导的轨迹分布，先验一旦接管则状态分布改变
   （协变量偏移），折外数字是旧策略下的估计而非保证。

→ **先 LOG_ONLY 跑一轮**，核对 `candidate_prior` 事件的运行时打分与离线复算逐位一致，
再谈翻开关。别一次翻两个未验证的东西。

指令词匹配计数。再往上到 57.5% 需要仲裁语义与几何的分歧，那是训练线的活。

## 十一、精确真值重建、SR 失败归因、仲裁器证伪（20260720）

### 11.1 候选坐标重建：复核确认原公式一直正确

本节初稿曾断言"原重建有 1.5 m 误差、导致 §七 数字失真"。**该断言错误，已撤回。**
1.5 m 是本次分析中我自己写错的变体（`z + d·cos` 而非 `z - d·cos`），当场即修。
参数扫描（heading/angle 符号 × 相位偏移 × sin-cos 互换，共 32 组合，判据为
"下一步实际记录位置应等于本步所选候选的重建位置"）得到的最优形式

```
theta = -heading - angle_rad - pi/2 ;  x + d*cos(theta),  z + d*sin(theta)
```

与既有记录的 `theta = -heading - angle_rad ; x + d*sin(theta), z - d*cos(theta)`
**代数恒等**（数值验证残差 ~1e-16）。**中位误差 0.000 m（n=618）**，次优 1.338 m。

**教训：先复核既有记录，再宣布它错。**我在三个文件里写下了"原数字基于坏几何"
然后才去核对，纯属自造事故。

## 十二、Arm C decision-active 结算：命中率提升未转化为 SR（20260720）

§11.5 第 1 条的预注册实验已执行完毕。**结论：Arm C 对 SR 的效应不可与零区分。**

### 12.1 运行事故：宿主掉电，非程序崩溃

`20260720_004318` 于 00:43:18 启动，09:42 中断在第 83 集，**83/100（完成 82 集指标）**。

排查结论是**宿主机层面的硬掉电**，与本项目代码无关：

- 无 traceback、无异常；
- 训练进程与 lmdeploy 后端**同一时刻**停止，后端日志末行是
  `Setting pad_token_id...` 且**无配对的 `200 OK`** —— 请求写到一半被切断；
- `journalctl -b -1` 末行停在 09:37:10（DHCP 续租），**关机序列 0 条**
  （无 `Reached target Shutdown`），37 分钟后 10:19:16 重新开机；
- 排除 OOM（内核无 `oom-kill`）、排除 SSH SIGHUP（09:31–09:36 关闭的是
  session 94/95/96，CPU 仅 9.4 s；评测所在 session 77 从未关闭）、排除 NVRM Xid。

宿主为 KVM 虚机（`ens3` / `192.168.122.7`），掉线前刚拿到新 DHCP lease。

### 12.2 数据可恢复性：checkpoint 被 rename-without-fsync 清零

`checkpoint_stats_episodes.json` 落盘为 **0 字节**。

初判"该文件只在跑完时写一次"——**错误，已更正**。它在
`base_il_trainer_llm.py:4087` **每集**写一次，且已用 `os.replace` 原子替换。

真实机制是 **`os.replace` 之前缺 `fsync`**：`os.replace` 只保证对*进程*崩溃原子，
不保证对*掉电*原子。rename 元数据落盘时数据块仍在页缓存，重启后得到长度为 0 的新
inode —— 经典的 rename-without-fsync 数据丢失。

**已修**（同文件同位置）：`flush()` + `os.fsync(fileno())` 置于 `with` 块内、
`os.replace` 之前；`os.replace` 之后再 `fsync` 目录 fd 以固化 rename 本身
（此步丢失只会退回上一份完整 checkpoint，是安全的失败模式）。

**这次靠 `logs/navigation_records/*.jsonl` 救回**——它逐集追加写，含完整官方指标
（`success` / `oracle_success` / `spl` / `ndtw` / `path_length`）。
**教训：逐集追加的记录比"原子替换的汇总文件"更耐掉电。**

### 12.5 结论：因果链断在第二环

预测与结果对照（预测在跑之前给出，此处如实结算）：

> 预测："六成概率上涨，最可能 +0 至 +4 点，三成概率持平或下跌。"
> 实测：+1.2 点、p=1.000 —— **落在区间最下沿，且与零不可区分。押注方向不算错，
> 但把握程度高估了。**

```
每步选得更准  →  轨迹更靠近目标  →  更多集进入 3m  →  SR↑
  ✅ 36.7→43.8%      ❌ 断在这里         —            —
```

离线命中率那 7 个点是真的（折外、GroupKFold-5），**但没有转化成轨迹质量**：
SPL 完全持平（0.143 vs 0.143）、nDTW 略降（0.415 vs 0.422）、OSR 仅 +1.2。
每步选中"欧氏最近候选"的频率提高了，智能体却没有更快接近目标。

两个已知的候选解释（本轮数据不足以判定，勿当结论）：
1. **训练标签用欧氏距离，不考虑墙**（欧氏 vs 测地 r=0.854）——
   先验可能偏爱"直线近但需绕行"的候选；
2. **单步贪心不等于路径最优** —— 逐步最近不构成最短路。

**对训练线的直接含义（本轮最有价值的产出）：**
