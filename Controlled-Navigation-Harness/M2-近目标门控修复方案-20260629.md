# M2：近目标门控修复方案

> **阶段定位**：M1（arrival_gate log-only）已落地。max_config 第一次评测（SR=21%）揭示新的主导失败模式为「stop-blocked」——STOP 信号存在但被门控拒绝。M2 的目标是在不引入新感知能力的前提下，修复门控的两类过度拒绝，将 SR 提升至 22-24%。

---

## 1. 当前状态（截至 20260629）

| 阶段 | 状态 | 关键结果 |
|---|---|---|
| A0 baseline | ✅ 完成 | SR=16%, OSR=25%, OSR→SR=64%, walk-through=77.8% |
| M1 arrival_gate (log-only) | ✅ 完成 | 817次检查，20/100 episodes 触发；recover 阶段不可见 |
| max_config 首次评测 | ✅ 完成 | SR=21% (+5pp), OSR→SR=80.8%; stop-blocked 成新主因 |
| M2 门控修复（本方案） | 🔄 进行中 | trajectory_bypass 已实现，待下次跑验证 |

---

## 2. 问题分析

### 2.1 失败分类迁移

```
A0 (9集 OSR=1/SR=0):       max_config (5集 OSR=1/SR=0):
  walk-through: 7/9 (77.8%)   stop-blocked: 3/5 (60%)
  off-goal-stop: 2/9          walk-through: 2/5 (40%)
```

max_config 激活了 U2 stop verifier，成功减少了 walk-through（从 7 降到 2），但引入了新的 stop-blocked 问题（3集）。净结果：OSR-SR gap 从 9 降到 5。

### 2.2 两类根因

**RC1 — trajectory_incomplete 硬拒绝（可修复）**

当 `all_actions_completed=False` 时，stop verifier 向 `reject_reasons` 追加 `trajectory_incomplete`，无论距离多近都拒绝 STOP。

影响集：ep11（0.40m）、ep1084（1.32m）

逻辑上：agent 已在成功半径内，「指令动作序列未完全执行」不应优先于物理到达事实。

**RC2 — final_target_not_visible 过严（待深入）**

completion_gate 97.9%（801/817）的检查以 `final_target_not_visible` 拒绝。agent 在 2-3m 时目标可能已移出视野（靠得太近），但视觉验证器报告 not_visible。

影响集：ep824（2.58m）、ep1106（2.68m）；ep1084 也包含此原因

## 3. M2 修复策略

### 3.1 M2a — trajectory_bypass（已实现 ✅）

**机制**：当 `latest_goal_dist < TRAJECTORY_BYPASS_DIST`（当前设置 3.5m）时，将 `trajectory_support` 从 "no" 降级为 "unknown"，不再追加 `trajectory_incomplete` 到 `reject_reasons`。

**安全性**：bypass 后 STOP 仍需通过 `intrinsic_support="yes"` 和 `visual_allow=True`（目标可见且 VLM 整体判定为 allow），并非无条件放行。

**实现**：
- `stop_evidence_verifier.py`: 新增 `trajectory_bypass_dist` 参数和 `latest_goal_dist` 输入
- `base_il_trainer_llm.py`: 传入 `latest_goal_dist` kwarg
- `run_OpenNav.yaml`: `TRAJECTORY_BYPASS_DIST: 3.5`

**预期**：ep11 和 ep1084 在近目标处的 STOP 不再被 trajectory 拦截，视觉证据通过则成功。预计 +1~2pp SR。

### 3.2 M2b — final_target_not_visible 距离衰减（待实现）

**问题**：agent 靠近目标 2-3m 时目标实体可能占满视野、或被部分遮挡，VLM 的 `final_target_visible` 判断变得不稳定。

**候选方案**：

| 方案 | 做法 | 风险 |
|---|---|---|
| 距离衰减：在 d<threshold 时放宽 visibility 要求 | 加 `visibility_bypass_dist` 参数，类似 trajectory_bypass | 增加误停风险（T2 off-goal-stop）|
| arrival_evidence 替代：有 `arrival_evidence=True` 时跳过 visibility check | 若 arrival 信号存在即认为到达 | arrival 信号本身可靠性待评估 |
| 仅记录不修改（log-only 先观测）| 先跑看 `final_target_visible` 在不同距离的分布 | — |

**当前策略**：先跑 M2a 的新配置，收集 `final_target_visible` 在近目标步骤的分布数据，再决定 M2b 方案。

## 4. 实验矩阵

### 4.1 M2a 验证跑（立即）

**配置差异**（vs max_config）：
- `ARRIVAL_GATE.ALLOWED_PHASES` 新增 `recover`
- `STOP_EVIDENCE_VERIFIER.TRAJECTORY_BYPASS_DIST: 3.5`

**观测指标**：
- SR、OSR、OSR→SR 转化率（对比 max_config 21%/26%/80.8%）
- `trajectory_dist_bypassed` 事件数（应在 ep11、ep1084 等近目标集中出现）
- arrival_gate 在 recover 阶段的新触发数
- 是否有新增的误停（T2 off-goal-stop 数量）
- OSR=1/SR=0 集的变化（ep11、ep1084 是否转为成功）

**预期结果**：
- 乐观：ep11 + ep1084 均转化 → SR=23%
- 保守：仅 1 集转化 → SR=22%
- 风险：bypass 导致 1-2 集新增误停 → SR 持平或 +1pp

### 4.2 M2b 数据收集（M2a 之后）

从 M2a 的 harness traces 中提取近目标步骤（d<4m）的 `stop_current_view_evidence` 数据，统计：
- `final_target_visible` 分布（vs 距离区间）
- `arrival_evidence` 与 `final_target_visible` 的一致性

## 7. 关键约束

1. **不增加步数限制以外的新感知**：trajectory_bypass 和 visibility 衰减都是门控参数调整，不引入额外 VLM 调用
2. **SPL 不退化**：bypass 后误停会降 SPL，需监控 T2 off-goal-stop 数量
3. **arrival_gate 仍为 log-only**：M2 阶段不赋予 arrival_gate decision-effect，避免引入新的过触发误停
4. **TRAJECTORY_BYPASS_DIST 设置原则**：应 > 成功半径（3m）给余量，但不超过 4m（避免远距提前放弃轨迹检查）；当前 3.5m 是合理的初始值
