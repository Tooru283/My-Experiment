# 明日组会报告风格复盘与困惑点

## 一、上一份报告的写法

复盘对象是 `experiment_report_20260730_group_meeting.md`《换更大的 Qwen 模型，能不能救选路？》。它的核心不是罗列项目所有进展，而是围绕一个单一问题，把一次实验讲成一个闭环：

```text
具体问题
  -> 两种相反解释
  -> 最小区分实验
  -> 对照结果
  -> 逐条解释
  -> 限制/作废数据
  -> 这次实验砍掉了哪条路线
  -> 下一步做什么
```

### 1. 先给一个可以直接复述的裁决

原报告开头只有一句核心判断：

> 试了三个大小不同的 Qwen，成绩都卡在 39–43% 之间，一条平线。及格线是 50%，一个都没够着。

它马上回答了三个问题：试了什么、结果在哪里、是否过闸门。听众不需要先读背景表格。

### 2. 先讲系统卡点，再讲实验

原报告先用很口语的方式解释“每一步要从几个方向选一个”，再把随机基线、当前系统和最长步基线放在一起。这样后面的 41%–43% 有明确的参照物。

### 3. 用“两个可能”说明为什么要做这个实验

原报告没有直接说“我们换了三个模型”，而是先提出：

- 可能是 9B 太小；
- 可能是这个输入和任务本身就问不出答案。

因此实验设计看起来是为了解决一个明确的分岔，而不是为了“再跑几组数”。

### 4. 方法只保留能帮助理解结果的部分

方法段只解释同一批点、同一 prompt、四种输入和错配图对照，没有展开代码目录、配置注册、日志架构等工程细节。

### 5. 结果表后面紧跟“看出来四件事”

表格不是结尾。原报告逐条解释：换大模型没用、图像比文字强但不够、文字描述贡献小、错配图证明模型确实在看图。每条都用“数字 → 含义”的顺序。

### 6. 主动写数据问题和容易被误解之处

原报告专门写了 API 并发导致的作废轮次，也专门解释了为什么不能说“大模型不如最长步”。这使负结果更可信，也提前回答了听众最可能的反问。

### 7. 最后写“这个实验值多少”和下一步

原报告没有把负结果写成“什么都没得到”，而是明确说明用一小时关闭了一条本来要花三周的路线；最后给出换骨干、训练、换数据集、收口写论文的分叉和复现命令。

## 二、我刚写的 20260826 报告与上一份报告的差异

### 差异 1：报告对象变了

上一份是**单实验报告**；当前稿是**跨多个实验和代码模块的项目状态报告**。因此当前稿更像项目总控，不像上一份的“一个问题、一条证据链”。

### 差异 2：当前稿过于正式、偏管理文档

当前稿用了“当前工程状态”“R0/R1/R2/R3”“需要组会上明确的决策”等项目管理结构；上一份更多使用“我们的系统卡在哪”“怎么做的”“看出来四件事”“这个实验值多少”等口头化标题。

### 差异 3：当前稿结论太多，第一屏不够聚焦

当前稿的“先说结论”有 5 条，包含基线、瓶颈、换模型、ACN、C0/C2。上一份只有一个实验裁决。听众可能不知道明天最需要记住的是：

> 当前性能主矛盾是 OSR/走不到；ACN 仍未上线；下一步还没有新的在线 SR 结果。

### 差异 4：实验结果和工程状态混在同一层级

当前稿同时汇报：

- 官方 SR/OSR 基线；
- M1 决策点命中率；
- ACN 代码是否存在；
- C0/C2 是否排队。

上一份把“实验结果”和“下一步路线状态”分成结果、价值、下一步三个阶段。当前稿容易让听众把“代码已落地”误听成“实验已验证”。

### 差异 5：当前稿的表格更多，但缺少每张表的口头解释

上一份每张主要表后面都有一句“这张表说明什么”。当前稿的 ACN 模块表和运行时表更像资料卡，明天讲时需要补一句因果解释，否则数字会显得并列而没有重点。

### 差异 6：当前稿把不同统计单位放在同一叙事里

SR/OSR 是 100 集 episode 指标；39%–43% 是 M1 的决策点候选命中率；L1 的“不同进度值中位数 2”是离线队列状态指标。当前稿虽然分别提到了这些数字，但没有像上一份那样明确标注“100 集 / 决策点 / 离线重放”的单位。

### 差异 7：当前稿的下一步更像执行计划，缺少“为什么这一步能区分问题”

当前稿写了 C0=4、C2=15/17，但没有充分复述上一份报告中的“两个可能/分岔”。明天讲 C0/C2 时需要明确：

- C0 只检验早停门是否在过早截断轨迹；
- C2 只检验增加预算能否让“正在靠近但从未到过”的集继续走到目标；
- 两者不能混开，否则无法判断是停止问题还是预算问题。

### 差异 8：当前稿没有上一份报告那种“数据作废/易误解”段落

当前稿虽然写了基线目录名错误和 OSR 欧氏/测地口径错误，但没有单独用一个听众友好的小节说明“哪些数字不能这样解释”。这会让人把 SR20、挂牌 SR16、旧 OSR21 混在一起。

## 三、需要记录的困惑点 / 迷惑点

以下不是新的实验结论，而是明天汇报前必须澄清的表达问题。

### 困惑点 1：到底应该汇报 SR16 还是 SR20？

- 文档挂牌的 `clean_baseline_v1` 是 SR16 / OSR21；
- 2026-07-19 trace 的 `episode_end.metrics` 是 SR20 / OSR25；
- 当前分析和 ACN 离线重放使用的是后者。

**建议说法**：把 SR20/OSR25 称为“当前分析所用 trace 的官方指标”，把 SR16/OSR21 称为“历史挂牌基线”，不要把二者放进同一条性能曲线而不加说明。

### 困惑点 2：“主要瓶颈是走不到”与“下一步先做禁早停”是否矛盾？

不矛盾，但需要解释层次：

- 全局上，OSR 低说明走不到是主问题；
- C0/C2 是低成本的失败转移实验，先验证早停和预算是否把已有近目标集截断；
- 它们不是声称能单独解决全部 OSR 短板。

**建议说法**：C0/C2 是先做的便宜诊断和局部杠杆，不是新的总瓶颈判断。

### 困惑点 3：M1 的 39%–43% 与 OSR 25/100 是不是同一个指标？

不是：

- OSR25/100 是 episode 级官方导航指标；
- M1 的 39%–43% 是固定决策点上“是否选中局部最优候选”的命中率。

**建议说法**：每次报 M1 数字时都加“决策点命中率”，不能直接说“模型 OSR 是 43%”。

### 困惑点 4：ACN “代码已落地”是否等于“ACN 已验证”？

不是。代码接线和离线重放已经完成，但 L1 未通过预注册闸门，所有 ACN 模块仍为 `LOG_ONLY`，没有产生在线 SR/OSR 因果结果。

**建议说法**：ACN 已完成“工程落地 + 首轮离线审计”，尚未完成“决策生效实验”。

### 困惑点 5：P1 是已证伪路线，还是当前代码仍待补路线？

历史离线校准曾得到 AUROC 约 0.542，接近随机，因此“基于同分布 vote-dispersion 的 P1 触发”不应作为当前主线。但当前代码仍保留采样和 `vote_dispersion` 基础接口，不能把“接口存在”说成“P1 已经在线完成”。

**建议说法**：P1 的原始触发假设已经被离线结果否掉；代码中的采样接口是遗留基础设施，不代表在线方法成立。

### 困惑点 6：当前报告是否应该继续讲所有已关闭路线？

上一份报告只讲与本次实验直接相关的路线。当前稿列了深度 veto、回溯、候选先验、打分头、M1、换 backbone、P1 等多个负结果，容易把主线冲散。

**建议说法**：正文只保留三条最相关的关闭路线：换大模型、无状态单步选路、同分布重复采样；其余放附录或被问到时再讲。

### 困惑点 7：C0 当前值是 3 还是 0？

- `run_OpenNav.yaml` 覆盖后的实际运行值是 3；
- `vlnce_baselines/config/default.py` 的默认值是 0。

**建议说法**：汇报当前实验配置时说“实际加载的 yaml 值为 3”，不要只引用 Python 默认值。

### 困惑点 8：运行时数字能否直接外推到新实验？

8.68 小时、2531 次调用是已有 100 集 trace 的实测账本，不是 C0/C2 新实验的实际耗时。开启不同模块、步数变长或服务端负载变化都会改变耗时。

**建议说法**：把它称为“上一轮基线的运行时账本”，不要说“下一轮一定是 8.68 小时”。

### 困惑点 9：当前是否已经有“上次组会之后的性能提升”？

没有新的在线 SR/OSR A/B 结果。新增内容主要是：口径和基线审计、多模型上界结论、ACN 代码与离线重放、C0/C2 实验准备。

**建议说法**：明天明确说“这次没有新的 SR 提升数字，新增价值是把问题和下一轮实验边界钉清楚”。

### 困惑点 10：报告时间写 2026-08-26 是否需要说明“最近没有新组会稿”？

上一份正式组会稿是 2026-07-30；8 月 5 日以后主要是当前任务、实验日志和专项审计文档，不是完整 ep100 性能报告。

**建议说法**：开头说明“这是 7 月 30 日之后的阶段性进展汇报”，不要让听众以为 8 月份已经完成了新的全量实验。

## 四、风格修正建议

如果要把 20260826 主报告改得更像上一份，建议采用以下顺序：

1. 标题改成一个问题，例如“我们现在到底卡在走不到，还是停不住？”
2. “先说结论”只保留一个主裁决：**当前首要瓶颈是 OSR/走不到，但还没有新的在线性能提升。**
3. 用一个小表先解释 SR20、OSR25、转化率80%。
4. 提出两个分岔：继续修 STOP/预算，还是换候选/规划结构。
5. 只讲三组证据：基线审计、多模型上界、ACN 离线结果。
6. 增加一个“容易被误解的地方”小节，放入上面的困惑点 1–4。
7. 最后用“这个阶段值多少”说明：没有涨 SR，但关闭了换大模型路线，并把下一轮 C0/C2 变成可验证的单开关实验。
8. 附上实际可复现命令；如果当前没有新实验命令，就明确写“本次没有新增在线运行”。
