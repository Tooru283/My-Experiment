# 组会汇报： selector还是空间记忆与分层规划？


## 先说结论

**下一阶段给导航器持久的空间状态，把单层逐步航点选择改成“规划器决定子目标、执行器完成局部动作”，并逐步验证是否需要绕开传统 waypoint 动作空间。**

建议把未来工作分成三层：

| 层级             | 方向                                               | 成本 | 近期动作                                                   |
| ---------------- | -------------------------------------------------- | ---: | ---------------------------------------------------------- |
| **低成本** | 文献中已验证的进度清单、拓扑回环告警、空间记忆接入 |   低 | 先解决提前停下和行动步数不足，再分别测试进度更新与回环告警 |
| **中成本** | Anchor Chain + Spatial Memory + Planner/Executor   | 中高 | 先做离线 replay，再做 ep10 结构性闸门                      |
| **高风险** | waypoint-free / BEV / 原语动作空间                 |   高 | 先做最小可行动作空间 probe，不直接重写主线                 |

目前的验证是：

```text
如果先限制提前停下、再增加行动步数，只是把失败从“提前停下”转成“走到预算耗尽”
    -> 说明问题不是 STOP，而是缺少长期空间状态
    -> 进入空间记忆 + 分层规划

如果空间记忆仍不能抬高 OSR
    -> 当前 waypoint 候选本身限制了可达性
    -> 评估 waypoint-free / BEV / 原语动作空间
```


例如普通plan划分可能是：

1. 去客厅
2. 找沙发
3. 停下

Anchor Chain 会把它写成可检查的目标：

```
目标 1：进入客厅区域
目标 2：看到沙发或沙发附近的地标
目标 3：确认沙发是最后目标，并满足停止条件
```


## 一、当前 selector 路线已经无法提升

当前分析得到的事实是：

- 官方基线约为 SR20 / OSR25 / 转化率80%；
- M1 在固定决策点上的图像选路为 39%–43%，跨三个 Qwen 规模没有上升趋势；
- 文字描述相对纯几何输入只增加约 2–4 个点；
- 错配图对照低于随机，说明模型在看图，但没有形成稳定的方向判断；
- 候选里曾出现近目标点的比例明显高于实际走到过的比例，说明选路损失存在，但候选集本身也有上限；
- 候选先验、隐藏态读取和同分布重复采样都没有显示出可以直接转化为 SR 的信号。

这组证据并不等于“LLM 不能导航”，它更准确地说明：

> **在没有持久空间状态、没有子目标、每一步只从局部 waypoint 中单独做选择的架构里，继续换 selector 或换 backbone 的边际收益很小。**

所以未来方向要从“让这一步选得更准”转向“让下一步有更多状态可以依据”。

## 二、文献中的可用的结构

### 2.1 GTA：拓扑图、进度清单和一次调用更新状态

本地对 GTA（arXiv:2602.15400）的整理显示，它的可迁移部分不一定是完整 TSDF，而是三个结构性设计：

1. **拓扑节点和访问计数**：回到同一位置多次时，明确提醒模型更换分支；
2. **Blueprint / TODO 清单**：指令被拆成有序子目标，进度不依赖 LLM 每步重新猜；
3. **同一次调用同时输出动作和更新后的清单**：动作和进度由同一决策产生，省掉独立的 completion estimation 调用。

这三项与我们当前的空间记忆、拓扑回环诊断、动作和进度联合更新工作直接对应：

| GTA 机制                     | 我们的对应物                                    | 当前状态             |
| ---------------------------- | ----------------------------------------------- | -------------------- |
| `G_topo` 回环告警          | 拓扑回环诊断（`VisualGraphMemoryDiagnostic`） | 代码已落地，尚未测试 |
| Blueprint / progress pointer | L0 Anchor Chain + L1 Progress Locator           | 代码已落地，尚未测试 |
| 动作 + 新 TODO 一次输出      | 动作和进度一次输出                              | 尚未完成             |

**需要保留的限制**：GTA 的 TSDF、BEV 和反事实规划不能因为“同一篇论文有效”就直接移植。我们当前的深度日志存在尺度陷阱，且没有完整 TSDF 世界表示。近期只抄结构，不抄完整感知栈。

### 2.2 空间记忆是决策状态

最新阅读论文中的 zero-shot 方法普遍拥有：

- 持久的空间节点和边；
- 地标的类别、位置、可见性和到达状态；
- planner/executor 分层；
- 阶段级或子目标级的历史，而不是只保留最近一步文本。

这与我们现在的差距不是提示语设计问题，而是决策状态的类型不同：

| 当前 Open-Nav                    | 文献中的强结构                               |
| -------------------------------- | -------------------------------------------- |
| 每步从候选 waypoint 中直接选一个 | planner 先选下一个子目标，再由 executor 执行 |
| 历史主要是压缩文本               | 持久空间图、已访问边、未探索分支             |
| completion estimation 每步重新猜 | 单调进度指针或锚点验证                       |
| 地标主要是当前帧标签             | 跨步融合的地标池                             |

**这条路线的核心假设**：模型不是完全没有能力，而是当前架构没有给它足够的跨步状态。M1 只测了“无记忆单步选择”的上界，不能直接否定“有空间记忆的规划”。

### 2.3 重新考虑 waypoint 是否是必要动作空间

本地文献整理中有两条相互支持的线索：

- P2DNav 的高 OSR 来自 waypoint-free 与全景到俯视的分层推理；
- AgenticNav 的消融指出动作工具可能优于传统 waypoint predictor。

这对我们的意义是：当前 OSR25 可能不只是 selector 选得不好，还可能是 **“候选 waypoint 从一开始就没有提供足够好的动作”**。

但是这条路线不能直接重写，因为它会同时改变：

- 动作空间；
- 环境交互频率；
- 候选生成与碰撞处理；
- 评测和 SPL 口径；
- 原有所有对照实验的可比性。

所以 waypoint-free 只能作为高风险分支，先做最小 probe，不能把文献的 OSR62.7 当作预期结果。

### 2.4 把进度、房间、物体和失败笔记合并到状态更新

HAM-VLN 设计与我们准备做的“动作和进度一起更新”方向相似：一次决策不仅输出动作，也顺带更新房间类型、物体、进度和失败笔记。

它的启发不是“多写几行记忆文本”，而是：

> **状态更新应该是导航决策的一部分，并且要能被下一步直接消费。**

因此可以把“动作和进度一起更新”作为低成本验证：先把 LLM 的动作 JSON 扩展成包含 `progress_update` 和 `failure_note` 的 schema；如果 schema 稳定，再接入锚点链的单调队列和拓扑回环告警。

## 三、未来方向一：先完成低成本、可归因的结构迁移

### 方向 1：让动作和进度一次输出

**问题**：当前 `completion_estimation` 每步单独调用一次，平均占一轮 36.3% 的时间，且有倒退、早饱和和跨步不一致。

**方法**：让 selector 的严格 JSON 同时输出：

```json
{
  "action": "candidate_id_or_stop",
  "progress": {
    "completed_anchor_ids": [],
    "current_subgoal": "...",
    "confidence": 0.0
  },
  "failure_note": "..."
}
```

**最小实验**：

1. 保留旧 `completion_estimation`，只记录新 JSON 字段；
2. 检查 JSON 解析率、进度倒退次数、不同进度值数量和与真实测地进度的关系；
3. 只有 schema 稳定且结构性指标通过，才跳过旧调用；
4. 先在 ep10 验证，再考虑 ep100。

**闸门**：

- 无效 JSON 不高于 baseline 空预测率；
- 进度倒退为 0 或不高于预注册上限；
- 不允许只用 SR 判定，必须同时看 OSR、失败结构和运行时间；
- 任何进度字段都不能读取 GT 距离。

**预期价值**：首先是减少 15.7s/步的冗余调用、让状态更新和动作一致；是否提升 OSR 需要实验，不预设。

### 方向 2：加入拓扑回环告警

**问题**：69/100 集发生过重访，但旧 `loop_flag` 过密，不能直接注入 selector。

**方法**：使用 GTA 风格的节点合并和访问计数，达到阈值后追加方向告警；不修改候选集，不碰 STOP。

**最小实验**：

- 固定 `merge_radius=0.8m`、`loop_threshold=3`；
- 只打开 `MEMORY_DIAGNOSTIC.LOG_ONLY=False`；
- 不和前面的停止限制、行动预算、图像证据接入同时开启；
- 记录告警后是否换方向、重访对数、节点数、假停数和 OSR。

**闸门**：

- 告警后至少 30% 的步出现方向变化；
- 重访对数下降；
- 假停数不得上升；
- OSR 作为主结果，SR 只作辅助结果。

**风险**：拓扑回环告警可能只是“集长检测器”，并不真正识别失败；离线结果显示触发集成功率和未触发集相同，因此不能预设它会提升 SR。

## 四、未来方向二：把锚点链和空间记忆做成真正的决策状态

### 方向 3：Anchor Chain + Landmark Pool + Spatial Graph

这是当前最适合本项目的中期主线，因为它复用已有代码，同时对应多篇文献共同出现的结构。

**目标**：把“我走到哪了”从每步文本猜测改成：

```text
指令 -> 有序锚点链
轨迹 -> 拓扑节点/边/重访状态
视觉 -> 地标池与到达证据
状态机 -> 单调进度 j
```

**当前已有资产**：

- L0 Anchor Chain 已实现；
- L1 Progress Locator 已实现但闸门未过；
- M1 空间记忆已加 floor 和未探索分支；
- M2 地标池已限制到锚点词表；
- L4 三重终止门已能离线计算。

**下一步不是继续加模块，而是补验证缺口**：

1. 对 location 判定器做 MP3D region precision 标定；
2. 修正或隔离 `candidate_novelty` 的坐标镜像问题；
3. 统一用官方 OSR 和测地距离评估；
4. 重新跑 L1 离线闸门；
5. 只有 L1 通过，才让它替换 completion estimation。

**中期成功标准**：

- 进度状态单调且非退化；
- OSR 比基线有可解释的提升；
- 假停不增加；
- 不依赖任何在线 GT；
- 运行时间因删除 completion estimation 而下降。

### 方向 4：Planner / Executor 分层

**文献动机**：SpaceVLN 等方法的消融表明，planner/executor 骨架本身可能比单独增加记忆更重要。

**最小版本**：不直接重写成完整 SOTA，而是做两层原型：

- planner：每个 anchor stage 只调用一次，决定当前子目标和允许的探索范围；
- executor：每步根据当前视角、候选、空间图和子目标选择 waypoint；
- stage 完成后才允许 planner 更新下一个子目标。

**最小实验**：

1. 在现有 trace 上离线构造 stage 边界，测 planner 输入是否包含比单步 selector 更多的有效状态；
2. 做一个 ep5 原型，只看轨迹长度、重访、OSR proxy 和 JSON 稳定性；
3. 再决定是否进入 ep20。

**主要风险**：planner 的方向先验可能只是把旧的候选重排换了一个名字，重蹈 Arm C / geometry injection 的死路。因此闸门不能用“候选命中率”，而要看 OSR、米制 regret 和重访结构。

## 五、未来方向三：高风险地评估 waypoint-free / BEV

### 方向 5：从 waypoint predictor 转向原语动作或局部 BEV

**为什么值得研究**：

- 我们的候选集上界说明，当前 waypoint 集本身可能限制 OSR；
- P2DNav 的方向是 panoramic-to-BEV 与 waypoint-free；
- AgenticNav 的动作工具消融也指向“动作工具可能优于传统航点预测器”。

**为什么现在不能直接开工**：

- 需要新的动作执行与碰撞处理；
- 需要重新定义候选/轨迹记录；
- 需要确认 RGB-D、位姿和 BEV 几何是否足够可靠；
- 与当前 Open-Nav baseline 不再是单开关可比实验。

**建议的最小 probe**：

1. 不改主线，选择少量失败集和高 regret 决策点；
2. 用现有 Habitat 位姿和候选渲染，构造局部 2D/BEV 观察；
3. 比较三种动作表示：原 waypoint、固定角度原语、连续短步方向；
4. 只测“能否找到更接近目标的可执行动作”和碰撞/轨迹长度，不宣称 SR；
5. 只有 probe 显示动作空间确实产生新可达动作，才开始架构重写。

**停止条件**：如果局部 BEV/原语动作没有比 waypoint 提供更多有效可达方向，就不投入完整重构。

## 六、暂时可以不投入的方向

### 1. 再换一个更大的同骨架模型

三档模型已经形成 39%–43% 平台；如果输入、状态和动作空间不变，继续换模型缺少区分性。

### 2. 继续堆 prompt 或 confusion 自报

同分布 vote-dispersion 早期校准接近随机；言语化“你困惑吗”也没有提供可靠信号。下一次主动再观测必须获取新证据，而不是重复询问同一个后验。

### 3. 直接移植 TSDF + BEV 全套的最新感知栈

这是高成本基础设施项目，不是下一轮组会后可以验证的单个机制。应先证明局部 BEV/动作空间有增量，再决定是否做完整 TSDF。
