# U 系列代码开发记录 2026-06-19

## 1. 开发目标

本轮代码修改的目标是按 U 系列方案落地最小可运行框架：

```text
U0-log:       统一记录 U1/U2/U3 trace，不新增 U 系列 decision-effect
U1:           phase-aware evidence scaffolding
U2:           evidence-grounded STOP verifier
U3:           failure-conditioned recovery
U4-combined:  由 U1/U2/U3 开关组合实现，不单独新增代码分支
```

命名统一使用 U 系列，不再引入 M 系列，避免实验表格和代码开关混乱。

## 2. 代码变更

### 2.1 新增模块

| 文件 | 作用 |
|------|------|
| `vlnce_baselines/common/opennav_ext/phase_evidence.py` | 生成 `phase_evidence`，判断 `search / approach / verify / recover / unknown` |
| `vlnce_baselines/common/opennav_ext/evidence_scaffolder.py` | U1 phase-aware selector context，默认 shadow/log-only |
| `vlnce_baselines/common/opennav_ext/stop_evidence_verifier.py` | U2 STOP evidence 证据层，记录 intrinsic / relation / trajectory / weak-target |
| `vlnce_baselines/common/opennav_ext/failure_diagnostic.py` | U3 failure type 诊断，记录 empty / stop rejected / drift 等触发 |
| `vlnce_baselines/common/opennav_ext/recovery_policy.py` | U3 conservative reselect policy，只基于已有 ranked fallback 候选 |
| `vlnce_baselines/common/opennav_ext/decision_audit.py` | 统一记录 U 系列是否发生 override |

## 3. 配置语义

当前 `run_OpenNav.yaml` 的 U 系列配置为：

```yaml
OPENNAV_HARNESS:
  U_SERIES:
    ENABLED: true
    DECISION_EFFECT_UNIT: none

    PHASE_EVIDENCE:
      ENABLED: true
      LOG_ONLY: true

    STOP_EVIDENCE_VERIFIER:
      ENABLED: true
      LOG_ONLY: true

    FAILURE_RECOVERY:
      ENABLED: true
      LOG_ONLY: true
      ENABLE_RESELECT: false
```

含义：

- `DECISION_EFFECT_UNIT: none` 表示 U 系列只记录 trace，不新增 U 系列动作改写。
- 现有 V 系列模块仍按自己的 `LOG_ONLY` 和 `ENABLE_DECISION_EFFECT` 生效。
- 后续 U1/U2/U3 单元实验必须显式切换 `DECISION_EFFECT_UNIT`，并把对应模块设为 `LOG_ONLY: false`。

## 4. 主循环接入点

### 4.1 U1 phase-aware context

接入位置：

```text
completion_estimation
-> phase_evidence
-> phase_aware_context shadow build
-> 如果没有 completion STOP，进入 selector 前才应用 U1 context
```

行为边界：

- U1 不直接改 STOP。
- U1 不直接调用 fallback。
- `phase=verify` 时不应用普通 selector context，STOP 验证交给 U2。
- U1 decision-effect 与 V4 unified context decision-effect 互斥。

新增事件：

```text
phase_evidence
phase_aware_context
unit_override  # 仅 U1 实际替换 selector context 时记录
```

### 4.2 U2 STOP evidence verifier

接入位置：

```text
completion_gate visual_target_verifier 后
selector_stop_gate visual_target_verifier 后
```

行为边界：

- U0-log 下只记录 `stop_verification` 和 `weak_target_decision`。
- U2 decision-effect 下，只约束 selector STOP 的 visual rescue。
- completion STOP 不由 U2 直接改写，避免和原 stop gate / V2 冲突。

新增事件：

```text
stop_verification
weak_target_decision
unit_override  # 仅 U2 阻断 visual STOP rescue 时记录
```

### 4.3 U3 failure recovery

接入位置：

```text
selector_empty_prediction_fallback 后
stop_rejected_fallback 后
```

行为边界：

- U0-log 下记录 `would_apply`，不改动作。
- U3 decision-effect 下，只有存在 `ranked_candidates` 的 fallback 才允许 reselect。
- 不基于原始候选顺序强行重选，避免引入不可解释动作漂移。
- 每个 episode 使用 `MAX_RECOVERY_PER_EPISODE` 控制恢复预算。

新增事件：

```text
failure_type_diagnostic
failure_recovery
unit_override  # 仅 U3 实际替换 fallback candidate 时记录
```

## 5. 配置校验

新增校验规则：

- `DECISION_EFFECT_UNIT` 只能是 `none | U1 | U2 | U3 | combined`。
- `U0-log` 下所有 U module 必须 `LOG_ONLY: true`。
- `DECISION_EFFECT_UNIT=U1` 必须 `PHASE_EVIDENCE.ENABLED=true` 且 `LOG_ONLY=false`。
- `DECISION_EFFECT_UNIT=U2` 必须 `STOP_EVIDENCE_VERIFIER.ENABLED=true` 且 `LOG_ONLY=false`。
- `DECISION_EFFECT_UNIT=U3` 必须 `FAILURE_RECOVERY.ENABLED=true`、`LOG_ONLY=false`、`ENABLE_RESELECT=true`。
- U1 decision-effect 不能和 V4 `MULTIMODAL_SELECTOR_CONTEXT.LOG_ONLY=false` 同时开启。
- `combined` 至少需要一个 U module 处于 decision-effect。

## 6. 二次审查发现与修复

| 问题 | 风险 | 修复 |
|------|------|------|
| U1 `stop_verify` 阶段仍会拼接 V4 visual summary | verify 阶段可能把普通 selector context 和 STOP verifier 混在一起 | 改为 `mode != "stop_verify"` 时才拼接 visual summary |
| U3 没有 ranked fallback 时可能按原始候选顺序重选 | decision-effect 解释性弱，可能引入随机漂移 | 要求存在 `ranked_candidates` 才允许 U3 reselect |
| U1 context 在 completion STOP 前就可能记录为 applied | trace 会显示 selector context override，但实际 selector 没有执行 | 改为先 shadow build，只有进入 selector 分支前才应用并记录 override |
| `DECISION_EFFECT_UNIT=U2/U3/U1` 可配置但对应模块仍 log-only | 实验名和实际行为不一致 | 增加 required-module 校验，配置不一致直接报错 |

## 8. 后续实验建议

建议下一步先跑 U0-log 小样本，确认新增 trace 字段稳定：

```text
U0-log: 10-20 episodes
检查事件: phase_evidence / phase_aware_context / stop_verification / failure_recovery
重点看: would_apply、not_applied_reason、weak_target_decision、recovery_budget_remaining
```

然后再做单元级 ablation：

```text
U2: STOP rescue 约束
U3: fallback reselect
U1: phase-aware selector context
```

不要直接从 `combined` 开始，否则无法解释是哪一个 U 单元带来的收益或退化。
