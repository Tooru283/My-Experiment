# 全链条重审：我们的问题不在某一层，在被五层分解漏掉的那一维

> 20260720 版的层级判定已被 10 天内的四组新证据推翻。本文重做归因。
> 纪律不变：只写已落代码 + 已实测数字；推测标为假说。

## 零、一句话结论（20260730b 修订：不需要新增一维，就是认知层）

> ~~五层框架里没有"状态"这一格~~ —— **初版这个说法是过度设计，已撤回。**
> ~~世界模型（world model）~~ —— **该词已撤回，见下方术语纪律。**
> **问题不是框架缺一格，是认知层只实现了一半。**

> [!warning] 术语纪律（20260730b）
> **本文初版用了"世界模型 / world model"，是导入的外部词汇，全库此前 0 次使用，已撤回。**
> ① 该词在 ML 里有专指：**学习到的环境动力学预测器**（Ha & Schmidhuber / Dreamer / JEPA），
> 能 rollout 想象未来。我们说的东西是**访问计数 + 已见地标集 + 子句指针**——
> 叫它 world model 是实质性过度声称，审稿人一句话可破："your world model is a visit counter."
> ② 我们引的四篇论文**没有一篇**用这个词：AgenticNav = *agentic memory*、SpaceVLN = 空间记忆、
> MemVLN = 情景/程序记忆、Dynam3D = *scene memory*。**领域里的词是 memory。**
> ③ **本项目早有自己的词：「路线状态」/「路线状态外置」**
> （[[实验框架-路线状态外置-20260713]] v1.1）。**统一用它，不另造。**

**认知层的两件事，我们只做了第一件：**

| | 定义 | 形态 | 我们有几个 |
|---|---|---|---|
| **解释** interpretation | 本步像素 → 本步语义 | **无状态函数** `f(obs_t) → z_t` | **7 个**（completion / phase / grounder / visual_evidence / context_builder …） |
| **累积** accumulation | 历次解释 → 持续修正的世界表示 | **有状态对象** `f(S_{t−1}, obs_t) → S_t` | 见下 —— **比"零个"更糟** |

**而累积那一栏的真实情况，是本次代码核实最重要的发现（§2.2b）：**

> **我们有两个由外部证据构成的状态累积器，被架构 `ValueError` 硬性禁止进入决策；
> 而唯一进入决策的跨步状态，是 LLM 给自己写的摘要。**

这不是"忘了做"，是**做了、然后主动锁死，再用一个模型自述顶替它**——
恰好是本项目"信念外置"原则在**状态层面**的完整反面，且由我们自己的架构强制执行。

## 一、为什么 20260720 的判定必须推翻

| 环节 | 0720 判定 | 0730 修订 | 推翻它的证据 |
|---|---|---|---|
| 感知 | ❌ 不是瓶颈 | ❌ **仍不是，但理由要换** | 见 §二.1 |
| 认知 | ⚠️ 成本瓶颈 | ⚠️→**结构瓶颈** | 见 §二.2 |
| 决策-选择 | ✅ **是瓶颈** | ↩️ **改写：不是"选不准"，是"无状态下选择本就近随机"** | M1/M1-Large（43% 上界，跨三模型平坦）+ §一decem 读数 Y |
| 决策-停止 | ❌ 不是 | ❌ **仍不是，且获外部佐证** | AgenticNav：他们转化 55%，我们 76% |
| 执行 | ❌ 不是 | ⚠️ **可能是（新增疑点）** | 四篇论文都在离开航点选择接口（§二.4） |
| 反馈 | ✅ 是（结构性） | ✅ **是，但归因错了** | 见 §二.5 —— 关键修订 |

### 三组新证据

**A. 43% 是问题形式的上界，不是模型的上界。**
M1：60→100 决策点，同模型同 prompt 只换候选携带什么 —— IMG 41.0 / TXT 30.0 / GEO 26.0 / 随机 25.7，
错配图对照 18.0（**低于随机**，三模型复现 p=0.001/0.001/0.002 → 模型确实在读像素，null 非伪）。
M1-Large：9B 41.0 / qwen3-vl-plus 43.0 / omni 39.0 —— **三档平坦**。
→ 这四个数测的是同一件事：**"给定此刻的观测，选哪个候选"**。
**它是一个无记忆的单步判别问题，而这个问题形式的上界就在 43%。**

**B. 而这个问题形式是架构强加的，不是任务要求的。**
R2R 指令是**路线描述**（"出卧室左转沿走廊过拱门在跑步机旁停"）。执行它在语义上必须知道：
*我走到指令第几句了 / 我来过哪里 / 哪些方向已被排除 / 那个拱门是不是刚才那个*。
**这些全是状态。** 我们把一个**状态相关**的任务，实现成了一串**无状态**的单步判别。

**C. 外部四个独立锚点，全部指向状态而非模型。**

| 来源 | 读数 | 训练? |
|---|---|---|
| AgenticNav | 去掉「紧凑地图 + 选择性回忆」**−14 SR** | **零训练**（Trained Modules = ×） |
| SpaceVLN（§一decem） | 去掉空间记忆 **−14.4 SR** | 零样本 |
| SoftNav（§4 已核） | Text-Hint（**完全未训练**的 VLM + 好的 3D 状态）OVON val_unseen **63.3**，而此前 SOTA MTU3D 40.8；soft token 只再加 3.4 | 投影器 17M |
| Dynam3D | **3.8B** 骨干 + 3D token → R2R-CE val_unseen **52.9** | 全训练 |

**两条读法：**
1. **规模不是差异来源。** Dynam3D 3.8B / SoftNav 3B，都比我们 9B 小，SR 是我们的 2.5–3 倍。
2. **状态可以是 training-free 的。** AgenticNav 的 −14 是在**零训练模块**下测出来的。
   → **"缺状态"不等于"必须训练"。这一条解除了我们最大的资源约束。**

## 二、逐层重审

### 2.1 感知：仍不是瓶颈，但旧理由已失效

**旧理由**："候选集 84% 的步骤含正确候选，几何误差 0.000m。"
**问题**：这只说明**候选集**够用，不说明**感知产出**够用。

**新理由**：感知的产出是**瞬时快照**，不是**可累积的实体**。
每步 12 路全景 + RAM 标签 + SpatialBot 描述，**下一步全部作废重来**。
一个门口在第 3 步和第 7 步被看到两次，系统不知道那是同一个门口。
→ **我们有物体的名字，没有物体的身份。**（Dynam3D 的 instance 层正是补这个：
"对象级 3D 持续身份"；其消融显示去掉 instance+zone 只留 patch 会大幅下降。）

⚠ **同时撤回一条旧结论**：0720 §六 列"prompt 注入几何 p=0.21"为已排除路。
**该实验无效**——`geometry_query.py:20-35` 从不读深度，2906/2906 条 `approx_world_point=True`，
注入的 `distance_dict` 就是候选表里已有的 distance。**注入的是同义反复，p=0.21 是必然。**
真实几何从未注入过。（详见 [[current_task]] §一undecim AF。）

### 2.2 认知：从"成本瓶颈"升级为"结构瓶颈"

0720 的判定是"贵但不一定影响 SR"。这个判定漏了一件事：

**`completion_estimation` 是整个系统里唯一试图承载"进度状态"的模块 —— 而它已自证伪。**

| 检验 | 结果 |
|---|---|
| 第 1 步就报"100% 完成" | 69/94 集 |
| 物理上不可能的"进度倒退" | 75 次 |
| 与真实进度相关 | r = 0.120（步内 r = +0.037） |
| 驱动 phase 判定 | 47.7% |

→ 不只是"贵且没用"。是：**系统的唯一状态变量是坏的，而下游都在读它。**
而且我们的实现方式是**让 LLM 每步猜一次**——这正是"信念外置"哲学要禁止的事：
把一个应该由外部证据确定的量，交给模型的自报。

**这一层的正确表述**：认知层没有维护状态，它在**每步重新幻觉一个状态**。

### 2.2b 认知层的累积侧：不是缺席，是被架构锁死（20260730b 代码核实）

**① 两个真累积器，被硬编码禁止进决策。**
`harness_config.py:279-302` 对下列模块**强制 `LOG_ONLY=true`，否则直接 `raise ValueError`**：

```
GEOMETRY_QUERY / GROUNDER_DIAGNOSTIC / MEMORY_DIAGNOSTIC / CONTEXT_BUILDER /
ORACLE_METRICS / VISUAL_EVIDENCE / VISUAL_TARGET_VERIFIER /
VISUAL_EVIDENCE_MEMORY / MULTIMODAL_SELECTOR_CONTEXT
```

其中**跨步累积的恰好是被锁的两个**：
- `MEMORY_DIAGNOSTIC`（`visual_graph_memory.py`）—— 位姿访问历史、`visit_count` / `revisit_score` / `loop_flag`
- `VISUAL_EVIDENCE_MEMORY` —— 跨步累积的视觉证据

→ **它们每步都在算、都在写日志、从不参与任何决策。** 这不是配置选项，是架构不变量。

**② 唯一进决策的跨步状态，是 LLM 给自己写的摘要。**
`spatialNavigator.py:91-107` 的 `save_history` **每步两次 LLM 调用**：

```python
observation = f"Direction {direction} " + self.llm.gpt_infer(OBSERVATION_SUMMARY..., curr_observe)
thought     = self.llm.gpt_infer(THOUGHT_SUMMARY..., thought)   # ← 对模型自己上一步"想法"的摘要
nav_history.append({step, viewpoint, observation, thought})
```

`review_history` 把它拼成字符串进 prompt。**所以我们的"记忆"是：
模型对自己观测叙述的摘要 + 模型对自己推理叙述的摘要，逐步复利叠加，全程无外部证据校验。**

**③ 为什么这一条比框架讨论重要**：我们已经独立证明了模型自述不可信
——三个不确定性探针全 ≈ 随机、`completion_estimation` r=0.120/75 次进度倒退、
verbalized confidence ECE 0.463。**而我们把状态完全托付给了同一类信号。**

**④ 它同时改变了修复成本的估计。**
不是"从零建一套新东西"，而是**"把已有的累积器解锁 + 换掉自述式记忆"**——
S1 的代码已经存在（§三），真正的工作量在 harness 不变量的重新设计和闸门验证。

### 2.3 决策-选择：从"是瓶颈"改写为"无状态下的选择本就近随机"

0720 说"9B 只比平凡启发式强 1 点"，读作选择器弱。
**现在的读法**：36.7% vs 35.7% 这个差距小，不是因为模型弱，
而是因为**在没有状态的条件下，局部选择本来就接近随机**——§一decem 读数 Y 已给出这个解释，
M1/M1-Large 给出了它的数值上界（43%）。

**本项目自己的"失败集 48% 走远 ≈ 随机游走"是同一症状**，当时被读作"选择层瓶颈"，
**现在应读作"无状态症状"**。

推论：**在补上状态之前，任何进一步优化选择层的努力都是在 43% 的天花板下打转。**
这解释了 Arm C（+7 点命中 → +0.094m/步）、G1 下界（+0.12m/集）、G1 隐藏态（FAIL）
为什么形成一条完美的递减序列——它们全在同一个天花板下。

### 2.4 执行：新增疑点（航点选择接口本身）

0720 判"干净、不是瓶颈"。这个判定只检查了**发射动作是否无歧义**，
没有检查**动作空间的形式**是否限制了上界。

**四篇论文各自独立地离开了航点候选选择：**

| 论文 | 换成了什么 | 代价证据 |
|---|---|---|
| AgenticNav | VLM 直接在 RGB 上点像素 | 换回航点预测器 **−5 SR** |
| MemVLN | 10 个原语动作（停/前进 25·50·75cm/转 ±15·30·45°） | 无航点预测器 |
| SpaceVLN | 原语动作 + 锚点链 | 剥掉记忆与 CoT 仍有 37.3 |
| DreamNav | 轨迹级规划 | 原文批评 "collapsing control to **point-level choices**" |

⚠ **重要限定**：这不构成"我们的执行层坏了"。它构成的是——
**M1 的 43% 上界可能是「航点候选选择」这个接口的属性，而我们恰好只在这个接口上测过。**
这是一个**未检验的替代解释**，不得当结论用。

### 2.5 反馈：诊断对了，归因错了（本文最关键的一条）

0720 写："反馈层是最弱的一环，它根本不闭环……**没有训练回路**，人在回路里当梯度。"

**诊断正确，归因错误。** 把"不闭环"归因为"缺训练回路"，导致我们把出路想成
"必须训练"，而训练又被数据量（6250 样本 / 100 集）挡死 —— 于是这一层被搁置了两个月。

**正确的归因**：不闭环 ≠ 权重不更新。不闭环 = **没有跨步累积的环境状态**。
AgenticNav 用**零训练模块**的紧凑地图 + 回忆工具，拿到了 14 个 SR。
→ **这一层的出路 training-free 可得，两个月前就可以做。**

## 三、我们设计过的解决办法，落在哪一层

| 机制 | 落点 | 结局 | 死因 |
|---|---|---|---|
| depth veto | 决策-停止 | ❌ | AUROC 0.531，任何阈值净负 |
| 位移回溯 | 决策-选择 | ❌ | 采纳率 1.9%，贡献 0 |
| 候选先验 Arm C | 决策-选择 | ❌ | +7 点命中 = 仅 0.094 m/步 |
| 几何注入 P0 | 感知→认知接口 | ❌→⚠ | p=0.21，**但实验无效（同义反复），已撤回** |
| 三个不确定性探针 | 认知 | ❌ | 全部 ≈ 随机 |
| 打分头 G1（标量/隐藏态） | 决策-选择 | ❌ | 输入端无信息 |

| M1 / M1-Large | 感知→决策接口 | ❌ | 43% 上界，跨三模型平坦 |
| ENDGAME_TILT_VIEW | 感知 | ⏸ | 未结算 |

**统计：9 项里 7 项落在「决策」与「接口」，0 项落在「状态」。**

而我们**写过**朝状态方向的代码，**从没让它参与决策**：

| 死代码 | 内容 | 状态 |
|---|---|---|
| `visual_graph_memory.py`（109 行） | `visit_count` / `revisit_score` / `loop_flag` / `candidate_novelty` | `MEMORY_DIAGNOSTIC.LOG_ONLY=True` |
| `landmark_matching.py`（135 行） | 地标匹配零件 | 无跨步地标池 |

⚠ **翻开关前必须先修的 bug（本次代码核实，新发现）**：
`visual_graph_memory.py:27-33` 的 `_candidate_next_position` 用
`angle = heading + angle_rad`、`x += d·sin(angle)` —— **与标定约定（θ=−heading−angle_rad）左右镜像**，
和 `geometry_query.py` 是同一个符号错误。
→ **`candidate_novelty` 目前算的是「镜像候选」的新颖度，直接翻 decision-active 会静默出错。**
→ 但 `visit_count` / `revisit_score` / `loop_flag` **只用 agent 自身位姿历史，不受影响，今天即可用**。

**"VLM 只作感知，永不作信念"**。

**真正的问题是它从没被执行，而且从跟踪文档里掉了出去：**

**我们跑完了外围两条臂，跳过了中间那台机器。**

⚠ **连带风险（对外材料）**：[[REALM-组会分享]] 附2 对照表里，我们那一行写的是
"路线状态外置：**路线一致性停止门**（覆盖×顺序×步数）∧ **depth veto** ∧ 负目标记忆"，

**与 07-13 相比，本轮真正新增的只有三件事**（框架照旧，证据是新的）：
1. **不做它的代价有多大**：无状态单步选择上界 **43%**，跨三个模型规模平坦（M1 / M1-Large）；
2. **别人做它值多少**：−14 / −14.4 SR（AgenticNav 零训练 / SpaceVLN），40.8→63.3（SoftNav Text-Hint）；
3. **为什么我们做不成**：§2.2b 的代码事实——两个累积器被 `ValueError` 锁死，位置让给了 LLM 自述摘要。

## 四、新的解决办法：把认知层的累积侧补回来

**不新增层，也不新增维度。就一句话：让认知层从"每步解释器"变回"状态维护器"。**

```
认知层（现状）           认知层（目标）
 f(obs_t) → z_t          f(S_{t-1}, obs_t) → S_t, z_t
 7 个解释模块 ✅          解释 ✅ + 累积 ✅
 2 个累积器 🔒 锁在日志    2 个累积器解锁 + 外部证据校验
 记忆 = LLM 自述摘要      记忆 = 外部证据构成的世界状态
```

三个组件，**按 training-free 程度排序**（这也是实施顺序）：

### S1. 访问状态 —— 纯几何、零训练、代码已存在

**内容**：位姿网格去重 + 重访计数 + 已排除方向 + 闭环标志。
**依据**：三篇独立论文的交集 —— AgenticNav 紧凑轨迹地图、DB-Nav 失败访问记忆、T2-Nav 闭环检测。
**我们的现状**：`visual_graph_memory.py` 已实现前三项，锁在 LOG_ONLY。
**前置**：修 `_candidate_next_position` 的镜像 bug（只影响 `candidate_novelty`）。
**预注册靶子**：先跑绕圈率统计（纯离线、半小时）——量化 23 集耗尽里有多少是重访。
⚠ **不得预设成功**：Arm C 已证"步内重排"不转化；但 visit-info 是"**跨步**避免重访"，机制不同。

### S2. 实体状态 —— 跨步对象身份，中等成本，不需要训练对齐

**内容**：把"有名字没身份"的物体列表，变成跨步持续的实体。
**依据**：Dynam3D 的 instance 层（其消融：去掉 instance+zone 只留 patch 大幅下降）。
**关键**：Dynam3D **不依赖 PQ3D 那种预训练任务专用 3D 编码器**（SoftNav 原文明确指出这一区别），
它从 CLIP-ViT patch 特征 + depth + pose 自建。
→ **表示层可分解、且大部分免训练**：patch 投影（现成）、frustum culling（纯几何）、
FastSAM 掩码（预训练）。需训练的是 instance encoder 与语言对齐 —— **这两块我们先不做**。
**最小可行形态**：只做"跨步实体关联 + 位置锚定"，不做语言对齐。

### S3. 进度状态 —— 替掉 `completion_estimation`

**内容**：用**已访问的地标锚点链**定位指令进度，而非让 LLM 每步自报。
**依据**：§一decem 阶段 2 已列此项；`completion_estimation` 的自证伪数据（§2.2）是它的死刑判决书。
**性质**：这是"信念外置"哲学的**正确应用范围** —— 我们过去只把它用在"停止信念"上，
**它本该用在"进度状态"上**。
**范围扩大（20260730b）**：S3 不止替 `completion_estimation`，还要替 **`nav_history` 的自述式记忆**
（§2.2b②）。两者同源——都是"让模型自己讲它到哪了"。
⚠ 但 `nav_history` **当前是唯一进决策的跨步信号**，直接拆会失去仅有的跨步信息。
**顺序必须是：先让 S1 的外部证据进决策，跑出对照，再谈替换 `nav_history`。**

## 五、科研问题的重新表述

**旧表述**（信念外置）：小 VLM 的信念不可靠且不可探测 → 决策证据全部来自模型外部。
**问题**：范围太窄（只覆盖停止判断），且已被 REALM/ConsistNav 等占位。

**新表述（建议）：从"信念外置"扩展为"状态外置"**

> **在视觉语言导航中，多少能力来自模型，多少来自状态表示？**

这个问题我们**具备别人没有的那一半答案**：

| 谁测了什么 | 数字 |
|---|---|
| **我们（独有）**：无状态时的能力上界 | **43%，跨三个模型规模平坦**；文本通道相对随机仅 ~9 点；有监督探针 ≈ 零样本 |
| 文献：有状态时的增量 | 记忆 −14（AgenticNav，零训练）/ −14.4（SpaceVLN）；状态表示 40.8→63.3（SoftNav Text-Hint） |

**文献全部「假设」状态有用并给出增量；没有人测过「没有状态时的地板在哪」。**
我们有八条带定量死因的关闭路线 + 预注册闸门 + 错配图对照 + 探针上界方法论 ——
**这是把两个月的负结果从负债转成资产的唯一表述方式，而且它是诚实的。**

## 六、诚实限定

1. §2.4「执行层可能是瓶颈」是**未检验的替代解释**，不得当结论。
   要检验它，需要在**非航点接口**上重测 43% 那条线——工程量大，排在 S1 之后。
2. AgenticNav 的 −14 是在其完整系统（分层 + 记忆 + 工具三者齐备）里测的，
   **不能线性挪用到我们的架构上**。S1 必须有自己的预注册闸门。
3. Dynam3D 的 lifelong memory +4.2（52.9→57.1）是**跨 episode 复用同场景表示**，
   标准评测协议不允许，**不得作为我们的期望增益**。
4. 本文的层级归因基于当前证据，**不是永久结论**。
   尤其"状态是那一维"这一条，**在 S1 跑出结果前仍是假说**——
   它目前的支撑是四个外部锚点 + 我们自己的 43% 上界，**没有一条来自我们系统内的干预实验**。
