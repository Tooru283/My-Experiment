# V 系列多模态视觉证据实验记录

本文档记录在 Controlled Navigation Harness 中新增的 **V 系列多模态视觉证据实验轴**。

V 系列的核心问题是：

```text
当前 Open-Nav 虽然运行在 Qwen3.5-4B 多模态模型上，
但导航主链仍主要把候选图像转成文本 observation 后交给 LLM。

V 系列要验证：
直接把候选视觉观察纳入证据、验证和记忆机制后，
能否减少纯文本观察导致的误判，尤其是提前 STOP、目标可见性误判和历史状态漂移。
```

---

## 1. 与 A/B/C/D/E/F 实验轴的关系

V 系列不是替代原有 A/B/C/D/E/F 阶段，而是一个横向实验轴。

| 轴 | 原含义 | V 系列关系 |
|----|--------|------------|
| A0 | Open-Nav original baseline | 不改 |
| A1 | harnessed / instrumented baseline | V1 可作为 A1 的 logging-only 增强 |
| A2+ | decision-impact variants | V2 之后才可能进入决策影响 |
| B | Grounder / semantic grounding | V1/V2 提供真实图像证据补充文本 grounding |
| C | VisualGraphMemory | V3 扩展为 VisualEvidenceMemory |
| D | ProgressTracker / progress state | V2/V3 可为进度状态提供视觉完成证据 |
| E | TargetVerifier | V2 是 visual TargetVerifier 的前置版本 |
| F | FallbackController | V4 之后可为 fallback 提供视觉不确定性触发依据 |

关键边界：

```text
V0/V1 不改变导航行为。
V2 先以 log-only 形式验证，再决定是否进入 decision effect。
V3/V4 只有在 V1/V2 日志证据稳定后再推进。
```

---

## 2. 当前已知事实

### 2.1 模型与服务

- 当前本地模型路径：`/root/models/Qwen3.5-4B`。
- 模型配置包含 `vision_config`、`image_token_id`、`video_token_id`。
- `preprocessor_config.json` 指向 `Qwen3VLProcessor`。
- `tokenizer_config.json` 的 chat template 支持 `image` / `image_url` / `video`。
- 本地 OpenAI-compatible 服务端口：`http://127.0.0.1:23333/v1`。
- `/v1/models` 有响应，但返回模型列表为空；实际 chat completion 可用。

### 2.2 当前 Open-Nav 主链状态

- `llmClient.gpt_infer()` 仍发送纯文本消息。
- 原有观察链路是：候选 RGB 图像 -> SpatialBot / RAM 等工具生成文本 observation -> LLM 读文本决策。
- 最新 A1 日志中仍存在 `selector_raw.predictions=[]` 后 fallback 到第一个 observed candidate 的问题。
- 最新 A1 日志中出现过提前 STOP 风险，尤其是文本 completion estimation 明确表示动作未完成时，STOP gate 仍可能被宽松字符串匹配放行。

## 4. V0: Qwen3.5-4B 多模态服务能力验证

### 4.1 目标

确认当前 `23333` 端口上的 Qwen 服务是否真的支持 OpenAI-style 多模态输入，而不只是模型配置声明支持。

### 4.2 验证内容

文本测试：

```text
model=/root/models/Qwen3.5-4B
prompt=Reply with exactly: ok
response=ok
```

图片测试：

```text
image=/root/wjj/Open-Nav/SpatialBot/bunny/serve/examples/example_1.png
payload=OpenAI-style content list with text + image_url data URL
```

返回摘要：

```json
{
  "contains_person": true,
  "main_objects": [
    "astronaut",
    "moon",
    "Earth",
    "beer bottle",
    "cooler",
    "space suit",
    "ladder",
    "stars"
  ]
}
```

### 4.3 结论

- Qwen3.5-4B 服务具备实际可调用的图文输入能力。
- `23333` 是当前本地 Qwen 服务端口。
- V1 可以在不改变导航主链的前提下，把候选图像发送给同一服务做视觉证据抽取。

## 5. V1: Visual Evidence Logging

### 5.1 目标

在不影响导航动作选择、不影响 STOP gate 的前提下，对候选视角图片做视觉证据抽取，并把结果写入 navigation JSONL 与 harness trace。

V1 解决的问题不是“提升指标”，而是先回答：

```text
纯文本 observation 说看到的东西，
和 Qwen-VL 直接看候选图像得到的证据是否一致？

提前 STOP 时，
图像证据是否真的支持 final target visible / arrival evidence？
```

### 5.2 已实现代码

```text

```


接入位置：

```text
/root/wjj/Open-Nav/vlnce_baselines/common/base_il_trainer_llm.py

```

## 6. V2: Visual TargetVerifier

状态：已完成初版；已支持 decision-effect 接入。

### 6.1 目标

把 V1 的视觉证据用于验证 STOP proposal 和最终目标可见性。默认可以保持 log-only；当全局 `ENABLE_DECISION_EFFECT=true` 且 `VISUAL_TARGET_VERIFIER.LOG_ONLY=false` 时，V2 会接入 STOP gate。

V2 重点回答：

```text
当导航器认为可以 STOP 时，
当前候选图像或当前观察是否真的显示 final target？

arrival_evidence 是否足够强？
是否存在“看到普通 door / hallway 就误停”的情况？
```

### 6.2 已实现代码

新增：

```text
/root/wjj/Open-Nav/vlnce_baselines/common/opennav_ext/visual_target_verifier.py
```

核心类：

```text
VisualTargetVerifier
```

接入位置：

```text
/root/wjj/Open-Nav/vlnce_baselines/common/base_il_trainer_llm.py
completion_gate should_stop() 之后
selector_stop_gate should_stop() 之后
```

输出事件：

```text
visual_target_verifier
```

配置：

```yaml
OPENNAV_HARNESS:
  VISUAL_TARGET_VERIFIER:
    ENABLED: false
    LOG_ONLY: true
    CONFIDENCE_THRESHOLD: 0.6
    REQUIRE_ARRIVAL_EVIDENCE: true
    REJECT_ON_MISSING_FINAL_LANDMARKS: true
    REJECT_ON_UNCERTAIN: true
```

默认关闭；打开后默认仍保持 `LOG_ONLY=true`。当前 V2 decision-effect 实验配置中设置为 `LOG_ONLY=false`。

Decision-effect 行为：

```text
STOP proposal -> VisualTargetVerifier verdict

verdict=allow:
  允许 STOP 继续执行。

verdict=reject:
  拦截 STOP，回到 selector 选择移动候选。

verdict=uncertain:
  当 REJECT_ON_UNCERTAIN=true 时拦截 STOP；
  当 REJECT_ON_UNCERTAIN=false 时只记录不拦截。
```

### 6.3 输入

- instruction
- decomposed actions
- landmarks
- history_traj
- current observation
- V1 `visual_evidence.parsed`
- stop proposal / stop reason
- candidate metadata

### 6.4 输出

当前 schema：

```json
{
  "stop_proposal": true,
  "source": "completion_gate",
  "verdict": "allow|reject|uncertain|not_applicable",
  "final_target_visible": false,
  "arrival_evidence": false,
  "matched_final_landmarks": [],
  "missing_final_landmarks": [],
  "contradictions": [],
  "confidence": 0.0,
  "reason": "short string",
  "best_candidate": {},
  "visual_evidence_candidate_count": 0
}
```

### 6.5 当前规则

- 若没有 STOP proposal，记录 `verdict=not_applicable`。
- 若视觉证据缺失或 JSON parse error，记录 `verdict=uncertain`。
- V2 以 candidate 为单位计算 verdict，不跨 candidate 合并 `final_target_visible`、`arrival_evidence` 或 final landmark match。
- 若同一个 candidate 同时满足 `final_target_visible=true`、`arrival_evidence=true`、final landmarks 完整且 confidence 达到阈值，整体记录 `verdict=allow`，并写入 `supporting_candidate_id`。
- 若 STOP proposal 存在、所有候选已覆盖且没有 candidate 支持 STOP，则根据缺失 final landmarks、final target 不可见或 arrival evidence 不成立记录 `verdict=reject`。
- 若 `sampled_all=false` 且没有 supporting candidate，整体记录 `verdict=uncertain`，避免把抽样子集证据误写成全局拒绝。
- 若 completion estimation 包含 `not executed`、`not done`、`has not` 等否定完成信号，同时出现 STOP proposal，记录 contradiction。

### 6.6 已完成验证

单元级 smoke 使用手工构造的 V1 visual evidence：

```json
{
  "visible_landmarks": ["doorway", "hallway"],
  "matched_instruction_terms": ["door", "hallway"],
  "missing_instruction_terms": ["bedroom"],
  "final_target_visible": false,
  "arrival_evidence": false,
  "confidence": 0.8
}
```

在 `landmarks=door, bedroom` 且 `stop_proposal=true` 时，V2 输出：

```text
verdict=reject
matched_final_landmarks=["door"]
missing_final_landmarks=["bedroom"]
contradictions=[
  stop_proposed_without_final_target_visible,
  stop_proposed_without_arrival_evidence,
  stop_proposed_with_missing_final_landmarks,
  stop_proposed_while_estimation_is_negative
]
```

集成 smoke 使用真实导航循环同时打开 V1/V2/V3；验证到事件写入后手动中断，不作为完整 episode 指标。

输出文件：

```text
/root/wjj/Open-Nav/logs/navigation_records/v123_visual_logonly_smoke_20260612_184828_train_navigation_20260612_184854.jsonl
```

结果：

- 共 29 条 JSONL record。
- `visual_target_verifier`: 2 条。
- 两条均为 `source=completion_gate`、`verdict=not_applicable`，因为这两步没有 STOP proposal。
- 即使 `verdict=not_applicable`，事件仍记录了 `missing_final_landmarks=["bedroom"]`，可用于后续与 STOP proposal 对齐分析。
- 审查后新增手工 smoke:
  - 两个候选分别提供 `bedroom` 与 `door + arrival_evidence` 时，整体 `verdict=reject`、`supporting_candidate_id=null`，验证不再跨 candidate 拼接证据。
  - `sampled_all=false` 且抽样候选不支持 STOP 时，整体 `verdict=uncertain`。

### 6.7 成功标准

- 能覆盖每次 `stop_decision`。
- 能明确区分 `door visible` 与 `door before bedroom visible`。
- 对失败 STOP episode，能给出与最终 distance / success 一致的拒绝证据。
- 在进入 decision-effect 前，不改变任何 episode 行为。

- 区分“曾经看见 door”与“已经到达 target door”。
- 记录目标相关 landmark 的首次出现、持续出现和消失。
- 为 progress tracker 提供视觉完成证据。
- 为 fallback 提供“最近可靠目标证据位置”。

- `visual_evidence_memory`: 2 条。

- `target_seen_count=0`。
- recent missing terms 包含 `bedroom`，第二步还记录了 `stop at the door before the bedroom`、`walk all the way to the end of the hallway` 等未满足指令项。
- 审查后新增手工 smoke:
  - raw `final_target_visible=true` 但 final landmarks 不完整时，`raw_target_seen_count=1`、`target_seen_count=0`。
  - 没有 verified target 时，`best_target_evidence=null`。
  - 普通最高视觉证据保留在 `best_visual_evidence`。

### 7.6 第一版边界

V3 第一版保持 log-only：

- 只更新 memory trace。
- 不注入 selector prompt。
- 不改变 candidate 排序。
- 不触发 fallback。

配置保护：

- 启用 `VISUAL_TARGET_VERIFIER` 或 `VISUAL_EVIDENCE_MEMORY` 时，必须同时启用 `VISUAL_EVIDENCE`。
- 单独启用 V2/V3 会在 `validate_a1_harness_config()` 阶段抛出 `ValueError`，避免产出空视觉证据日志。

## 8. V4: Multimodal Selector Context

状态：已完成初版。

默认仍保持 `LOG_ONLY=true`，只记录增强后的 selector context，不改变导航行为。只有同时设置：

```yaml
OPENNAV_HARNESS.ENABLE_DECISION_EFFECT: true
OPENNAV_HARNESS.MULTIMODAL_SELECTOR_CONTEXT.ENABLED: true
OPENNAV_HARNESS.MULTIMODAL_SELECTOR_CONTEXT.LOG_ONLY: false
```

才会把 selector 输入替换为带视觉证据摘要的 `selector_observation` / `selector_observe_dict`。

### 8.1 目标

让 selector 不再只看纯文本 observation，而是读取经过压缩的视觉证据摘要，从而减少 observation caption 幻觉或文本遗漏导致的候选选择错误。

### 8.2 输入形式

不建议直接把所有候选图像塞进 selector。

优先建议：

```text
candidate_id
text_observation
visual_evidence_summary
geometry_summary
memory_summary
uncertainty_flags
```

其中 `visual_evidence_summary` 来自 V1/V3 的结构化输出。

### 8.3 风险

- 会改变 selector prompt，属于 decision-impact variant。
- 需要和 A1/A2 基线严格隔离。
- 多候选图像直接输入会显著增加 latency 和 token / image budget。
- 如果 Qwen-VL 输出不稳定，可能引入新的选择偏差。

### 8.4 进入条件

只有满足以下条件才进入 V4：

- V1 完整 episode 日志稳定。
- V2 对 STOP 误判有明确解释能力。
- V3 memory 能稳定聚合视觉证据。
- 有对照实验证明纯文本 observation 与视觉证据存在可利用差异。


暴露的问题：

1. V2 目前只会拦截 STOP，不会主动放行旧 STOP gate 拒绝的 selector STOP。

   典型 case：episode 11 多次出现 selector 预测 STOP，视觉证据显示 `final_target_visible=true`、`arrival_evidence=true`，但旧 `should_stop()` 返回 false，因此 V2 被记录为 `not_applicable`，最后被迫继续移动到 step_length_limit。

2. V2 有 1 次 `allow` 但最终 metric 失败。

   episode 116 step 3 中 V2 `verdict=allow`、`supporting_candidate_id=7`，但最终 `distance_to_goal=4.816`、`success=0`。说明视觉目标语义与 VLN success 半径 / 真实目标点仍可能不一致。

3. selector 空预测 fallback 仍存在。

   本轮 `selector_raw.predictions=[]` 出现 10 次，全部 fallback 到第一个 candidate。V4 context 无法修正“无候选输出后直接选第一个”的策略风险。

4. `VISUAL_EVIDENCE.MAX_CANDIDATES=4` 在 5 候选 step 会漏掉 1 个候选。

   本轮 `sampled_all=false` 为 14/57。若漏掉的是目标候选，V2/V4 都可能得到错误证据。

5. latency 上升。

   本轮平均 step 耗时约 101 秒，`observation -> visual_evidence` 平均约 35 秒。直接把 `MAX_CANDIDATES` 提高到 5 会进一步增加成本。

下一阶段方案：

#### 8.8.1 STOP gate 改成 V2-first 双向 gate

当前 selector STOP 逻辑近似为：

```text
selector predicts STOP
-> old should_stop()
-> should_stop=false 时强制 fallback movement
-> V2 只记录 not_applicable
```

建议改为：

```text
selector predicts STOP
-> call VisualTargetVerifier with stop_proposal=true

if verdict == allow:
    accept STOP
elif verdict == reject:
    reject STOP and fallback movement
elif verdict == uncertain:
    if REJECT_ON_UNCERTAIN:
        reject STOP and fallback movement
    else:
        fallback to old should_stop()
```

completion gate 仍保持：

```text
old should_stop() proposes STOP
-> V2 verifies STOP
-> verdict=allow 才执行 STOP
```

这样 V2 既能拦截错误 STOP，也能在 selector 主动 STOP 且视觉证据强支持时放行 STOP，避免 episode 11 这类“视觉已到但旧 gate 不认”的问题。

新增日志建议：

```text
visual_stop_allowed
  source
  original_stop_reason
  verifier_reason
  supporting_candidate_id
  final_target_visible
  arrival_evidence
  confidence

visual_stop_rejected
  已有，保留
```

#### 8.8.2 V2 allow 增加几何/候选一致性约束

为降低 episode 116 这类视觉 allow 但 metric 失败的风险，`allow` 不应只看“某个候选图像支持目标可见”。建议增加：

```text
allow requires:
  final_target_visible=true
  arrival_evidence=true
  confidence >= threshold
  missing_final_landmarks=[]
  supporting_candidate_id is selected/current STOP-relevant candidate
```

对于 completion gate 的 STOP：

- 若 V2 支持候选不是当前朝向 / 当前 observation 对应候选，应记录 `allow_candidate_mismatch`，默认降级为 `uncertain`。
- 如果存在 oracle distance gain 信息，可仅作为日志记录，不直接用于决策，避免泄露 oracle。

新增字段建议：

```text
visual_target_verifier:
  supporting_candidate_id
  stop_relevant_candidate_id
  candidate_alignment: aligned | mismatch | unknown
```

#### 8.8.3 selector 空预测 fallback 改成证据排序 fallback

当前空预测策略：

```text
predictions=[]
-> fallback first observed candidate
```

建议改为：

```text
predictions=[]
-> rank movement candidates by:
   1. V4 candidate summary final_target_visible / arrival_evidence
   2. matched_instruction_terms count
   3. confidence
   4. geometry distance sanity
   5. original candidate order
-> select best ranked candidate
```

新增事件：

```text
selector_empty_prediction_fallback
  fallback_strategy: visual_evidence_ranked
  ranked_candidates
  selected_candidate
  previous_first_candidate
```

这能把 V1/V4 已经抽取出的候选级证据用于替代“第一个 candidate”启发式，同时保留可审计日志。

#### 8.8.4 候选采样改成两阶段策略

不建议直接把 `MAX_CANDIDATES` 永久改成 5，因为 latency 已经较高。

建议：

```text
default MAX_CANDIDATES=4

if candidate_count > MAX_CANDIDATES:
  include candidates selected by:
    - selector top / predicted candidate if available
    - current heading / forward candidate
    - candidates whose text observation contains current/final landmarks
    - remaining slots by original order

if STOP is proposed or selector predicts STOP:
  run targeted visual evidence refresh on:
    - current/STOP-relevant candidate
    - top 1-2 target-like candidates not sampled before
```

新增日志：

```text
visual_evidence_sampling
  total_candidate_ids
  requested_candidate_ids
  selection_reason_by_candidate
  sampled_all
```

这样可以降低漏掉目标候选的概率，同时控制图像调用成本。

#### 8.8.5 latency 控制

建议把 V1 prompt 输出压缩，减少 token 和解码耗时：

```text
- 限制每个 candidate 的 spatial_notes <= 40 chars。
- 删除长句解释，强制 compact JSON。
- 候选字段只保留 selector/V2/V3 需要的字段。
- 对 parse_error 增加一次 JSON repair，而不是重新调用 VL model。
```

目标：

```text
parse_error rate < 5%
observation -> visual_evidence mean latency < 25s
```

#### 8.8.6 下一轮实验矩阵

建议按以下顺序做小样本对照：

```text
R1: V2/V4 current
    baseline for current 10 episode result.

R2: V2-first selector STOP gate
    验证 episode 11 类 case 是否能正确 STOP。

R3: R2 + visual ranked fallback
    验证 predictions=[] 的 10/57 fallback 是否改善。

R4: R3 + adaptive candidate sampling
    验证 sampled_all=false 的 14/57 是否减少，同时观察 latency。
```

核心指标：

```text

stop_requested count
visual_stop_allowed count
visual_stop_rejected count
selector_empty_prediction_fallback count
visual_evidence parse_error rate
sampled_all=false rate
step latency
```

## 9. 当前下一步

优先级顺序：

1. 实现 V2-first selector STOP gate：selector 预测 STOP 时直接以 `stop_proposal=true` 调 V2，`verdict=allow` 可放行 STOP。
2. 为 V2 allow 增加候选一致性记录，至少记录 `supporting_candidate_id` 与 STOP-relevant candidate 是否一致。
3. 把 selector 空预测 fallback 从“第一个 candidate”改成“视觉证据排序 fallback”。
4. 增加候选采样日志，并设计 adaptive candidate sampling，减少 5 候选时漏掉目标的风险。
5. 压缩 V1 输出格式，降低视觉证据调用 latency，并保持 parse_error rate < 5%。
6. 按 R1/R2/R3/R4 小样本矩阵重跑对照实验。

当前已进入 V2/V4 decision-effect 修正阶段。

重点风险：

- V2 放行 selector STOP 后，可能引入视觉误停；必须保留 `visual_stop_allowed` 日志做 case study。
- selector 空预测 fallback 若使用视觉排序，可能放大 V1 错误证据；需要保留 ranked candidate 明细。
- adaptive candidate sampling 可能增加 latency；需要同步记录 step latency。
- 需要分别归因 V2 STOP 拦截收益与 V4 selector context 收益。
