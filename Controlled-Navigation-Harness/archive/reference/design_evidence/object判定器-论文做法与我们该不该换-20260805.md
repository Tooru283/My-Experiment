# object 判定器：论文都怎么做，以及我们该不该换

> 起因：ACN 首轮离线后，**object 判定器成了 L1 的第一瓶颈（45.1% 的卡步）**。
> 我们现在的做法是 **RAM 标签匹配 + 航点距离 ≤3m**。

---

## 1. 最新论文用什么（全部来自本地库已读笔记）

| 论文 | 检测器 | 关键细节 |
|---|---|---|
| **CA-Nav**（我们 L1 的蓝本） | **GroundingDINO** + r≈5m | ⚠ 作者要求**"手术"改 GroundingDINO 的推理逻辑**，否则预测不稳 |
| **Context-Nav** | **GroundingDINO** + 开放词汇实例建图 | 额外加了 **3D 空间关系验证** |
| **REALM** | **BERT-QA 抽名词短语 → OWLv2** | 先滤掉导航动词再查询 |
| **MSGNav** | **YOLO-World + SAM + CLIP** 增量场景图 | 自己写明"YOLO-W 等检测器受预设词汇限制" |
| **3D-Mem** | **YOLOv8x-World**（ScanNet-200 词表） | 预过滤依赖类别词汇，开放词汇场景会失效 |
| **SG-Nav** | 开放词汇 3D 实例分割 | 自承"3D 开放词汇分割精度有限，**会成为性能瓶颈**"→ 主张**感知-推理闭环自我校验** |
| **GTA**（当前 SOTA） | **没有物体检测器** | 走 TSDF + BEV，让 MLLM 在俯视图上点像素 |

**共识**：大家都用**开放词汇检测器**（GroundingDINO / OWLv2 / YOLO-World）。
**我们用的 RAM 是 tagger 不是 detector** —— 出图像级标签，**没有框、不能按查询词问**。这是类别差异，不是程度差异。

⭐ **但最值钱的一条不是"换谁"，是 REALM 的指标解耦**（我们自己的笔记 §2 早就标了要抄）：

> **GS vs OracleGS 的差 = 检测器的锅；OracleGS 低 = 导航的锅。**

**换检测器之前，先量一下瓶颈到底是不是检测器。** 下面就是这个测量。

---

## 2. ★ REALM 式解耦：在我们自己的 100 集上量

180 条 object 约束，88 集：

| 量 | 值 |
|---|---:|
| RAM 全轨迹任意方向**报出过**该地标词 | **130/180 = 72.2%** |
| 且该方向航点 ≤3m | 130/180 = **72.2%** |
| ↳ **距离门额外砍掉的** | **0.0%** ← 距离阈值完全不是瓶颈，再次确认 |
| 🔴 **从没报出过** | **50/180 = 27.8%** |

### 归因拆分（这是决定性的一步）

那 50 条"从没报出"，agent 到底有没有走到目标附近？

| | 条数 | 归因 |
|---|---:|---|
| 从没报出 **且 agent 进过目标 3m 内** | **8** | **确定是检测器的锅**（东西就在那儿，它没认出来） |
| 从没报出 **且 agent 从没接近** | **42** | 归因不明 —— **换任何检测器也报不出没走到的地方** |

### 终点地标单列（最关键的那一条约束）

| | 值 |
|---|---:|
| 终点地标约束数 | 63 |
| RAM 报出 | 44 = **70%** |
| **其中 agent 确实到过 3m 内的** | 20 条 |
| **这 20 条里 RAM 报出** | **18 = 90%** |
| 🔴 **到了却没报出** | **2 条** |

**只要 agent 真的走到了，RAM 有 90% 认出终点地标。纯检测器失败只有 2 条。**

### 漏得最多的词（确实是开放词汇的短板）

`piano 3/3` · `treadmill 2/2` · `rug 2/2` · `stove 2/2` · `couch 2/5` · `tub / bathtub / cabinet 各 1`

这些确实是 RAM 词表覆盖不到的具体物体 —— **但总共只有十来条。**

---

## 3. 🔴 裁决：不换检测器

**换检测器的收益上界 ≈ 8~10 / 180 条 object 约束 ≈ 5%。**
成本是：新模型 + 每步每方向一次检测推理 + CA-Nav 说的"还得改它的推理逻辑"。

**性价比不成立。**

### 那 45.1% 的 object 卡步是怎么回事？

**大部分不是"判错"，是"在等"。** 卡步是按**步**计的：队列停在某个 object 格上等 agent 走过去，
每等一步就记一次卡。而 RAM 一旦报出该词，距离门 0.0% 额外拦截 —— 说明**报出来的时候人已经到了**。

→ **object 判定器没坏。它在如实报告「agent 还没走到那儿」。**

**这和 GTA 对照得出的结论是同一个**：我们的缺口是 **OSR（走不到）**，不是感知。
两条完全独立的分析路径收敛到同一句话。

---

## 4. 那该抄什么

按性价比：

| 抄什么 | 来源 | 成本 | 为什么 |
|---|---|---|---|
| ⭐ **指标解耦本身** | REALM | **零**（本文已做） | 它刚刚替我们省掉了一次检测器迁移 |
| ⭐ **感知-推理闭环自我校验** | SG-Nav 明确主张"不能盲目相信检测器结果" | 低 | 我们的 L1 已经有弃权分支，是同一思路的雏形 |
| ⚠ 开放词汇检测器 | CA-Nav / Context-Nav / REALM / MSGNav | 高 | **上界 5%，本轮不做**。若将来 OSR 上去了、agent 真能走到地标附近，这个上界会随之变大，届时再评 |
| ❌ TSDF + BEV 点像素 | GTA | 最高 | 依赖高质量深度；我们的深度在 JPEG 归一化时丢了米制尺度 |

**留一条复评触发条件（写死，防止以后凭感觉重开）：**
> 当 OSR 从 21 提到 ≥35 之后，重跑本文 §2 的归因。
> 若"确定是检测器的锅"那一格从 8 涨到 ≥25，再评估开放词汇检测器。

## 5. 诚实声明

1. "确定是检测器的锅"用的是 **agent 是否进过目标 3m 内**做代理。R2R-CE **没有物体级 GT 位置**，
   所以这只是下界，不是 REALM 的 OracleGS（那个有 GT bbox）。**我们做不出真正的 OracleGS**
   —— 本地笔记 §对比表已写明原因：R2R-CE 终点是坐标不是实例，硬标"目标实例"会循环定义。
2. RAM 的召回统计基于**已发生的轨迹**。如果 agent 走了别的路，RAM 会看到别的东西。
   这是所有基于既有 trace 的离线分析的共同限制。
3. 本文没有测 RAM 的 **precision**（误报率）。若 RAM 大量误报，object 约束会**提前满足** ——
   那是另一个失效模式，L1 规格 §5 的"提前推进率 ≤15%"闸门才是测它的地方。
