# N0：OSR 口径核对，以及两条基线更正

> 起因：我用欧氏距离算出"走到过 ≤3m"是 **31/100**，而引用的 OSR 是 **21**。
> 差 10 点，而今天所有 OSR 论断都压在这个数上。
> **不需要重跑评估器 —— 官方指标本来就在 trace 里**（`episode_end.metrics`）。

---

## 1. 口径对照：查清了

| 口径 | 值 |
|---|---:|
| **官方 `episode_end.metrics.oracle_success`** | **25/100** |
| trace 内 `min(action_post_step.distance_to_goal) ≤ 3m`（**测地**） | **25/100** |
| 我用的 `min(step_start 位置到目标的欧氏距离) ≤ 3m` | **31/100** |

**官方与 trace 内测地距离逐集一致，0 集不符。** → 官方 OSR 就是"任一步测地距离 ≤3m"。

**31 vs 25 的 6 集差，全部来自欧氏 vs 测地**：欧氏是直线穿墙，系统性低估真实距离，
于是多算出 6 集"到过"。

✅ **口径问题关闭。以后一律用 `episode_end.metrics`，不要自己算距离。**

## 4. 🔴 更正三：航点候选集上界也要按口径下修

昨天报的"候选集上界 45%"用的是**欧氏**距离。同一口径下"实际走到过"是 31，官方是 25，
**欧氏系统性高估约 6 集**。

| | 欧氏口径 | 推定官方口径 |
|---|---:|---:|
| 实际走到过 ≤3m | 31 | **25**（已核实） |
| 候选里曾出现 ≤3m | 45 | **约 39**（推定，同样下修 ~6） |
| 差（选路能救的） | 14 | **约 14**（两端同口径，差值近似守恒） |

⚠ "约 39" 是**推定**：无法给假想的候选位置算测地距离（需要模拟器）。
**引用时必须标注是欧氏口径或推定值。**

**结论不变**：选路在已走过的路径上丢约 14 点；即使选路完美，上界也只有 ~39%，
而 P2DNav 的 OSR 是 **62.7**。→ **航点预测器仍是限制。**

## 5. ★ N0b 顺手解决：不去考古那个 0.120，改做配对测量

`r = 0.120` 的原始出处找到了：`experiment_record_20260719.md` §10.1
「自报进度 vs 真实靠近目标进度 | Pearson r = 0.120」。**但定义仍不够精确**
（"自报进度"是文本里的百分比还是 `completed_action_count/action_count`？
"真实靠近目标进度"用测地还是欧氏？）。

**所以不考古了 —— 直接在同一批步、同一公式上把两者一起算。**
`phase_evidence` 事件里本来就有 LLM 的 `action_count` 与 `completed_action_count`，
`action_post_step` 里有**测地** `distance_to_goal`。配对测量（n = **721 步**）：

| 进度信号 | 与真实进度（测地）的 Pearson r |
|---|---:|
| **L1 约束队列 `j/N`** | **+0.188** |
| **LLM 自报 `completed/action_count`** | **+0.021** |
| L1 与 LLM 互相之间 | +0.027 |

**三条结论：**

1. ⭐ **配对下 L1 是 +0.188，LLM 是 +0.021 —— 差约 9 倍**，而不是我之前报的
   "0.166 vs 0.120（1.4 倍）"。**这个说法比之前强得多，且完全不依赖那个历史数字。**
2. 🔴 **历史那个 0.120 在这一轮上复现不出来**（我算出 0.021）。可能是定义不同或不同轮次。
   **不要再引用 0.120，改引本表。**
3. ⭐ **L1 与 LLM 几乎不相关（r = 0.027）** —— 两者在测完全不同的东西。
   LLM 那个不是"弱版本的进度"，是**另一个量**。

⚠ 注意 L1 的 r 从早先报的 0.166 变成 0.188：因为真实进度信号从**欧氏**换成了**测地**。
测地是正确口径 → **以后一律用 `action_post_step.distance_to_goal`。**
