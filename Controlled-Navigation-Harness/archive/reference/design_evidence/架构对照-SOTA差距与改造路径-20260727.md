# 架构对照：与 zero-shot SOTA 的差距，与最小可行改造路径

> 触发：M1 / M1-Large 判 FAIL 后追问"优化 pipeline 值不值"。查文献后结论是**值，且方向明确**。
> 本文档 = 「他们有什么 / 你有什么 / 怎么改」的逐层对照。
> 相关：[[current_task]] §一octo/§一nonus、[[全链条梳理-感知认知决策执行反馈-20260720]]

---

## 0. 一句话结论

**本项目的 SR 16 是对 Open-Nav（ICRA 2025）的忠实复现，而该赛道在 18 个月内已从 ~16 走到 53.3。
差距不在实现质量，在架构代际：所有 40%+ 的方法都有持久空间记忆 + 分层规划，本 pipeline 两者皆无。**

## 2. 逐层对照

| 层 | SpaceVLN (53.3) | 本项目 (16) | 差距性质 |
|---|---|---|---|
| **动作空间** | 原语 {Stop, Forward, TurnL, TurnR}，**171.7 步/集** | 航点跳转 `move_to_next_vp`，**预算 10–12 跳、实测 6.56 步/集** | 控制粒度差一个量级 |
| **规划结构** | **planner/executor 分离**：planner 每阶段 1 次（约每 30 原语），executor 每步 1 次 | 单层：每步一次选择器调用 | 无分层 |
| **空间记忆** | **Spatial Waypoint 图** `w=(位姿, 楼层, 区域, 地标线索)`，含可达边 + 已走链边，跨步持久 | **无**。仅 `VisualGraphMemoryDiagnostic`（109 行，位置历史+距离），且 `LOG_ONLY=True` | **最大缺口** |
| **地标记忆** | Local Landmark Memory：类别/融合位置/距离/方位/可见性/到达状态，每步从 RGB-D 开放词表更新 | `landmark_matching.py` 存在，被 3 个模块引用，但无跨步累积的地标池 | 有零件无系统 |
| **进度定位** | 锚点链 `Verify()` 取**最远已验证锚点**，下一个未验证锚点 = 当前目标 | `completion_estimation`（已自证伪：r=0.12，75 次倒退） | 已证伪 vs 有效机制 |
| **终止** | 三重合取：最终锚点已定位 ∧ 先前锚点全验证 ∧ 地标证据支撑 | 停止请求占终止 72/100，假停 56（均 8.3m） | 无锚点约束 |
| **模型** | Qwen3.5-Plus（规划）+ Qwen3.5-Flash（执行） | 本地 Qwen3.5-9B 纯文本 | **两者你账号里都有** |

## 3. SpaceVLN 消融 → 改造优先级

| 移除的组件 | SR | 损失 |
|---|---|---|
| 完整 | 53.3 | — |
| w/o 分层空间记忆 (HSM) | 38.9 | **−14.4** ← 最大 |
| w/o 局部地标记忆 (L-LM) | 42.9 | −10.4 |
| w/o Planner Spatial-CoT | 44.8 | −8.5 |
| w/o Executor Spatial-CoT | 47.1 | −6.2 |
| w/o 全部记忆与推理 | 37.3 | −16.0 |

⚠ **注意最后一行**：即使剥掉全部记忆与 CoT，仍有 **37.3**。说明 planner/executor 分层 +
原语动作空间 + 锚点链这个**骨架本身**就远强于逐步航点选择。**骨架的价值 ≥ 记忆的价值。**

## 4. 这对既有结论的修正

**M1 / M1-Large 的 null 适用范围被高估了。** 它测的是「无记忆、单步、从候选视角图挑方向」= 43%。
而 SpaceVLN 的 planner 做的是**在空间记忆图上选下一个未验证锚点**——手里有走过的轨迹、
已验证地标、子任务链。信息量完全不同的决策问题，且用的是同家族模型。

→ 准确表述：**M1 界定了「无记忆单步选择」的上界，未界定「有空间记忆时」的上界。**

**同理，"选择层近随机"这条核心诊断需要重新归因。** 无记忆策略在局部做选择，本来就接近随机——
这不是模型的缺陷，是架构没给它可依据的状态。本项目自己的证据早已指向此处：
关闭 waypoint 路线时测得**"失败集随机游走 48% 走远"**，那正是无记忆策略的典型症状，
也正是 visit-info 拓扑记忆专门解决的问题。当时被读作"选择层瓶颈"。

## 5. 最小可行改造路径（分阶段，每阶段独立可验证）

### 阶段 0：诊断（1 轮 ep100，最便宜，决定后续）
- **禁停跑一轮**，测真实 OSR 上界。当前 OSR 21 是"带早停策略"测出来的，
  假停 56 集一停 episode 就结束，走不走得到永远不知道。
- 同轮加大 `SHORT/LONG_ACTION_STEP_LIMIT`（现 10/12）。23 集撞上限，预算是否绑死未知。
- **判据**：禁停后 OSR ≈ 23 → 导航本身到不了，须动骨架（阶段 2）；
  OSR ≈ 40+ → 停止策略是瓶颈，先做阶段 1 性价比更高。

### 阶段 1：把已有的死记忆接上（小改动，先验证机制方向）
- `MEMORY_DIAGNOSTIC.LOG_ONLY: True → False`，让 `revisit_score` / `candidate_novelty` /
  `loop_flag` 进入决策。
- ⚠ **诚实预期：这不等于 SpaceVLN 的 +14.4。** 现有模块只有"位置历史 + 距离"，
  没有区域/楼层/地标/可达边，是 visit-info 的一个薄片。
- ⚠ **且有已知风险**：Arm C 已测过"把先验特征加进选择器重排"→ 命中 +7 点、SR 净 +1（p=1.000）。
  但机制不同：Arm C 是**步内重排**，visit-info 是**跨步避免重访**。值得测，不得假设会成功。
- 成本：一个 flag + 一轮 ep100。

### 阶段 2：骨架改造（真正的工程，对应文献 37.3 那条线）
按消融收益/成本排序：
1. **planner/executor 分离** + 锚点链进度定位（替掉已证伪的 `completion_estimation`）
2. **持久 Spatial Waypoint 图**：位姿 + 区域 + 可达边 + 已走链边
3. **跨步地标池**：复用现有 `landmark_matching.py` + RAM 标签，加跨步融合与到达状态
4. 终止改为三重合取（最终锚点定位 ∧ 先前锚点全验证 ∧ 地标证据）—— 直接打假停 56 集

### 阶段 3：模型分工
`qwen3.5-plus`（规划）+ `qwen3.5-flash`（执行），已确认在账号中可用。

## 6. 诚实限定

1. **复现 SOTA 从来打折**，别按 53.3 做预期。
2. **表中数字未逐篇核对口径**（航点预测器、步数预算、评测集划分可能不同），
   引用进论文前须逐篇复核。
3. **阶段 2 是重写不是调参**，几周量级；阶段 0/1 是几小时。
4. **已有诊断资产不浪费**：oracle 审计、终止校准、三模型规模曲线、选择层三方证据，
   是新方法的动机章与消融对照——比孤立发表更有价值。
5. 本文档的文献数字来自检索摘要与 HTML 全文抽取，**未逐篇通读原文**。
