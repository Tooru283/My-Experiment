# 近目标终止 — 文献调研 + 子问题拆解

> 本文件回答两件事：(1) 近目标终止这个问题**立不立得住**(有没有人做过、novelty 在哪)；
> (2) 把这个大问题拆成几个**可解的小方面**，每个解决后大问题就缓解。

---

# 第一部分：调研 —— 这个问题立得住吗？

## 1.1 一句话结论

**问题立得住，但不是"无人区"。** 近目标终止是被广泛承认的真实问题，已有命名先例(image-goal/ObjectNav 的 "last-mile")；但**在零样本 VLN-CE + 小 VLM 这个具体设定下，它一直是别人论文里的一个子模块，从没被当成中心问题系统化形式化过。** 所以你不能claim"我发现了这个问题"，但可以claim"我第一个在指令跟随的零样本 VLN-CE 里，把它作为中心问题形式化、拆解、并做成跨规模鲁棒的终止决策框架"。

## 1.2 先行工作全景(按"做到哪一步"分层)

### A. Image-Goal / Point-Goal 的 last-mile —— 问题已命名，但任务不同、方法是几何

| 工作 | 做了什么 | 与你的区别 |
|---|---|---|
| **SLING**(Last-Mile Embodied Visual Navigation, NeurIPS 2022, arXiv:2211.11746) | 把导航拆成"探索发现目标 + last-mile 精确停靠(1m 内)"，用 neural descriptor 做几何对齐 | image-goal，无语言指令；几何方法，非 VLM 推理 |
| **AnyImageNav**(Any-View Geometry for Precise Last-Meter Image-Goal Nav, 2026, arXiv:2604.05351) | last-meter 精确停靠，多视角几何 | 同上，image-goal + 几何 |

→ 结论：last-mile/last-meter 是 image-goal 的成熟子领域，但**靠几何描述子，不是终止决策推理**，且**没有自然语言指令**。你的设定(指令跟随 + 零样本 VLM)完全不同。

### B. ObjectNav 的"停止验证" —— 普遍做法，但任务不同

| 工作 | 做了什么 | 与你的区别 |
|---|---|---|
| **MSGNav**(arXiv:2511.10376，你库里有) | **首次明确定义零样本导航的 last-mile 问题** + VVD 最优视点决策；但论文自承"VVD 只缓解，未完全解决" | **ObjectNav**(找物体实例)，非 VLN-CE 指令跟随；VVD 靠点云可见性 |
| **SG-Nav** | 置信度阈值(0.8)判定真目标 + 超步数放弃假阳性 | ObjectNav，场景图 |
| On Calibration of Object Detectors(ECCV 2024 Oral) | 检测器置信度校准 | 检测器层面，非导航终止决策 |
| 多数 ObjectNav 零样本工作 | "高置信检测 + VLM 二次验证才停" | ObjectNav，目标是物体类别不是指令终点 |

→ 结论：ObjectNav 里"停前验证 / 防假阳性"是标准操作，MSGNav 甚至命名了 last-mile。**但都是 ObjectNav，不是 VLN-CE。**MSGNav 是你最近的"撞名"对象，related work 必须正面区分。

### C. VLN / VLN-CE 的停止 —— 被当成子模块/失败节点/指标，没人当中心问题

| 工作 | 怎么处理停止 | 定位 |
|---|---|---|
| **AwareVLN**(你库里有) | "Stopping Error"是 3 类关键失败节点之一(Subtask/Deviation/Stopping) | 失败诊断的一个**类别** |
| **R3**(你库里有) | "Ending"模块：Runner 预测 STOP 时用 GPT-4o 验当前是否真目标 | 一个**验证子模块** |
| **DUET** | 细粒度编码器提升 stopping 精度 | 编码器的一个**功能** |
| Three-Step Nav(arXiv:2604.26946) | "look backward"在停止前审计轨迹纠漂移 | 流程里的一**步** |
| REV-SPL | 改 SPL 指标以惩罚 premature stopping | 一个**指标变体** |
| 普遍观察 | 零样本 MLLM agent "halt prematurely"、低温度→过早保守 STOP | 公认**现象**，未系统攻 |

→ 结论：VLN-CE 圈子**知道**停止有问题(误停、漏停、premature stop 都被点名)，但它一直是别人系统里的一个 verifier / 失败节点 / 指标，**从没有一篇把"OSR→SR 转化"作为中心目标、做失败模式拆解 + 校准/弃权机制 + 跨规模消融的论文。**

## 1.3 Novelty 判定(诚实版)

| 你不能claim | 你能claim(可辩护) |
|---|---|
| ❌ "我发现/命名了近目标终止" (MSGNav 已命名 last-mile；VLN 已知 stopping error) | ✅ 第一个在**指令跟随的零样本 VLN-CE** 里把 **OSR→SR 转化**作为中心、可测目标 |
| ❌ "停前验证是新的" (ObjectNav/R3 都有) | ✅ **针对小 VLM 的校准/弃权**终止决策(miscalibration 是小模型特性，大模型不需要) |
| ❌ "last-mile 视点是新的" (SLING/MSGNav VVD 有) | ✅ 把视点、关系、弱终点、漂移统一成**一套终止失败 taxonomy + 受控消融框架** |
| | ✅ **跨 backbone 一致性**：终止杠杆随规模鲁棒 |

**一句话：问题立得住，但 novelty 不在"提出问题"，在"在你的设定下系统化地解决它 + 小模型校准角度 + 可消融框架"。related work 必须正面处理 MSGNav / SLING / AwareVLN / R3，否则审稿人会说"last-mile 早有人做"。**

# 第二部分：把大问题拆成可解的小方面

> 原则：按**失败模式**拆。每个小方面 = 一种具体的、可从 trace 测量的近目标失败。
> 各自解决 → 各自吃掉 OSR→SR gap 的一块 → 大问题缓解。
> 贯穿所有小方面的统一线索是：**小 VLM 的终止置信度不可靠 → 用校准/弃权代替硬二元判断。**

## 子问题总览

| # | 小方面 | 失败表现 | 可测信号(trace) | 解法 | 借鉴 |
|---|---|---|---|---|---|
| T1 | 到达识别(漏停) | 进过 3m 但没认出到达，继续走 | OSR=1, min_dist 小, final_dist 大(如 810: 0.045→5.18) | current-view auto-stop：arrival evidence 触发 | 你的 S1；DUET 细粒度 |
| T2 | 目标满足性(误停) | 在干扰物/相关物上提前停 | stop 时 dist>3m，附近有 distractor | 证据驱动验证：intrinsic + relation | R3 Ending；SG-Nav 阈值；Context-Nav 关系 |
| T3 | 弱终点(漏停) | 终点是 room/doorway/area，gate 太严永远不敢停 | OSR=1/SR=0 集中在 door/room/hallway | target-type-aware 阈值 + 连续两步二次确认 | 你的 weak-target gate；AwareVLN |
| T4 | 视点不满足 | 几何到了 3m，但视角差、目标不可见/关系不成立，无法确认 | dist<3m 但 target_visible=false | 视点感知验证 + 选最优终止视点 | MSGNav VVD；SLING/AnyImageNav 几何；Context-Nav |
| T5 | 近目标漂移 | 在目标附近震荡，进 recover 后走远 | 近目标进 recover，dist 回升 | near-goal hold + recovery 距离收益约束 | Dual-Anchoring(progress drift)；HiMemVLN revisit；你的 U3 |

## 逐项展开

### T1 到达识别(false negative / walk-through)
- **本质**：模型"在目标旁边"却没意识到"已到达"，于是继续执行。
- **怎么测**：analyze 脚本里 `oracle_success=1 & success=0` 且 `min_distance` 很小、`final_distance` 大。你已有现成 case(810/513)。
- **解法**：phase==verify 且 near-goal 时，current-view 出现 arrival evidence(目标占据视野中心/足够近)→ 触发 auto-stop。
- **吃掉的 gap**：walk-through 类，是你 gap 里最大的一块。

### T2 目标满足性(false positive / 误停)
- **本质**：把"看见相关物体"误当成"到达终点"就停了。
- **怎么测**：stop 发生时 `final_distance>3m`，且 trace 里 final_target_visible 但 arrival_evidence 弱 / 有 distractor。
- **解法**：把 STOP 从"selector 一个选项"改成验证问题——查 intrinsic(目标在不在)+ relation(near/inside/left_of 等是否成立)。不满足则拒停。
- **吃掉的 gap**：premature-stop 类。

### T3 弱终点(weak-target miss)
- **本质**：终点是区域/通用词(room、doorway、hallway、sink)，强阈值下模型永远不够自信，漏停。
- **怎么测**：OSR=1/SR=0 的 episode 按 target 词聚类，看是否集中在弱终点词。
- **解法**：按 target 类型放松/收紧阈值；弱终点用"连续两步 current-view allow + arrival"才放行，平衡误停与漏停。
- **吃掉的 gap**：weak-target-miss 类。

### T4 视点不满足(viewpoint mismatch)
- **本质**：物理上到了 3m，但停在一个看不见目标/关系不成立的视角，VLM 无法确认 → 要么漏停要么乱走。
- **怎么测**：`final_distance<3m` 但 `target_visible=false` 或 relation 不成立的 episode。
- **解法**：不只判"可见"，验"是否处在满足任务判定的终止视点"；在多个近目标候选间选**最优终止视点**(MSGNav VVD 思路)。
- **吃掉的 gap**：到了但确认不了 → 转化失败的一块。

### T5 近目标漂移(near-goal drift)
- **本质**：到目标附近后进入 recover/继续移动，被拉远。
- **怎么测**：episode 在 near-goal 后进入 recover，`distance` 从最小值回升(你 6/23 的 `226/371/1092` 等 9 条就是)。
- **解法**：near-goal hold(到附近后抑制大幅移动)；recover 只允许不降低"最近距离收益"的候选；借 revisit 检测压震荡。
- **吃掉的 gap**：near-goal-drift 类，也是你 6/22→6/23 掉 SR 的主因。

## 贯穿性机制：小模型终止校准 / 弃权(cross-cutting)
- T1-T5 共同的根因是：**4B 的终止置信度不可靠**。你现在用 `confidence>=0.95` 硬阈值就是在手动补这个。
- 统一解法：给终止决策引入**三态(stop / move / abstain-and-reobserve)**，证据不足时弃权再观察一步，而不是被迫二元。这同时降 T1(给机会再确认)和 T2(不轻易停)。
- 借鉴：AbstainEQA(证据不足可弃权)、Fast-SmartWay Disambiguation(不确定→主动再观测)、检测校准(ECCV2024)。
- 这是论文里"for small models"的核心卖点，也是和 P2DNav RRM(只管局部可走性)拉开区分的地方。

# 第三部分：怎么验证"大问题被缓解"

1. **主指标单列 OSR→SR 转化率**(= SR/OSR)，不再只看 SR/OSR 绝对值。
2. **按 T1-T5 给每个失败 episode 打标签**，统计 gap 的成分构成(谁占多少)。这是 M0 要在 analyze 脚本里加的。
3. **每解决一个 Ti，看对应标签的 episode 数下降多少、转化率升多少**——这就是"解决小方面→缓解大问题"的直接证据，也是干净的消融。
4. 约束：SPL/nDTW 不退化(防止为了停而增加无效步数)。

落地顺序接 `近目标终止-单问题创新方案` 的 M0-M5：M0 先把 T1-T5 taxonomy 统计跑出来，知道每块多大，再按占比大小决定先攻哪个 Ti。
