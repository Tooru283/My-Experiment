M1（把 selector 的输入从 SpatialBot 文本描述换成候选视角 RGB）**20260727 跑完 = FAIL**。
n=100 决策点，同模型（本地 Qwen3.5-9B 贪心）、同 prompt 骨架，只换每个候选携带什么。

| 臂 | 命中 | regret m/步 |
|---|---|---|
| IMG@512（最佳） | 41.0% ± 4.9 | 0.944 |
| IMG@1024 | 40.0% | 0.902 |
| IMG@224（在线同分辨率） | 34.0% | 1.027 |
| TXT（当前部署通道） | 30.0% | 1.120 |
| GEO（纯几何） | 26.0% | 1.466 |
| IMGSHUF（错配图对照） | 18.0%（**低于随机**） | 1.468 |
| 9B在线 / 最长步 / 随机 | 29.0 / 43.0 / 25.7% | 1.102 / 1.036 / 1.224 |

**四条要记住的**：
1. **闸门 FAIL 且已排除分辨率解释**：224→512 涨 7 点、512→1024 不再涨 = 饱和。
   ⚠ 只跑 224 那一轮我曾误读成"图像毫无增益"——224 确实压低图像臂 7 点，**必须在最佳分辨率上判读**。
2. **非伪 null**：IMGSHUF 把每个选项配上邻居的图 → 18%，低于随机，p=0.017。
   错配图会**主动误导**模型 ⇒ 模型确实在读像素，不是"没看图"。这个对照是让 null 有信息量的关键。
3. **IMG−TXT = +0.218 m/步(+1.44 m/集) 但 95%CI [−0.047,+0.484] 跨零**，n=100 分辨不了。
   而 IMG−GEO(+0.563) 与 TXT−GEO(+0.345) 都显著 → **"有感知vs无感知"的差距比"像素vs文本"大一倍以上**。
4. **两个预注册闸门名义结论冲突**：M1 命中闸门 FAIL，但 20260720 上线闸门（≥0.5m/集）
   被 IMG 名义越过（vs 在线 +1.32m/集 p=0.047）。**按纪律以唯一预注册的 M1 闸门为准**——
   其余是 5+ 次事后比较、未做多重校正。反之也不得宣称"图像无用"。

**因果链改写**（[[project_selector_bottleneck_20260719]] / 文本通道上界的最后一环是错的）：
不是"图像→文本丢掉方向信息"，而是**接口只丢了一部分，9B 从任一模态都只拿到同一档**。
主瓶颈在更上游：这个规模的 VLM 判别"哪个方向通往终点"本身就弱。
→ 按预注册分叉表落"换赛道（换基准/允许训主干/换更大模型）或收口成最小可发表版"。
连带：backbone 快筛与图像版打分头的重开条件均**未满足**，保持关闭。
